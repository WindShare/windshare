# 增量传输与续传架构收缩执行计划

> 本文承接 [`即时分享与文件浏览重构收尾计划.md`](即时分享与文件浏览重构收尾计划.md)，用于收缩
> `740dd96` 留下的迁移结构。产品行为继续以现行协议、威胁模型和功能变化文档为准。

## 背景与目标

`740dd96` 已完成正确的产品方向：下载任务从冻结的 `TransferIntent` 打开唯一 `OutputSession`，按已提交
catalog generation 逐目录 admission，并让 discovery、文件写入和 file-local checkpoint 独立推进。Web 生产路径也已统一到
增量 `v2-job`。

当前 Go 原生输出仍在每次 `AdmitDirectory` 时重建累计 `OutputSelection`，重复排序、全树校验、materialize 和 ancestry
检查，目录增长时形成 O(D²) 工作。旧 header、`SessionAuthority`、session candidate、terminal store 和第二套
crash-safe record 安装流程也仍被编译和测试。本次直接替换这些迁移结构，不增加双读、feature flag 或兼容层。

当前 `make check`、`make hygiene`、`make vectors` 均通过且 `core/testvectors` 干净，可作为行为基线，但不证明旧 authority
已物理退役。旧计划须改为“产品行为已闭合、Go 输出 authority 收缩中”，完成本计划前不得声称物理清理完成。

## 架构裁决

### 唯一生产合同

- 生产输出合同固定为
  `TransferIntent → OpenOutput → AdmitDirectory → BeginFile → FinalizeDirectory(DirectoryAdmission)`。
- `TransferIntentDigest + backend + root identity` 是恢复 namespace；只有完全相同的 intent 才能续传。不同选择、root 或
  backend 不复用 checkpoint。
- durable `OutputSession` 在枚举 checkpoint 前取得该 namespace 的独占 lease，并持有到稳定的 Pause/Complete；并发 opener
  只返回 typed busy，不得打开第二个 runtime。
- `OutputSessionID`、directory receipt 和运行中 ledger 只属于当前进程。`FileCheckpointV1` 是唯一 durable file state。
- `PauseJob/CompleteJob` 不提供删除权。用户确认的破坏性清理由独立 `ResumeStateAuthority.Discard` 执行，普通传输错误不得调用。
- `OutputSelection`、`TerminalSelectionObservationV1.BindPlan` 及其 osfs 消费链全部删除。诊断只保留不参与授权或恢复的
  `SelectionObservationV1`。
- 用户已有或已发布文件永不覆盖；只有 checkpoint 精确证明 ownership 的未完成对象才可 reopen。collision 按文件隔离并继续；
  identity 或 ownership 不明确时进入 needs-attention，不自动删除或从零重来。

### 增量 authority 模型

所有 `OutputSession` 都持有以下有界进程内状态。durable tree 变体另外持有 certified platform、root binding 和独占 checkpoint
claim；`DurabilityNone` stream 只持有 sink capability，不虚构 root 或 checkpoint authority。

- `DirectoryClaim`：冻结 `DirectoryID + Generation + ParentAdmission + canonical path + ModifiedTime`，状态为
  `pending → admitted → settling → settled(finalized|isolated-failure)`。只有 mutation 结果不明确时才阻断 session。
- `FileClaim`：冻结 intent、完整 revision descriptor、canonical path、exact size、parent admission 和 target，状态为
  `pending → active → settled(FileSettlement)`；终态保留到 session settlement，以支持确定性重试和汇总。
- `locatorClaims`：以 platform canonical locator key 同时索引目录和文件，拒绝大小写、Unicode、DOS alias 等平台等价路径。
- output-local `nodeClaims`、path index 和 per-directory counters：拒绝已 admission 节点的同一身份换 path、文件/目录冲突和
  tuple 扩宽，并以 O(1) 查找、O(depth) 更新维护 active descendants 与未 settled 的直接子目录。

catalog path 规范化、平台 locator key、保留 control namespace、全局 NodeID 身份和 metadata capability 都必须保留。收缩目标是
把这些不变量改成增量索引，不是删除 session-global 不变量。TransferJob 的 catalog NodeID ledger 继续在 selection 前覆盖全部已发现节点，
包括未选中节点；它与只覆盖已 admission 输出对象的 output-local `nodeClaims` 不得合并。现有 directory-admission count 和
retained-metadata budget 继续生效；reservation 前 charge，失败回滚，耗尽按 output pause 结算。

directory receipt 使用已认证 root scope 内的 session key，对版本化、长度分帧的完整 `DirectoryClaim` 做 HMAC-SHA256。完全相同
tuple 的重试返回同一 receipt；任一字段变化都按 directory scope fail closed。root admission 还必须绑定 intent 的 synthetic root。

### 并发与目录 finalization

- ledger reservation 和状态切换在 session lock 内完成；filesystem、checkpoint、trace observer 等外部调用不得持有全局 session lock。
- 同 tuple 的并发 admission 等待同一个 pending operation；冲突 tuple 立即拒绝。I/O 失败后按实际 mutation 结果 reconcile，再决定回滚、
  重试或 session pause，不能留下无 ledger 的已创建目录。
- `BeginFile` 先原子取得 `FileClaim`，再进入文件执行引擎。`FinalizeDirectory`、`BeginFile` 及返回 transaction 的
  `WriteRange/Checkpoint/Commit/Pause/Retire` 都必须取得同一 operation lease，并与 session settlement 遵守固定锁顺序。
- `FinalizeDirectory` 在 session lock 内把 claim 切到 `settling` 并封口；此后拒绝新的 descendant admission/`BeginFile`。相同
  receipt 的 settled 重试返回缓存结果，冲突 receipt fail closed。
- 同 tuple 的并发 `BeginFile` 只允许一个 transaction owner；等待者不得共享 mutable transaction，只能取得已有 terminal
  settlement 或 typed already-active 结果。
- TransferJob 负责证明 generation 已完成遍历且全部 selected children 已结算。OutputSession 只验证 receipt、已知直接子目录均已
  settled、该目录下没有 active mutation，然后使用 claim 中冻结的 metadata 完成 finalization。可隔离的 metadata 失败必须在
  reconcile 后把 claim 结算为 `isolated-failure`，使祖先能够继续结算；结果不明确才进入 output pause。
- synthetic root receipt 也必须结算。对调用者提供的既有 output container，root finalization 只封存 authority，不改写其 metadata；
  只有 backend 创建并拥有的目录才应用 claim 中冻结的 metadata。
- `PauseJob` 和 `CompleteJob` 先阻止新 operation，再等待在途 reservation/transaction 到达稳定切点；不得依赖 terminal whole-tree
  reopen。

关键状态切换保留结构化 trace，携带稳定的 intent/session/file operation 标识、前后状态和失败 scope，不记录密钥或明文路径。

## 原生输出重构

- 从旧 `Session` 提取文件创建、range 写入、checkpoint、恢复、quarantine、publication、retirement 和 ancestry 操作，形成依赖窄
  directory-authority、platform 和 checkpoint repository port 的文件执行引擎。
- `AdmitDirectory` 只沿当前 path 重新证明 ancestry，只 materialize 当前目录，并把平台等价 locator、reserved namespace 和
  metadata 校验写入增量 claim。
- 每个 `DirectoryClaim` 至多建立一次 parent namespace snapshot/index。Windows long/short name 只按 parent claim 枚举一次，后续
  direct-child alias 查找为 O(1)；snapshot 不是 mutation authority，实际 open/create 仍用 retained guard 精确重验并 reconcile 外部变化。
- `BeginFile` 直接验证 parent receipt、descriptor、target、locator claim 和 checkpoint identity，不安装 selection overlay。
- restart 后先按 intent/root 打开 checkpoint namespace；只有 discovery 重新提交 generation、取得新 parent receipt 并再次
  `BeginFile` 后，checkpoint 才能绑定到当前进程的 `FileClaim`。
- 切换唯一 composition root 后，删除 legacy selection session、`SessionAuthority`、header/session bootstrap、session candidate、
  terminal state、旧 reducer、旧 fixture 和只服务这些类型的公共 API。

## Checkpoint 与旧状态清理

- `checkpointstore` 成为唯一 fixed-record create/replace/reopen/reconcile 实现，统一 temporary naming、exact compare、atomic install、
  parent sync、crash recovery 和 contention 语义。
- `outputnamespace` 只保留 capability-level 的目录、文件、lock 和 exact-read 操作；删除 `outputnamespace.Store` 及其 state
  installation/recovery 流程。
- recovery、quarantine、publication 和 retirement reducer 直接读写 `FileCheckpointV1`，不经过 `FileRecord`、
  `BoundFileRecord` 或旧 session authority。
- `ResumeStateAuthority` 在 TransferJob 之外列出/删除 paused namespace。Discard 取得同一 namespace lease，逐 checkpoint 执行
  user-discard retirement；只删除 owned stage/anchor/record，保留 published final，任何歧义进入 needs-attention。
- cleaner 内部保留独立、只读的 legacy ownership decoder，只解析安全删除所需的 marker、backend/root/certification、control 名称和
  lock；不得解析或返回旧 ranges、selection、header authority 或 terminal state。
- cleaner 只在证明 WindShare ownership 并取得旧 coordinator/session locks 后删除自有旧 namespace；unknown owner、已发布文件和路径
  冲突只进入报告。
- 收缩 `core/osfs/checkpoint.go` 公共面。协议向量只覆盖 canonical checkpoint、ownership 和 crash-cut，不公开内部 repository
  生命周期。

## 错误边界

- 先定义封闭的 source、catalog、session、output 和 checkpoint fault，以及多个 fault 的确定性 severity join；保留
  file-local、directory-local、session-terminal 和 output-pause 的作用域。
- 在 collaborator 边界用标准 `errors.Is/As` 完成一次归一化；原始 cause 只供 trace 和诊断，settlement 不再遍历任意 error graph。
- context cancellation 保持独立；任何未归一化错误都转为 dependency-contract/session pause，绝不能降级为 file-local failure 或
  retirement authority。
- 全部生产调用者迁移后，再删除反射式 error graph walker、节点预算和循环/巨型 mock graph 测试。

## Web 与用户体验

- 保留 `v2-job`、增量 `OutputSession`、FSA/OPFS、stream/ZIP 和 `FileCheckpointV1` 的现行生产结构。
- `transferIntentDigest`、backend 和 root identity 组成必填的 checkpoint namespace binding value；生产构造器不接受 optional 字段、
  `allowTestFallback`、`compat-intent`、`compat-root` 或 readable identity 推断。
- 精确匹配的 checkpoint 自动续传；不同 intent/root/file identity 不复用，并以任务级 needs-attention 提示处理。
- durable FSA/OPFS paused task 可跨刷新 Resume：只持久化版本化 `PausedTaskDescriptorV1`（canonical `TransferIntent` 与 root
  capability reference），不保存链接密钥、receipt、session ID 或动态 ledger；恢复时重新取得当前 share authority、root permission
  和新 run ID。descriptor 只负责重建任务，have-state 仍只来自 `FileCheckpointV1`。
- `DurabilityNone` 的直接 single-file/ZIP stream 不显示可续传 checkpoint，暂停后只能从零 Retry；Cancel 只能停止后续输出，不能撤回
  已交给浏览器的字节。durable Cancel 经确认后调用 `ResumeStateAuthority.Discard`，始终保留已完成文件。
- collision 和 isolated file failure 不逐文件弹窗，继续兄弟文件并汇总为 `CompletedWithErrors`。discovery 未完成时只显示
  “已发现/已完成”，不显示伪百分比。
- IndexedDB legacy cleaner 只清理应用自有旧 stores；正常 journal 不再推断旧 store 或 runtime session identity。

## 测试、hygiene 与验证

- 保留延迟兄弟目录时首文件已写出、generation 原子提交、unknown/partial 显式目标、文件失败隔离、checkpoint crash-cut、取消、
  receipt 冲突、root confinement、no-replace 和 platform alias collision 等行为回归；用 fake transaction 确定性覆盖 settlement 与
  admission、重复 `BeginFile`、range write、checkpoint、directory sealing/finalization 的竞态。
- 固定 path depth，逐步增加历史 admission 和同 parent sibling 数量；同时统计 ledger 操作与注入的 platform enumeration work，证明
  单次 admission 不随 D 增长、每个 parent claim 最多枚举一次；不设置 wall-clock 性能门槛。
- coverage/wave 测试先迁移仍有价值的安全语义，再删除重复或只追分支数字的文件，重点清理未对应生产变化的 Windows wave 和
  `core/content` 跨领域分支测试。始终满足 core total ≥90%、root total ≥80%、
  every package ≥70%，不得通过扩大忽略配置补覆盖率。
- hygiene 保留精确退役路径检查和真实 production dependency graph；删除测试源码扫描、泛化符号黑名单及重复的
  Vitest graph/string assertions。包级 graph 之外，评审还须确认已退役类型没有生产构造点。
- 迭代期间运行 focused gate 或 `make check`；结构、Web、文档和向量同步完成后运行 `make ci`，再按双模块流程生成固定 commit 的
  发布证据。
