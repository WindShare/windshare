# Incremental transfer and resume-authority contraction

> Status: implementation complete. This is a concise closure record; current behavior is defined by
> [协议规范.md](协议规范.md), [威胁模型.md](威胁模型.md), and
> [重构功能变化.md](重构功能变化.md).

## Result

WindShare now has one production output lifecycle:

```text
TransferIntent
  → OpenOutput
  → AdmitDirectory
  → BeginFile
  → FinalizeDirectory(DirectoryAdmission)
  → PauseJob | CompleteJob
```

A committed catalog generation can begin output without waiting for terminal discovery. The catalog-wide NodeID
ledger still covers every discovered node, while the output session keeps a separate bounded ledger only for admitted
objects. Directory receipts are runtime-only HMAC-SHA256 capabilities bound to the intent digest, directory and
generation, parent receipt, canonical path, and modified time. Finalization consumes the receipt and returns a cached
`DirectorySettlement`; it cannot reconstruct authority from a path.

The native session incrementally reserves canonical node, path, and platform-locator claims before I/O. One operation
gate coordinates directory/file mutations with `PauseJob` and `CompleteJob`; stable settlement drains in-flight
work before resources and the durable lease are released. Resource exhaustion and ambiguous mutation cuts pause the
output instead of being misclassified as file-local failures.

## Durable output and resume

- The durable namespace is exactly `(TransferIntentDigest, backend, root identity)`. Native ownership additionally
  persists the certified filesystem and `RootOpenDisposition`.
- A durable opener acquires the intent's exclusive lease before enumerating or mutating its subtree and holds it until
  stable pause or completion. Contention returns typed busy; a second runtime is not opened.
- `FileCheckpointV1` is the sole durable per-file authority. Runtime session IDs, directory receipts, progress, and
  claim ledgers are never recovery inputs. A new run may reuse only ranges from an exact canonical checkpoint after
  current discovery, parent admission, root capability, and file identity are revalidated. A published checkpoint
  retains its private anchor as the exact final-identity witness until confirmed discard; its writable stage is retired.
- `ResumeStateAuthority` is separate from `OutputSession`. It lists a live inventory and consumes an opaque,
  single-use reference under the same namespace lease. Confirmed discard removes only identity-proven stage, anchor,
  and checkpoint records in crash-safe order. Published files are preserved; replacement, unknown children, corrupt
  binding, or ambiguous publication returns `NeedsAttention`.
- The native and IndexedDB legacy cleaners remain isolated maintenance capabilities. They recognize only enough old,
  WindShare-owned state to remove it safely and never import legacy ranges or participate in current resume.

## Root and fault boundaries

An existing output directory is always a caller-provided container, even when the open requested creation. Only a root
created and revalidated by that open is `authority-created-root`; restart trusts the persisted certified disposition,
not path existence. Synthetic-root finalization seals both forms, but never applies catalog metadata to a caller-owned
container. An exact preexisting descendant is retained as an unowned container, so restart can reach file checkpoints
without fabricating directory state; it receives no catalog metadata. Descendant creation and publication remain
root-confined and no-replace.

Go and Web share closed fault domains (`Source`, `Catalog`, `Session`, `Output`, `Checkpoint`) and scopes
(`FileLocal`, `DirectoryLocal`, `OutputPause`, `SessionTerminal`). Collaborator errors are normalized once;
policy never walks an arbitrary error graph. Cancellation stays separate, unknown errors become
`Session/DependencyContract/OutputPause`, and only the explicit permanent-source or invalidated-revision allowlist can
retire a file.

## Browser resume and transient output

Durable FSA directory and OPFS ZIP pauses persist only `PausedTaskDescriptorV1`: schema version 1, the canonical
run-ID-free `TransferIntent`, and an independent non-zero 32-byte `rootCapabilityRef`. It contains no link key,
receipt, runtime ID, checkpoint, range, progress, or dynamic ledger. Resume rechecks the current share, renews the root
or save capability, creates a fresh `TransferRun` and `OutputSessionID`, then obtains have-state only from exact
`FileCheckpointV1` records.

`DurabilityNone` single-file and ZIP streams never create a paused descriptor or resumable checkpoint. Pause/Cancel
can stop only future bytes, and Retry starts from byte zero. The Blob-backed portable fallback is separately bounded to
64 MiB; native save streams are not described by that buffer limit. Confirmed durable Cancel preserves completed FSA
files; OPFS exports committed members as a partial ZIP before retiring staging, and ambiguous publication remains
`NeedsAttention`.

## Physical retirement

The old whole-tree authority graph has been removed from production: `OutputSelection`,
`TerminalSelectionObservationV1`, `SessionAuthority`, `outputnamespace`, `resumestate`, terminal plan binding,
and the duplicate checkpoint installer/reducer paths are gone. `SelectionObservationV1` remains only as a
non-durable diagnostic digest. Hygiene now requires the native production graph to reach `outputsession`,
`directoryauthority`, `fileexecution`, `checkpointstore`, and `resumeauthority`, while rejecting the retired
packages and Web paths.

This contraction does not change root first-level prefetch, catalog generation atomicity, file revision semantics,
0/8-second relay fallback, WebRTC/relay racing, or the irreversible boundaries of direct streams and ZIP members.
