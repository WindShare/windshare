WindShare 从“先扫描完整内容，再开始分享”重构成了“链接立即可用、按需浏览、按文件独立传输”的即时分享产品。

| 用户场景 | 主要变化 |
|---|---|
| 创建分享 | 不再递归扫描、读取、哈希或复制全部文件。relay 确认注册后立即显示链接，链接生成时间基本不受目录规模和文件体积影响。 |
| 浏览文件 | 接收方打开链接后立刻看到根目录；链接就绪后低优先级预取所选目录根的第一层，其余目录只在浏览或下载请求时扫描直接子项，未被请求的更深内容不会提前加载。 |
| 选择下载 | 可以直接选择尚未展开的目录，未来发现的后代会继承选择。下载整个目录时边扫描边加入文件传输，不必等待整棵树扫描完成。 |
| 进度显示 | 内容尚未发现完时，只显示“已发现”的文件数和体积，不再把未知总量伪装成精确百分比。 |
| 预览媒体 | 支持显式点击图片预览和视频拖动定位；预览与正式下载共享范围读取和缓存，但不在创建链接时生成缩略图或分析媒体。 |
| 错误隔离 | 文件被修改、删除或无法读取时，通常只失败该文件，其他文件继续。目录扫描失败也会跳过该分支并给出“部分完成”，而不是整次下载全部失败。 |
| 续传与保存 | `FileCheckpointV1` 按 exact intent/root/file identity 独立记录已验证范围；一个文件变化不会让其他文件的进度作废。Durable FSA directory 与 OPFS ZIP pause 可跨刷新恢复，但会重新验证当前 share、root/output capability 并创建新的 runtime session；paused descriptor 本身不保存密钥或文件进度。Direct single-file/ZIP streams 没有 checkpoint，Retry 从 byte zero 开始。 |
| 取消与清理 | 普通暂停或错误只保留续传状态，不会顺便删除。用户确认 durable Cancel 后，独立的 resume authority 只清理 identity-proven unfinished state 并保留已完成文件；OPFS 会先导出已完成成员的 partial ZIP，任何 ownership/publication 歧义都保留并提示。旧 v2/v3 状态不迁移、不双读，只由 ownership-scoped cleaner 清理 WindShare 自有旧 state。 |
| 连接体验 | 浏览目录默认走已经建立的 relay；点击预览或下载才开始 P2P。大分享或规模未知时不会长时间等待直连，约 8 秒内启用 relay 兜底。 |
| 安全与隐私 | 链接和 `#` 后的密钥可以分开复制，通过不同渠道发送；缺少密钥时由接收方本地输入，不上传密钥。relay 看不到文件名、内容和协议中明示的精确文件大小，但仍能观察流量和时序。 |
| 停止分享 | 当前仍是纯在线分享：发送端明确停止或退出后，现有下载终止，新接收方无法加入；尚未支持发送端退出后链接继续有效。 |

用户需要特别理解的行为边界：

- 根层预取仅有一层且不递归；其余目录在接收方第一次按需浏览或下载时分别“定格”，并不是点击分享那一刻得到整棵目录的统一快照。
- 目录定格后新增或修改的内容不会自动同步；源文件发生变化可能导致对应文件下载失败，需要重新分享。
- 发送端不会为保证稳定下载而偷偷制作完整文件副本；因此分享期间文件可能被锁定，本机修改也可能中断该文件传输。
- 没有 native save capability 时，Blob-backed portable download 的 transient buffer 上限为 64 MiB，且不能跨刷新续传；native save stream 不受该 buffer 上限描述。OPFS staging 也不能绕过最终保存目标的能力或上限。
