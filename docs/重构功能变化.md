WindShare 从“先扫描完整内容，再开始分享”重构成了“链接立即可用、按需浏览、按文件独立传输”的即时分享产品。

| 用户场景 | 主要变化 |
|---|---|
| 创建分享 | 不再递归扫描、读取、哈希或复制全部文件。relay 确认注册后立即显示链接，链接生成时间基本不受目录规模和文件体积影响。 |
| 浏览文件 | 接收方打开链接后立刻看到根目录；链接就绪后低优先级预取所选目录根的第一层，其余目录只在浏览或下载请求时扫描直接子项，未被请求的更深内容不会提前加载。 |
| 选择接收 | 可以直接选择尚未展开的目录，未来发现的后代会继承选择。系统先确认最终 artifact shape，再显示“下载文件”“保存到文件夹”“按原层级保存”“下载 ZIP”或“检查后下载”；后台确认不会自动打开 picker。 |
| 输出产物 | `original-file` 保持单文件；`directory-tree` 保留原层级；`zip-archive` 是用户明确选择的 `store`、`complete-only` package，不再是隐藏默认，也没有 partial ZIP。 |
| 进度显示 | 内容尚未发现完时，只显示“已发现”的文件数和体积，不再把未知总量伪装成精确百分比。 |
| 预览媒体 | 支持显式点击图片预览和视频拖动定位；预览与正式下载共享范围读取和缓存，但不在创建链接时生成缩略图或分析媒体。 |
| 错误隔离 | CLI ordinary output 保留成功文件，item/subtree failure 只让本次命令 partial 并保持 operation active；`item-blocked` 不阻止独立兄弟项，只有 authority ownership 不确定才停止整个 operation。Web lifecycle 保留 `partial-directory`。完整产物仍不发布已知残缺结果。 |
| 命名与层级 | CLI 默认保存到当前目录；`-o` 始终是容器。单文件不额外套结果根，完整目录使用原目录名，部分目录使用 `<目录名>-selection`，多根使用 `windshare`。顶层冲突不覆盖/合并，而为新 operation 选择稳定后缀；同一 active operation 恢复时复用原名称。Web ZIP 沿用对应 `<结果根>.zip`。 |
| 续传与保存 | Native destination 的四项能力全部成立才可 resumable；只有 safe publish + crash cleanup 时以 warning-once 进入 live-only，下一次 `get` 使用新名称重下 selection。active registry 只属于指定目标根，不维护全局/终态历史。Web Workspace 完整封存后仍可进入 `waiting-to-save` 并再次 handoff。继续均要求 sender、revision 与权限有效。 |
| 完成状态 | Native CLI 的 command result 与 persistent operation state 分离；retryable failure 不创建终态历史。Web 受控 target 确认 commit 才是 `published`；`browser-handoff` 只能到 `download-started`。24 小时 retention 只属于 Web 的 stable resumable/waiting states；portable 64 MiB route 不可恢复。 |
| 停止与清理 | Native `resume discard` 只删除 identity-matching unfinished WindShare-owned state，永不删除 final 或陌生对象；不确定时保留并进入 attention。Web discard/expiry 仍只删除 ownership-proven unfinished workspace/package/checkpoint/metadata。旧 state 不迁移、不双读，只由 certified cleaner 清理。 |
| 连接体验 | 浏览目录默认走已经建立的 relay；点击预览或下载才开始 P2P。大分享或规模未知时不会长时间等待直连，约 8 秒内启用 relay 兜底。 |
| 安全与隐私 | 链接和 `#` 后的密钥可以分开复制，通过不同渠道发送；缺少密钥时由接收方本地输入，不上传密钥。relay 看不到文件名、内容和协议中明示的精确文件大小，但仍能观察流量和时序。 |
| 停止分享 | 当前仍是纯在线分享：发送端明确停止或退出后，现有下载终止，新接收方无法加入；尚未支持发送端退出后链接继续有效。 |

用户需要特别理解的行为边界：

- 根层预取仅有一层且不递归；其余目录在接收方第一次按需浏览或下载时分别“定格”，并不是点击分享那一刻得到整棵目录的统一快照。
- 目录定格后新增或修改的内容不会自动同步；源文件发生变化可能导致对应文件下载失败，需要重新分享。
- 发送端不会为保证稳定下载而偷偷制作完整文件副本；因此分享期间文件可能被锁定，本机修改也可能中断该文件传输。
- Workspace ZIP 与 portable download 在请求任何文件内容前完成 exact preparation 和容量检查；超限时零 content request。`WorkspaceBudgetV1.peakOwnedBytes` 是 `uniqueRawBytes`、`packageBytes`、`peakTemporaryBytes` 与 `durableMetadataBytes` 的 checked sum；quota estimate 不是 reservation。
- 当前 Web 可继续或安全丢弃 `resumable-receive`/`resumable-package`；Continue 由 output-owned executor 复核 exact preparation 或 sealed package evidence。`waiting-to-save` 保存、workspace `download-started` 再次 handoff、expiry 与 cleanup 也由 output authority 执行。
