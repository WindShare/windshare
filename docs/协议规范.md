> 不属于 suite；当前产品行为见[功能变化](重构功能变化.md)，安全理由见[威胁模型](威胁模型.md)，

## 1. 适用范围与编码规则

本文是 suite `0x02` 的权威线合同。严格解码只作用于已协商的 suite/schema：closed schema 中未列出的
字段、critical flag、消息类型和枚举值必须拒绝；capability bit、显式声明为 open 的 extension container，以及
本文明确允许降级为 opaque permanent failure 的 error-code 值域，按所在 schema 的规则忽略、保留或最小作用域
失败。未知信息绝不能静默启用行为、扩大 authority 或改变已知字段含义。
实现不得从已退役语义推断缺失字段，也不能把本地数据库版本、浏览器版本、UI 状态、队列容量、超时、
backoff 或运维默认值提升为 wire compatibility 条件。本文的“必须/不得”只用于互操作、安全边界或对端
资源上限；未编码到消息中的调度与保留时长属于有界本地策略。组件边界、goroutine/worker、队列、锁、
存储布局、重试算法和 UI 呈现不属于 suite；实现只需产生相同 wire 语义并保持本文明确列出的安全与资源结果。

### 1.1 基础密码档

suite `0x02` 固定为：

- AES-256-GCM，96-bit 随机 nonce，128-bit tag；每次 Seal 取得全新 nonce；
- HKDF-SHA256；
- Ed25519 sender 签名（public key 32B、signature 64B）；
- X25519 临时 ECDH（public/private value 32B）；
- SHA-256、HMAC-SHA256；
- `readSecret` 16B；sender Ed25519 私钥与 relay resume token 永不进入能力链接。`readSecret` 与 sender key pair
  定义 capability link 身份；产品可以为新分享生成新 capability，也可以在 refresh 生命周期中保留它们。

Ed25519 公钥只接受 RFC 8032 的 32B 压缩编码；X25519 只接受 RFC 7748 的 32B little-endian
u-coordinate。全零 X25519 shared secret 必须拒绝。实现应优先使用 non-extractable key；由应用持有的私钥或
临时 shared-secret byte buffer 在派生完成后清零。运行时不暴露底层 key material 时，不要求伪造不可验证的清零保证。

### 1.2 整数、文本与 canonical CBOR

- 固定二进制头中的整数全部 big-endian；`u32/u64` 溢出在算术或分配前拒绝。
- 结构对象使用 RFC 8949 Core Deterministic CBOR：definite length、最短整数/长度、map key 按确定性顺序。
- closed schema map 只使用本文列出的非负整数 key；重复/未知 key、tag、float、undefined、indefinite length、
  非最短整数、非确定性 key 顺序和尾随字节全部拒绝。只有明确标为 open 的 extension map 可以接收未知 key。
- schema 版本字段值为 `1`；未知版本返回 upgrade-required，不做宽容字段解析。
- text 是有效 UTF-8；需要 NFC 的协议标识由各 schema 单独声明。catalog 名称按
  `windshare/path/v2-exact-utf8` 保留原始 Unicode code point sequence，不做隐式规范化或大小写折叠。
- 超过 JavaScript safe integer 的线值仍可用 CBOR `u64`，但 `ExactSize` 和所有本地文件 offset 上限
  明确为 `2^53-1`，使浏览器文件 API 能逐字节精确表达。

### 1.3 固定宽度身份

| 身份 | 编码 | 生成/语义 |
|---|---:|---|
| `ShareInstance` | 16B | `crypto/rand`；每个内容实例生成一次，在该实例的注册、重连与服务生命周期内不变 |
| `NodeID` / `DirectoryID` / `FileID` | 16B | `crypto/rand`；实现保留 kind distinction；线上不编码 kind bit |
| `DirectoryGeneration` / `ScanAttemptID` | 16B | `crypto/rand`；目录提交/扫描 attempt 身份 |
| `FileRevision` | 16B | share-scoped `revisionIdentityKey` 对规范 source evidence 的 HMAC-SHA-256 前 16B，见 §5.2 |
| `LeaseID` | 16B | `crypto/rand`；每次成功打开独立 |
| `ProtocolSessionID` | 16B | transcript hash 截断，见 §6 |
| `ReceiverInstanceID` | 16B | receiver 随机诊断身份；不授权、不进 AAD/输出 ownership |
| `PeerPathID` / `AttemptID` | 16B | connectivity 的非零随机协商身份；首个 offer 绑定本次 attempt |
| OperationEnvelope `OperationID` / block `RecordID` | 16B | 线请求关联随机值；record 为完整 sender object SHA-256 前 16B；均不授予 receiver-local lifecycle authority |
| `OutputSessionID` | 16B | receiver 随机本地恢复身份 |
| `RelaySessionID` | 8B | relay 外层路由；不可信、不进 E2E 身份 |
| `LaneID` / `LaneEpoch` | u32 | LaneID 是 session 内唯一的逻辑 lane（可跨 channel instance 复用）；epoch 是 ProtocolSession 全局计数，初始为 0，之后每个 FrameChannel 严格递增且跨 lane 不复用 |
| page/local block/replay sequence | u32/u64/u64 | page u32；file-local block 与方向 sequence u64 |

secret、MAC、token 及其 authority-gating digest 使用常数时间比较；公开随机身份使用逐字节精确比较即可。
全零的随机 16B 身份保留并拒绝；`DirectoryID`/`FileID` 只由父
generation 中认证的 entry 建立，receiver 不能把任意 `NodeID` 改解释为另一 kind。
ShareInstance 在一次 root transaction 前生成，随后锚定 descriptor、catalog、revision、session 与 route，
不得在局部失败、网络重连、relay resume 或 receiver 页面刷新后悄悄换值。明确停止永久结束该 ShareInstance；
旧 descriptor/page/open 不能在另一 instance 下重放。产品是否为后续分享生成新 capability link，或在同一
capability 下通过明确认证的 refresh transition 创建新 ShareInstance，不属于 suite 的用户体验约束；refresh 不能
由旧 resume、旧 proof、墓碑缺失或本地 UI 状态隐式推断。

`PeerPathID/AttemptID` 只属于 connectivity signaling。WebRTC channel 建立后，connectivity 只把
`FrameChannel` 及 `LaneID/LaneEpoch` 交给 session；provider、TURN、RelayNode、路径成本和 peer identity
不得进入 BlockRef、cache、OutputSession 或 catalog 身份。

### 1.4 suite-02 逻辑名称与路径

当前 suite 的路径策略标识固定为 `windshare/path/v2-exact-utf8`。每个 catalog 名称必须是有效 UTF-8 的单一
segment，并逐 code point 保留 source provider 给出的名称；只拒绝空段、NUL、`/`、`\\` 以及精确的 `.`、`..`。
盘符、设备名、ADS、尾随空格/点、Unicode control/format character 或大小写关系本身不是 wire 拒绝理由。
control/format character 的安全呈现属于 receiver-local 安全策略；任何呈现结果都不能反向改变 wire 名称身份。
名称的 wire equality 与排序都是原始 UTF-8 bytes 的精确比较，不做 NFC、大小写或兼容性折叠。

完整 root-relative 路径由已认证的父子 NodeID 链派生，最大 256 segments、32 KiB UTF-8；receiver 不向 sender
提交本地路径。两个名称能否在目标文件系统共存属于 receiver-local materialization 问题：compatible-name 映射
不得改写 catalog、BlockRef 或恢复身份；其安全性与用户呈现由 receiver 文档定义。source provider 无法表示为有效 UTF-8 segment
的 child 可以作为 omitted entry 计数；只有无法维持稳定对象身份或父子关系时才使整个 scan attempt 失败。

sender 默认不跟随目录中的 symlink、junction、reparse 或 irregular object。产品可以把用户显式选择的 root
解析为一个稳定打开且 root-confined 的目标对象，但这种 source admission 不改变 wire 名称或给 receiver 路径 authority。

## 2. 能力链接、分享身份与 relay 注册

### 2.1 suite `0x02` 链接

```text
https://<frontend>/<shareId>?r=<relay-base>#<fragment>
```

`?r=` 可重复且只携非秘密 relay base hint。fragment 不进入 HTTP/WebSocket 请求；浏览器必须在任何应用发起的
relay/content 请求或日志记录前捕获 fragment 并从地址栏擦除。加载承载页面本身不受这条表述约束，因为 URL
fragment 不会进入该 HTTP 请求。receiver 可以为页面刷新或本地恢复保留 capability，但该 secret-bearing state
只属于 receiver-local policy：不得进入请求、日志、遥测、诊断导出或应用同步，且恢复时必须重新绑定本链接的
`shareId`、`pkHash` 与解封后的 ShareInstance。缺 fragment 时可以使用匹配的本地 capability 或由用户本地输入；
具体存储、保护、期限和清理由 receiver 决定，不参与 wire compatibility。

fragment 的原始字节固定为：

```text
suite(0x02,1B) || readSecret(16B) || pkHash(16B)
```

再以 strict base64url、无 padding 编码，结果必须恰为 44 ASCII chars；任何 padding、别名字母或非 33B
解码结果拒绝。`pkHash` 与 `shareId` 映射为：

```text
pkHash     = first16(SHA-256("windshare/v2 sender-key\x00" || senderPublicKey))
shareIdRaw = first12(SHA-256("windshare/v2 share-id\x00" || pkHash))
shareId    = base64url-no-pad(shareIdRaw) // 16 ASCII chars
```

shareId 与 fragment 标识 capability link；ShareInstance 标识该 capability 当前认证的内容实例，并在该实例的网络
重连和 receiver 页面刷新期间保持稳定。receiver 解封 descriptor 后必须同时验证 public key→`pkHash` 与
`pkHash`→URL `shareId`，再把 descriptor 的 ShareInstance 作为所有 v2 对象/session 身份锚。同一 capability 是否
以后指向新的 ShareInstance 属于 refresh 产品语义；receiver 必须把它当新内容实例，不能迁移旧 instance 的
catalog、lease、verified ranges 或输出 authority。`?r=` 继续是多值、非秘密提示。

relay 以 shareId 查路由但必须保存并比较完整 pkHash：活跃 shareId 若映射到不同 pkHash，返回不泄露现有
身份的 `share_id_collision`，不得覆盖；sender 只能生成新 key/fragment。相同 pkHash 的 fresh 重注册仍须
通过 challenge 私钥证明，且 route 活跃时返回 `already_registered`，不能把截断碰撞或持链者当 owner。

### 2.2 relay endpoint、identity 与 challenge

v2 对每个 `?r=` relay base hint 使用 [v2 session vector](../core/testvectors/v2-session.json) 中
`v2-relay-endpoint-normalization` 的严格 authority、base-path、query、
百分号转义和边界空白规则，但有两个有意收紧：userinfo 与 fragment 一律拒绝。`http/https` 分别规范为
`ws/wss`，scheme/host/IP/default port 按向量规范化；base path 只移除一个字面结尾 `/`，再追加固定且
**不含 shareId** 的 `/v2/ws`。`REGISTER_INIT`/`JOIN` 内的 `shareIdRaw` 才是 v2 share 路由输入。

规范化产生两个不同用途的 ASCII 值：

```text
DialEndpointASCII          = ws(s)://authority/base/v2/ws[?originalCanonicalQuery]
RelayIdentityEndpointASCII = ws(s)://authority/base/v2/ws
RelayIdentity              = SHA-256("windshare/v2 relay-identity\x00" ||
                                    RelayIdentityEndpointASCII)
```

query 可承载 relay admission credential，拨号时逐字节保留，但不属于 relay 的长期密码身份；userinfo、
fragment 和 redirect 都不是 v2 凭据或发现机制。公开 relay 必须使用 `wss`（本地测试可 `ws`），并以同一
规则从运维配置的 public base URL 得到 `RelayIdentityEndpointASCII`；不得从不可信 `Host`/
`X-Forwarded-*` 临时猜测 identity。HTTP upgrade path 必须逐字节等于规范化 base path + `/v2/ws`。
`v2-relay-endpoint-normalization` 向量同时冻结 base hint、拨号值和 identity 输入，sender 与 relay 任一侧
不一致都在 challenge proof 前失败。

注册/恢复在 descriptor 上传前执行一次性 challenge：

1. sender 只在 synthetic-root/NodeRecord/预算事务提交后发送 `REGISTER_INIT`：
   `{shareId, ShareInstance, pkHash, descriptorDigest, resumeTokenHash, mode}`；
2. relay 验证 shareId 映射，生成 purpose=`register(0)` 的
   `ChallengeID(16B) + ChallengeNonce(32B) + ExpiresAt`，在签名的 ExpiresAt 前有界缓存且只用一次；
3. sender 回 `REGISTER_PROOF`：`senderPublicKey + signature`，随后才发送 descriptor；
4. relay 验证 pkHash、签名、descriptor digest/大小及 descriptor 外层签名，原子发布 route 后回 `REGISTERED`；
5. ACK 前失败释放 route、descriptor 与 admission；客户端不得输出 ready 链接。

`mode`：fresh=`0x00`、resume=`0x01`；其他值当前均为 `unsupported_mode`。fresh 只发送 32B
`resumeTokenHash=SHA-256(token)`；resume 另在 TLS 连接内先出示 32B token，再取得
purpose=`resume(1)` 的新 challenge。token 只增加节点本地恢复约束，**不能替代私钥证明**。

注册/恢复签名 preimage：

```text
domain = mode==fresh ? "windshare/v2 relay-register\x00"
                     : "windshare/v2 relay-resume\x00"
domain || shareIdRaw(12) || ShareInstance(16) || pkHash(16) ||
descriptorDigest(32) || resumeTokenHash(32) || RelayIdentity(32) ||
ChallengeID(16) || ChallengeNonce(32) || u64_be(ExpiresAtUnixSeconds)
```

明确停止是独立的一次性 challenge：sender 先发 `STOP_INIT`，relay 绑定完整 init 签发
purpose=`stop(2)` challenge，再验 `STOP_PROOF`。签名 preimage 为：

```text
"windshare/v2 relay-stop\x00" || shareIdRaw(12) || ShareInstance(16) || pkHash(16) ||
RelayIdentity(32) || StopID(16) || ChallengeID(16) || ChallengeNonce(32) ||
u64_be(ExpiresAtUnixSeconds)
```

challenge expiry 是排他的：`now == ExpiresAt` 已过期；ledger 在验签前原子消费 challenge，因此错误签名不能
重试成 oracle。ChallengeID 不回显于 proof frame，因为当前连接 attempt 唯一拥有它，但 ID、nonce、purpose
与 expiry 全部受 ledger binding 和签名约束。现有已证明的 sender 连接仍必须完成该 exchange，不能把连接归属
当成协议所有权。

STOP 接受后，relay 必须先原子封存该 route 的 stopped 结果，再结束精确 participant 集合并返回 `STOPPED`。
在停止事务的保留期内，同 StopID 的并发或后续重试幂等；提交结果不确定时 route 立即 fail-close，只能用同一
StopID 重新证明和收敛，不得从普通 I/O error 猜测是否已停止。STOP 使现有 route、resume credential、challenge
与 session authority 失效；旧 proof 或旧 resume 不能重新取得该轮分享的 authority。

停止记录的文件格式、锁、journal、压缩、配额和保留期属于 relay storage policy，不是 wire 合同。回收停止记录前，
relay 必须已经删除或失效所有能恢复该 route 的活动状态。suite 不要求为历史 StopID 或 ShareInstance 保存永久、
无界的墓碑，也不把墓碑回收解释为 refresh authority。以后若用同一 capability 创建不同 ShareInstance，仍必须
完成绑定新 instance、descriptor digest 与 relay identity 的 fresh challenge/proof；它不是旧 route 的 resume，且
relay 可以按部署或产品策略拒绝该 refresh。部署可以另行保留审计历史，但其容量与耗尽行为不是 wire 常量。

descriptor 总长上限 16 KiB。relay 只保留 descriptor 与外层 route 状态，不保存 catalog page。
join 成功回 `RelaySessionID + descriptor`；ACK 前 join 可以在部署配置的短暂、有界发布窗口得到 `starting`，窗口后
返回 `not_found`。实际窗口与 retry backoff 是 relay policy，不参与 route identity。

### 2.3 relay v2 binary control

v2 注册控制只接受以下 big-endian binary frames；magic/长度/reserved/模式不符立即关闭注册 attempt，不回显
attacker 字段：

```text
REGISTER_INIT = "WS2R" || wire:u8(2) || mode:u8 || reserved:u16(0) ||
                 shareIdRaw(12) || ShareInstance(16) || pkHash(16) ||
                 descriptorDigest(32) || resumeTokenHash(32)                 // 116B
CHALLENGE = "WS2Q" || wire:u8(2) || purpose:u8 || reserved:u16(0) ||
             ChallengeID(16) || ChallengeNonce(32) || ExpiresAt:u64          // 64B
REGISTER_PROOF = "WS2P" || wire:u8(2) || mode:u8 || reserved:u16(0) ||
                  senderPublicKey(32) || signature(64)                       // 104B
REGISTERED = "WS2K" || wire:u8(2) || reserved(3B zero) || shareIdRaw(12) ||
               ShareInstance(16) || descriptorDigest(32)
RESUME_CREDENTIAL = "WS2T" || wire:u8(2) || reserved(3B zero) || resumeToken(32)
STOP_INIT = "WS2X" || wire:u8(2) || reserved(3B zero) || shareIdRaw(12) ||
            ShareInstance(16) || pkHash(16) || RelayIdentity(32) || StopID(16) // 100B
STOP_PROOF = "WS2V" || wire:u8(2) || reserved(3B zero) ||
             senderPublicKey(32) || signature(64)                             // 104B
STOPPED = "WS2Y" || wire:u8(2) || reserved(3B zero) || StopID(16)
JOIN = "WS2J" || wire:u8(2) || reserved(3B zero) || shareIdRaw(12)
DESCRIPTOR_UPLOAD = "WS2U" || wire:u8(2) || reserved(3B zero) ||
                     descriptorLength:u32 || descriptor sender-object bytes
DESCRIPTOR_DELIVERY = "WS2D" || wire:u8(2) || reserved(3B zero) || RelaySessionID(8) ||
                       descriptorLength:u32 || descriptor sender-object bytes
OPAQUE_ROUTE = "WS2O" || wire:u8(2) || reserved(3B zero) || RelaySessionID(8) ||
               ciphertextLength:u32 || ciphertext(1..65536)
SESSION_RETIRED = "WS2F" || wire:u8(2) || reserved(3B zero) || RelaySessionID(8) // 16B
```

`purpose` 固定为 register=`0`、resume=`1`、stop=`2`，并必须与当前 attempt 类型相同；fresh/resume mode
仍为 `0/1`。`descriptorDigest = SHA-256(descriptor sender-object bytes)`。REGISTER_INIT 长度固定，任何 mode
出现尾部或未知 mode 均拒绝。resume 的 RESUME_CREDENTIAL 必须紧跟 INIT 且在发 challenge 前验证；fresh
出现该 frame 拒绝。REGISTER_PROOF 后 sender 恰发送一个
`DESCRIPTOR_UPLOAD`；它没有尚未分配的 RelaySessionID，也不得用零值伪装 delivery。relay 只在成功 JOIN 后
以新分配的非零 RelaySessionID 发送 `DESCRIPTOR_DELIVERY`。两种 frame 的方向、magic 与长度不可互换；
digest、上限、外层 sender signature 全部验证后才发 REGISTERED。当前已定义错误码：1 malformed、2 unsupported_mode、
3 share_id_collision、4 already_registered、5 challenge_expired、6 invalid_proof、7 descriptor_invalid、
8 not_found、9 starting、10 admission、11 stopped。错误 frame 为
`"WS2E"||wire:u8(2)||reserved:u8(0)||code:u16||retryAfterMilliseconds:u32`。只有 starting/admission 可带
非零 retry hint；stopped 与其余 code 必须为 0。receiver 将该 u32 值视为最早重试建议，并可使用更长的本地
backoff。未知 code 在 retry hint 为 0 时作为不透明的永久 attempt failure 处理；未知 code 携非零 hint、未知
frame 形状或尾字节仍拒绝。这样未来可以增加不授予重试 authority 的诊断结果，而不改变现有注册状态机。

JOIN 后 client→relay 只允许 `OPAQUE_ROUTE`；relay→client 允许 `OPAQUE_ROUTE` 或 `SESSION_RETIRED`。
WebSocket 已认证连接角色决定方向；外壳不得出现 kind、direction、
terminal、lane、operation、file 或 size 字段。ciphertext 可以是 ClientHello/ServerHello/LaneHello/LaneAccept/
LaneReject 或 OperationEnvelope 的不透明字节；relay 只校验非零 RelaySessionID、`1..65536` 长度与连接对该 route
的 sender/receiver ownership。只要旧 frame 仍可能被接受，同一 ShareInstance 就不得把该 RelaySessionID 分配给
另一 session；allocation、tombstone 与安全回收机制属于 relay policy。
An active owner is forwarded. Frames for a retained former ID are discarded session-locally. Unknown or compacted
expired IDs do not create state and are dropped; repeated probing may be rate-limited or close that connection. A
non-owner using a currently active ID is an authenticated connection-role violation and may close that connection.
`SESSION_RETIRED` 是 relay 对已结束 session 的精确、幂等生命周期通知：命中本地 RelaySessionID 时只关闭对应
channel；本地不存在或已关闭的 ID 不得创建状态且直接忽略。畸形 frame 仍是 connection-level protocol violation；
该控制不能被 data 无限饿死；局部 admission 失败只退休精确 session。只有共享 peer link 无法继续有界推进或
framing 已不可信时才 fail-close 整条 link。ID 只有在已在途 `OPAQUE_ROUTE` 不可能命中新 session 后才能安全回收。

## 3. transport-neutral sender object

descriptor、CatalogPage、DirectoryError、FileRevisionDescriptor 与 BlockRecord 共用外壳：

```text
wireVersion:u8(2)
flags:u8(0)
reserved:u16(0)
ciphertextLength:u32_be       // 包含 16B GCM tag，不含 nonce/signature
nonce:12B
ciphertextAndTag:ciphertextLength
signature:64B
```

固定开销 84B；`ciphertextLength >= 16`。未知 flags/reserved、长度不符、超对象上限或尾随字节拒绝。
当前所有 flags 都必须为 0；未来扩展必须通过新 suite 或明确协商，不能静默翻转受 AAD/signature 覆盖的 header。
完整 object 上限固定为 descriptor/directory-error/revision 各 16,384B、CatalogPage 61,440B、
BlockRecord 4,194,816B；plaintext 必须非空。调用方只能通过对象类型构造带上述 ceiling 的 binding，不能传入
任意 domain/context/maxBytes 形成无界 envelope。

每类调用提供 ASCII `objectDomain` 与固定 `objectContext`：

```text
contextHash       = SHA-256(objectContext)
aad               = objectDomain || 0x00 || contextHash || first8BytesOfObjectHeader
signaturePreimage = objectDomain || 0x00 || contextHash ||
                    objectBytesThroughCiphertextAndTag
```

receiver 已知 context 后先验 Ed25519 签名再解密；descriptor 是唯一 bootstrap 例外：它先在 16 KiB
上限内解密，再以 link `pkHash` 验 public key，随后验签，任何一步失败都丢弃。持链者虽能造 AEAD，
但不能产生 sender 签名。

| 对象 | `objectDomain` | `objectContext` | key |
|---|---|---|---|
| descriptor | `windshare/v2 object/descriptor` | suite || pkHash || shareIdRaw | descriptorKey |
| catalog page | `windshare/v2 object/catalog-page` | ShareInstance || DirectoryID || u32(page) | catalogKey |
| directory error | `windshare/v2 object/directory-error` | ShareInstance || DirectoryID | catalogKey |
| revision descriptor | `windshare/v2 object/file-revision` | ShareInstance || FileID | fileObjectKey |
| block record | `windshare/v2 object/block-record` | ShareInstance || FileID || FileRevision || u64(localBlock) || u32(DataLength) | fileSegmentKey |

对象领域字面量不含尾 NUL；表中 `|| 0x00` 是统一域终止字节。对象 ciphertext 的逐字节重传幂等；
缓存逐出后允许用新随机 nonce 重 Seal BlockRecord，身份仍由语义 context 确定，`RecordID` 随密封字节变化。

### 3.1 HKDF tree

`K(secret,label,context) = HKDF-SHA256(secret, salt=nil, info=ASCII(label)||0x00||context, 32)`：

```text
descriptorKey  = K(readSecret, "windshare/v2 descriptor", pkHash)
catalogKey     = K(readSecret, "windshare/v2 catalog", ShareInstance)
fileObjectKey  = K(readSecret, "windshare/v2 file-object", ShareInstance || FileID)
revisionKey    = K(fileObjectKey, "windshare/v2 file-revision", FileRevision)
fileSegmentKey = K(revisionKey, "windshare/v2 file-segment", u64_be(segment))
sessionAuthKey = K(readSecret, "windshare/v2 session-auth", ShareInstance)
```

`segment = floor((LocalBlockIndex * chunkSize) / 16 GiB)`，乘法用溢出安全除法实现。每个 AES-GCM key
最多 `2^32` 次 Seal；descriptor/page/revision seal-once 仍计一次，BlockRecord 重 Seal 与多 receiver 扇出
都计入 segment key。达到上限只永久失败对应 revision，不升级为整个 share 失败。

## 4. descriptor、Catalog 与目录事务

### 4.1 ShareDescriptor schema

canonical CBOR map：

| key | 字段 | 合同 |
|---:|---|---|
| 0 | schema | `1` |
| 1 | wireVersion | `2` |
| 2 | suite | `2` |
| 3 | ShareInstance | bstr 16 |
| 4 | SyntheticRoot DirectoryID | bstr 16 |
| 5 | chunkSize | power-of-two `[1 KiB,4 MiB]` |
| 6 | capabilities | u64 bitset |
| 7 | senderPublicKey | bstr 32 |
| 8 | createdAtSeconds | non-negative int ≤ `2^53-1` |
| 9 | pathPolicy | exact `windshare/path/v2-exact-utf8` |

capability bits：0 catalog、1 file-range、2 authenticated-mtime。未知 bit 表示 receiver 可以忽略的可选能力；
忽略后仍无法正确解释 core object 或安全完成请求的能力必须改用新 schema/suite 或显式 critical extension，不能借
unknown bit 改变已知语义。多 relay hint 继续由可重复 `?r=` 表达，且不能改变分享身份。descriptor
不含 root entries、文件/字节/块总数、跨文件地址或 OperationID。同一 ShareInstance 只 Seal 一次并供所有 receiver/relay 重用。

### 4.2 CatalogPage 与 entry

CatalogPage map：0 schema；1 ShareInstance；2 DirectoryID；3 DirectoryGeneration(16B)；
4 PageIndex(u32)；5 Terminal(bool)；6 PreviousDigest(32B)；7 Entries(array)；8 OmittedCount(u64)。

entry 是定长 7 元数组：

```text
[Kind, NodeID, Name, ExpectedSize|null, ModifiedSeconds|null, ModifiedNanos, Precision]
```

Kind directory=`1`、file=`2`；Name 是符合 §1.4 的 exact UTF-8 segment；目录 size 必为 null，文件 size 为
`0..2^53-1`。mtime 缺失时 `[null,0,0]`；Precision seconds=`1`/milliseconds=`2`/nanoseconds=`3`，
ModifiedSeconds 必须在 `[-(2^53-1),2^53-1]`；`ModifiedNanos` 分别必须为 0、1e6 的倍数或
`0..999999999`。输出仅在值存在且后端声明支持时恢复。
同级名称按原始 UTF-8 bytes 精确比较和升序排序，随后才分页；kind、NodeID、OS 枚举顺序、Unicode canonical
equivalence、大小写关系与 receiver UI locale 都不得参与排序或 wire collision。普通目录出现逐字节相同的两个
名称说明 provider 无法给出稳定、无歧义的枚举，该 attempt 失败；case-fold 或目标文件系统 collision 由 receiver-local
compatible-name mapping 解决。synthetic-root 的逐字节重复名称必须在 transaction 前取得稳定逻辑别名；别名与
source locator 的映射只属于 sender-local preparation。

page 0 的 PreviousDigest 是 32B zero；后续为前一页**完整 sender object bytes**的 SHA-256。PageIndex
从 0 连续；唯一 Terminal page 提交 generation，之后追加拒绝。Terminal 前的已认证 page 是可渐进展示和选择的
provisional prefix，但不能证明目录完整、最终计数或 complete artifact；scan 未提交时 receiver 只退休该 generation
的 completeness authority，不把 prefix 变成 durable have-state。页面最多 256 entries、完整 sender object 最多
60 KiB。超过一页只按编码大小/entry 上限切分，不受 UI 行数控制。

Unsupported reparse/symlink/irregular child 或无法编码为 §1.4 segment 的 child 不跟随且不发 NodeID，终页只累计
`OmittedCount`；单项 omission 不使兄弟项失败。目录替换/改类型/reparse、逐字节重复名称、枚举前后身份变化或
其他无法证明 pages 来自同一 opened directory 的证据仍使整个 attempt 失败，且不提交 generation。

### 4.3 DirectoryError

map：0 schema；1 ShareInstance；2 DirectoryID；3 ScanAttemptID；4 Code(u16)；5 Retryable(bool)；
6 RetryAfterMilliseconds(uint|null)。永久错误在 share 生命周期逐字节复用；瞬时错误携带 sender 建议的最早
重试延迟，receiver 可以施加更长的本地 backoff。
Retryable=false 必须配 null；Retryable=true 必须配正 u32 毫秒整数。transient-io 必须 retryable；budget 只有在
session/process 容量可释放时可 retryable，share 累计硬上限则永久；cancelled 与其余 code 不建议自动 retry。
每次实际重试使用新 ScanAttemptID。

### 4.4 root 与普通 generation 事务

分享准备只读取每个 selected root 自身的 opened identity、name、size 与 mtime，不枚举后代。synthetic-root、
selected-root NodeRecord、pages 与 terminal 必须作为一个 generation 原子提交；只有提交成功后才能构造 descriptor
和发送 `REGISTER_INIT`。transaction、journal、spill 与 recovery 的存储形式属于本地实现。

selected roots 数量必须在 1..4,096，名称总 UTF-8 bytes ≤1 MiB；每个 root 必须最终 admission 为打开后确认的
regular file/directory。产品可以拒绝 root symlink/reparse，也可以在用户显式选择时解析一次并把稳定 opened target
作为 root；irregular object 仍拒绝。所有 root 名按 exact UTF-8 bytes 排序，重复名先取得稳定逻辑别名；任何仍无法
消歧或完成 stable admission 的 root 都在 transaction/REGISTER 前结束。

普通目录的 `LIST_CHILDREN` 可以渐进发布 §4.2 provisional pages，但只有唯一 Terminal page 提交完整、不可变
generation。目录身份绑定父 generation 的 NodeRecord 和 sender-private opened-object evidence，不绑定 receiver path。
已发布页面在 retained 期间必须逐字节重放；没有活动 operation 或本地 pin 依赖后，sender 可以逐出该 generation。
逐出后，指定旧 Generation 的请求返回 signed stale error，Generation=null 的新请求可以产生新 generation；绝不能
重扫后复用旧 DirectoryGeneration 或伪造旧 page bytes。任何可选 catalog backing 只能保存认证元数据，不能保存
内容字节或延长 `LiveOnly` 分享生命周期。预取、singleflight、保留期、内存与 spill 容量是有界本地策略。

## 5. FileRevision、lease 与 file-local content

### 5.1 几何

`ExactSize ∈ [0,2^53-1]`；`BlockCount = ceil(ExactSize/chunkSize)` 只在内存派生。零文件为 0 块；
非空文件末块长度由 size 派生。任何 wire `BlockCount` 字段或一个块跨两个 FileID 必须拒绝。

`BlockRef = (FileID, FileRevision, LocalBlockIndex:u64)`；range 为 canonical、排序、不重叠不相邻的
`[offset,end)` u64 集合。`ReadRange` 只请求相交块；首尾合计冗余小于 `2*chunkSize`。

### 5.2 Revision descriptor 与打开

FileRevisionDescriptor map：0 schema；1 ShareInstance；2 FileID；3 FileRevision；4 ExactSize；
5 ModifiedSeconds|null；6 ModifiedNanos；7 Precision。没有 OperationID、LeaseID 或 BlockCount。

`OPEN_REVISIONS` 一次最多 64 个 FileID，可带每项 initial ranges；response 逐项且保持请求顺序：

```text
success = [FileID, 0, RevisionObjectBytes, LeaseID, LeaseTTLMilliseconds, RenewAfterMilliseconds]
error   = [FileID, 1, RevisionErrorCode, Retryable, RetryAfterMilliseconds|null]
```

success 的 `LeaseTTLMilliseconds` 必须是正 u32 毫秒整数，`RenewAfterMilliseconds` 必须满足
`0 < RenewAfterMilliseconds < LeaseTTLMilliseconds`。sender monotonic clock 决定实际 expiry，receiver 按认证值
安排续期并可以提前重连；suite 不固定 TTL。revision error 的 `Retryable=true` 必须携正 u32 毫秒整数，
`Retryable=false` 必须携 `null`；receiver 可以施加更长的本地 backoff。
每个 success 是独立 lease；批量不共享续期/释放/失败。RevisionStore 在发 descriptor 前必须：验证 catalog
private candidate + ExpectedSize、建立稳定 source、完成句柄与 quota admission、注册 drift invalidation。
`SourceIdentity` 是 provider 规范化的 sender-private opaque object identity；Windows volume/file ID、POSIX
device/inode 只是当前 provider 的例子，不是 suite 白名单。`VersionCandidate` 再包含 size、修改时间及 provider
mutation/version evidence。两者都
必须从父 generation 的已打开对象取得，不能只保存路径；open 时同一
root slot/relative locator 必须重新打开并匹配两项 evidence。相同 FileID 的并发首次 open 可以共享或独立执行，
但成功请求各发独立 LeaseID；一个请求的取消不能撤销已经向其他请求发布的 source。

稳定 source 可以由排除写入的已打开句柄、可靠 mutation/version evidence、snapshot 或其他可审计 provider
能力建立。每次读取都必须继续绑定同一已打开对象并验证冻结证据；路径和平台名称本身不能证明稳定性。
无法提供这些能力的 provider 返回 `unsupported_stability`。具体文件系统、操作系统和 provider 覆盖属于
平台验证矩阵，不是 wire 白名单。产品可以按已声明的有界策略对小文件使用临时 snapshot；会造成显著额外磁盘、
写入或保留期的完整副本必须由用户显式选择，并说明空间、保密与清理成本。suite 只要求 snapshot 进入同一
source evidence 与资源预算，不按文件大小一律禁止或要求复制。

`FileRevision` 标识 share 内一个已验证的 source-evidence version；handle 与 lease 只控制资源保留，不定义
revision 身份。`OpenStable` 与 `Verify` 成功后，从 frozen catalog 的规范值构造按下列顺序逐字段 u32-BE
length-framed evidence；ModifiedTime 编码 presence、seconds、nanoseconds 与 precision：

```text
RevisionEvidence = framed(
    ShareInstance, FileID, SourceIdentity, VersionCandidate,
    ExpectedSize, ModifiedTime, ChunkSize
)
FileRevision = Trunc128(HMAC-SHA256(
    revisionIdentityKey,
    "windshare/file-revision/v1" || RevisionEvidence
))
```

32B `revisionIdentityKey` 在 live-share preparation 时独立随机生成，不复用协议加密 key。live share 拥有该 key；
只有所有依赖它的 admitted open/read authority 都结束后才能销毁。

Lease TTL and renew-after are the authenticated values returned by OPEN/RENEW. A sender may enforce a bounded local
cumulative lifetime or deny renewal under admission policy, but it must return the typed revision result and cannot
shorten an already advertised lease. The suite does not impose a two-hour lifetime.
A lease ending carries evidence, not receiver publication state:

- `relinquished`: an authenticated `RELEASE_LEASE`; the receiver gives up that lease, but this does not prove
  that output committed;
- `undelivered`: rollback only when the lease result provably could not have been learned by the receiver;
- `detached`: expiry, session/service loss, ambiguous OPEN delivery, or a later renewal failure after the receiver
  may know the lease; the receiver may reconnect and resume.

Revision invalidation is a separate tuple-global authority transition, not a lease-ending outcome. The first
authoritative ending wins; an unknown/replayed LeaseID is a no-op, and a late release cannot replace expiry's
detached evidence. No block-delivery path may infer receiver output completion.

Each detached ending updates the revision-level deadline before removing its lease:

```text
recoveryUntil = max(recoveryUntil, endedAt + RevisionResumeGrace)
```

`RevisionResumeGrace` is a bounded local policy, not wire identity; it may be zero on constrained providers, while a
longer value improves best-effort resume without guaranteeing source availability. For expiry, `endedAt` is
the authoritative `expiresAt`. The update applies even while sibling leases or readers remain active, and acquiring
another lease never clears it. Relinquished and undelivered endings release their lease/session charges immediately.
An otherwise idle stable source closes immediately only when no reader, active
lease, or unexpired detached deadline remains; an earlier detached deadline is never erased by a later
relinquishment. Readers defer physical close, and active readers or leases are never pressure-reclaimed.

An idle source retained only by `recoveryUntil` is best-effort recovery state. It normally remains resident until
the deadline, but new transfer work may reclaim it under an actual stable-handle limit. After explicit
relinquishment, grace expiry, or pressure reclamation, durable receiver checkpoints and bounded cache evidence may
remain, but they do not pin the live source. A later request must reopen the frozen catalog object and repeat stable
open plus source-identity, version, size, and modified-time verification.

Reopen comparison has only `Match`, `Mismatch`, and `Unavailable`. Exact evidence equality reuses the same
derived `FileRevision` and issues a new random lease. Proven different evidence or drift invalidates that revision;
missing evidence, permission or temporary I/O failure, cancellation, and any incomplete comparison issue no lease
and are reported precisely under their own error semantics. This extra I/O—and possible resume failure
when the live source changed, disappeared, or cannot be verified—is the deliberate cost of not pinning handles.
A newly authenticated revision/generation may describe changed content, but old leases, cache entries, or verified
ranges never migrate to it.

RevisionStore retains invalidation evidence while any active lease, operation or advertised recovery window can still
refer to that revision. If metadata pressure prevents safe retention, sender retires the affected revision/FileID
authority and returns typed stale/invalidation results. It may require a new catalog generation, but it cannot stop new
revision admission for unrelated files. Explicit relinquishment does not revoke bounded sealed block cache, but every
cache read still requires a valid new lease for the same revision. Invalidation revokes that cache and all leases and
sends the affected operations a sender-signed file error. The receiver retires only that file transaction as
`InvalidatedRevision`; its `VerifiedDurableRanges` cannot move to another revision.

Online TTL/RenewAfter values are relative durations, and the sender monotonic clock is authoritative; receiver wall
clock, Unix time, and relay time never decide expiry. Normal process stop ends related operations and lease/source
authority, and only then destroys the revision identity key. An OS closes handles after a
crash; relay route grace does not retain revision identity authority. Lifecycle evidence uses safe IDs/digests and
closed enums; an enabled local trace may additionally record paths and bounded raw errors, but never as authority.

### 5.3 BlockRecord

BlockRecord map：0 schema；1 ShareInstance；2 FileID；3 FileRevision；4 LocalBlockIndex；5 Data(bstr)。
Data 长度必须等于由 descriptor 派生的块长。完整 sender object 最大 `MaxChunkSize + 512 = 4,194,816B`。
同 revision 的所有 Data 只能来自 RevisionStore 的同一 admitted object。cache miss 重读仍须在 source 变化
校验内完成，并用新 nonce 重 Seal。

## 6. ProtocolSession transcript、lane 与 OperationEnvelope

### 6.1 sender-authenticated transcript

receiver 从 descriptor 验证 sender key 后生成 `ReceiverNonce(32B)`、X25519 ephemeral key 与诊断用
ReceiverInstanceID。ClientHello canonical binary body 为：

```text
"WS2C" || wire:u8(2) || ShareInstance(16) || ReceiverInstanceID(16) ||
ReceiverNonce(32) || ReceiverX25519Public(32)
```

随后附 `ClientProof = HMAC-SHA256(sessionAuthKey,
"windshare/v2 client-hello\x00" || SHA-256(body))`。sender 在任何 catalog/revision admission 前验证 proof，
并对 `(ShareInstance,ReceiverNonce,receiverPublic)` 的 hash 保留有界 replay evidence。保留期内的精确重放直接
丢弃或返回无 authority 的失败；证据回收后，即使再次处理相同 body，也必须使用新的 sender ephemeral key/nonce
形成不同 transcript，且在对端用原 receiver private key 证明能够发送有效 envelope 前不得取得昂贵业务资源。
任何重放都不能恢复旧 ProtocolSession、traffic key、lane 或 operation。保留时长、rate limit 与握手 admission
预算属于本地策略。

ServerHello body：

```text
"WS2S" || wire:u8(2) || SHA-256(ClientHelloWithProof) || SenderNonce(32) ||
SenderX25519Public(32) || u32_be(initialLaneID) || u32_be(initialLaneEpoch=0)
```

附 Ed25519 signature：`"windshare/v2 server-hello\x00" || SHA-256(ServerHelloBody)`。

```text
transcriptHash    = SHA-256(ClientHelloWithProof || ServerHelloWithSignature)
ProtocolSessionID = first16(SHA-256("windshare/v2 protocol-session\x00" || transcriptHash))
dh                = X25519(localPrivate, peerPublic)
handshakeSecret   = HKDF-SHA256(dh, salt=sessionAuthKey,
                    info="windshare/v2 handshake\x00" || transcriptHash, 32)
receiverToSender  = K(handshakeSecret,"windshare/v2 traffic/receiver-to-sender",transcriptHash)
senderToReceiver  = K(handshakeSecret,"windshare/v2 traffic/sender-to-receiver",transcriptHash)
```

新 ProtocolSession 使旧 OperationID、terminal、lane attach 全部失效。只有用当前 traffic key 认证的
LANE_ATTACH 可以延续 session；RequestedLaneID=0 时分配从未使用的非零逻辑 LaneID，非零时只可重附该
session 已拥有的 LaneID。初始 FrameChannel 使用 LaneEpoch=0，
之后每次 attach 从 ProtocolSession 全局计数器取得前值+1；即使 LaneID 不同也不得复用 epoch。
接收 grant/hello 时只要求 epoch 严格大于**该 LaneID** 上次接受值，允许 gap；不得用跨 lane 的全局
接收 watermark 拒绝乱序到达，因为已签发但丢失的 grant 会烧掉计数值，并发 lane 也可乱序建立。
全局 counter 到 `2^32-1` 后拒绝新 grant 并建立新 ProtocolSession，绝不 wrap。
RelaySessionID 改变不参与以上任何派生。ReceiverInstanceID 虽受 transcript 完整性保护，但不授权、不进
envelope AAD、不进 OutputSession identity。

### 6.2 OperationEnvelope

每个 FrameChannel 的 `Recv` 与 `Send/SendTerminal` 分别保持串行、可靠有序语义；并发组织、router/writer、
goroutine 或 actor 结构不属于 wire 合同。

```text
wireVersion:u8(2)
flags:u8                 // bit0 direction: 0 receiver→sender, 1 sender→receiver
reserved:u16(0)
sequence:u64_be
ciphertextLength:u32_be  // 包含 GCM tag
nonce:12B
ciphertextAndTag
```

固定开销 28B（tag 另在 ciphertext 内）；整帧 ≤65,536B，故 canonical plaintext ≤65,492B。
AAD：

```text
"windshare/v2 operation-envelope\x00" || wire || direction ||
ShareInstance || ProtocolSessionID || u32_be(LaneID) || u32_be(LaneEpoch) ||
u64_be(sequence) || u32_be(ciphertextLength)
```

每方向/LaneEpoch sequence 从 0 严格递增；FrameChannel 可靠有序，因此 replay window 固定为下一序号 1 帧，
重复、跳号、回退、跨 epoch 重放为 ProtocolSession error。`2^64-1` 用后关闭该 lane，不得 wrap；每次 Seal
仍使用新随机 nonce。

Ordinary plaintext is the canonical CBOR map `0 MessageKind(u8); 1 OperationID(bstr16|null); 2 Body`.
`OperationID` MUST be fresh and never intentionally reused within a ProtocolSession. The session retains enough bounded
replay evidence to handle active and recently completed operations idempotently, and it can never admit an old ID as a
new operation under the same traffic keys. Each ProtocolSession therefore has a bounded cumulative admission lifetime:
when an implementation can no longer preserve that property within its local budget, it ends or replaces the session.
The concrete budget and evidence representation are not wire constants.
`SESSION_TERMINAL` MUST use null; every other operation request/response/error/cancel MUST use a non-null ID. The ID is
wire correlation, not local lifecycle authority. Local continuation, terminal import, cancellation, and cleanup must
remain bound to the exact admitted operation generation, so delayed work cannot affect a replacement generation even if
an adapter repeats a wire ID. The local binding representation is not transmitted or prescribed by suite.

| kind | value | Body |
|---|---:|---|
| LIST_CHILDREN | 1 | `[DirectoryID, Generation|null, PageIndex]`；一个 final CATALOG_RESULT/ERROR，扫描中可有 progress |
| CATALOG_RESULT | 2 | sender control，恰好一个 page/error object bytes，结束 LIST_CHILDREN |
| OPEN_REVISIONS | 3 | ≤64 项 `[FileID, InitialRanges]` |
| OPEN_RESULTS | 4 | sender control，逐项 success/error，项数/顺序与 request 相同并结束 operation |
| RENEW_LEASE | 5 | `[LeaseID]` |
| RELEASE_LEASE | 6 | `[LeaseID]`；重复 release 幂等 |
| REQUEST_BLOCKS | 7 | `[LeaseID, LocalBlockIndex[]]`，最多 256 indices |
| BLOCK_FRAGMENT | 8 | §7 特殊 binary plaintext |
| CANCEL | 9 | `[ReasonCode]`；重复 cancel 幂等 |
| OPERATION_ERROR | 10 | sender control 或 receiver AEAD error |
| SESSION_TERMINAL | 11 | sender-signed，无 OperationID |
| LANE_ATTACH | 12 | established lane 上请求/返回一次性新 lane grant |
| SCAN_PROGRESS | 13 | sender control `[ScanAttemptID,DiscoveredEntries]`；同 operation 零或多条 |
| OPERATION_COMPLETE | 14 | sender control `[ResultCount]`；结束 release/block operation，renew 禁止 |
| LEASE_RESULT | 15 | sender control `[LeaseID,LeaseTTLMilliseconds,RenewAfterMilliseconds]`；结束 renew |
| PEER_OFFER | 16 | receiver→sender；开启一个 E2E peer negotiation operation |
| PEER_ANSWER | 17 | sender control；同 operation 一个语义答案，精确重放幂等丢弃，不结束 candidate trickle |
| PEER_CANDIDATE | 18 | 双向；绑定 PEER_OFFER 的 path/attempt identity；canonical 精确重放幂等丢弃 |

InitialRanges 是 canonical `[Start,End)` u64 数组：排序、不重叠、不相邻，每文件最多 256 段、每个 OPEN
合计最多 1,024 段。REQUEST_BLOCKS 的 index 唯一且严格递增。一个 operation 恰有一个 final：
CATALOG_RESULT、OPEN_RESULTS、LEASE_RESULT、OPERATION_COMPLETE、OPERATION_ERROR 或被 CANCEL；保留 detailed
replay evidence 期间，同 OperationID 的重复 final/fragment 丢弃。能够完整认证并精确绑定该 OperationID 的冲突内容终止该
operation，并使其结果不可用，但不自动终止无关 operation 或健康 lane。只有冲突同时破坏 session 级身份、顺序、
framing 或共享 authority 时才升级为 session error。详细证据回收后同 ID 一律作为 stale operation 拒绝，不能重新
admission；无法继续识别 stale ID 时按上面的累计预算换代 session。REQUEST_BLOCKS 为每个 index 交付一个
完整 record 后以 `OPERATION_COMPLETE(ResultCount=request count)` 结束，故缺块不能被静默当成功。
RENEW_LEASE 只以 LEASE_RESULT 或 OPERATION_ERROR 结束；RELEASE_LEASE 以 OPERATION_COMPLETE(0) 结束。
PEER_OFFER operation 接受一个 PEER_ANSWER 与任意有界 PEER_CANDIDATE；由 receiver CANCEL、sender
OPERATION_ERROR 或 SessionTerminal 结束。answer 不是 final，candidate 可先于 answer 到达。相同 authenticated
SemanticBody 的 answer 重放不再次交付或推进答案基数；不同的第二个 answer 终止该 peer operation，除非同时存在
独立的 session 级不变量失败。

sender control 的签名外壳固定为 canonical CBOR map：

```text
SignedControl   = {0:1, 1:SemanticBody, 255:Signature(bstr64)}
UnsignedControl = {0:1, 1:SemanticBody}
```

signature 不是 SemanticBody 的字段。验签成功后 session 返回 field 1 的 canonical encoding，因此业务 body
可以是 map 或 array，不会因签名层丢失类型。SemanticBody 固定为：

```text
CATALOG_RESULT     {0:1, 1:ObjectBytes}
OPEN_RESULTS       {0:1, 1:RevisionOpenResult[]}
OPERATION_ERROR    {0:1, 1:Scope(u8), 2:Code(u16), 3:Retryable,
                    4:RetryAfterMilliseconds|null, 5:Message(non-empty NFC UTF-8 <=512B)}
SESSION_TERMINAL   {0:1, 1:SessionCode(u16), 2:Message(non-empty NFC UTF-8 <=512B)}
LANE_ATTACH grant  {0:1, 1:1, 2:LaneID, 3:LaneEpoch, 4:AttachNonce(16B)}
SCAN_PROGRESS      {0:1, 1:ScanAttemptID, 2:DiscoveredEntries(u64)}
OPERATION_COMPLETE {0:1, 1:ResultCount(u32)}
LEASE_RESULT       {0:1, 1:LeaseID, 2:LeaseTTLMilliseconds, 3:RenewAfterMilliseconds}
PEER_ANSWER        SignalBody（§6.3）
PEER_CANDIDATE     SignalBody（§6.3）
```

`LEASE_RESULT` 的 TTL/RenewAfter 使用 §5.2 与 OPEN success 相同的正 u32 和相对大小约束。

LANE_ATTACH request Body 为 `{0:1,1:0,2:RequestedLaneID}`；response 与 request 共用非空 OperationID。SCAN_PROGRESS 的
DiscoveredEntries 单调，不能当 page 或最终总数。receiver 发 OPERATION_ERROR 时 Body 使用同一 error
schema 且没有 SignedControl 外壳；它只有 traffic-key AEAD 权威，不能伪装 sender error。
error Scope 固定：1 ProtocolSession、2 directory、3 revision、4 block、5 peer；OPERATION_ERROR 只允许 2–5，
已定义 Code 必须落在对应 §8 范围，未知 Code 只能使用 §8 的 opaque permanent-failure fallback。scope 1 必须使用
SESSION_TERMINAL/本地 terminal。CANCEL ReasonCode 固定：
1 user、2 superseded、3 output-abort、4 timeout、5 lane-race；receiver→sender CANCEL 无 sender signature，
sender 取消用签名 OPERATION_ERROR(cancelled)，不得发送无签名 CANCEL 冒充 receiver 意图。

sender 发出的非 transport-neutral 控制统一携 Ed25519 signature。签名 preimage：

```text
controlDomain || 0x00 || ShareInstance || ProtocolSessionID || u32(LaneID) || u32(LaneEpoch) ||
direction(1) || u64(sequence) || MessageKind || OperationID-or-16-zero ||
SHA-256(canonical UnsignedControl)
```

operation domain=`windshare/v2 control/operation`；terminal=`.../session-terminal`；lane attach=`.../lane-attach`。
AEAD 合法但 sender signature 错误终止 ProtocolSession；AEAD 无法认证时只产生无 ID 本地 terminal，不向对端
反射 attacker-controlled OperationID。

### 6.3 E2E peer signaling reservation

suite-02 base profile 由 receiver/browser 作为 offerer。这个角色不是安全身份；未来经明确协商的 connectivity
extension 可以定义 role reversal，但必须使用独立 schema/message kind，不能把现有 PEER_OFFER 方向静默反转。
三个 connectivity payload 使用 Core Deterministic CBOR 定长数组：

```text
Offer/Answer = [1, PeerPathID:bstr16, AttemptID:bstr16, SDP:tstr]
Candidate    = [1, PeerPathID:bstr16, AttemptID:bstr16, Candidate:tstr,
                SDPMid:tstr|null, SDPMLineIndex:uint16|null,
                UsernameFragment:tstr|null]
```

两种 identity 都必须非零。首个 PEER_OFFER 的 pair 绑定该 operation 内全部 answer/candidate；替换一个字节、
旧 AttemptID 重放或跨 PeerPath 拼接都终止该 negotiation。SDP 必须非空、有效 UTF-8/NFC 且 ≤60 KiB；
Candidate 非空且 ≤4 KiB；SDPMid/UsernameFragment 各 ≤256B。receiver 的 PEER_OFFER/PEER_CANDIDATE Body
直接是 SignalBody。sender 的 PEER_ANSWER/PEER_CANDIDATE 把 SignalBody 放入统一 SignedControl field 1；
验签后 session 只把该 field 的 canonical bytes 交给 connectivity codec。

`PeerPathID` 标识一个 ProtocolSession 内的 direct path；每个 negotiation attempt 使用新的 `AttemptID`、
PEER_OFFER OperationID 与本地 generation，绝不重开旧 operation。并发 path/attempt 数量、DataChannel 策略、
timeout、backoff 与恢复次数属于有界 connectivity policy，不进入 wire 身份。DataChannel Open 只证明 transport
phase 成功；它仍须完成 §6.4 lane admission，late callback 不得影响 replacement generation。

A well-formed sender-signed `OPERATION_ERROR` with peer scope and the exact admitted operation remains attempt-local.
A signature proves sender identity, not message kind, failure scope, or peer binding. An authenticated semantic conflict
that can still be unambiguously confined to one admitted peer operation seals and terminates that operation. It becomes
session-fatal only when parsing cannot remain synchronized or when session identity, signature, sequence, direction,
continuation ownership outside that operation, or another shared authority is no longer trustworthy. Invalid, zero, or
cross-binding adapter results are local adapter-contract failures and cannot mint remote terminal authority.

接收方向的每个 OperationID 代际只有一个 continuation authority。实现必须在有界状态内保证：精确 answer/candidate
重放不再次交付或消耗 peer-work quota；不同 candidate 恰好计费一次；超过 quota 只产生一个 operation-local
candidate-limit 结果；attempt 结束后，迟到且 binding-compatible 的消息不能重新打开 operation。ledger、queue、
dedup 与 adapter 的组件归属属于本地架构，不是 wire 合同。错误 response kind、binding 变化或冲突 answer/final
按上面的最小可信作用域规则失败。
Because transport acceptance does not prove remote routing state, an ambiguous initial `PEER_OFFER` retains its exact
generation-bound replay until operation end. After lane migration, that replay must be observed before dependent
`PEER_CANDIDATE`; the remote drops exact request replays idempotently. A migrated `CANCEL` may arrive first and
authoritatively ends the operation before any later replay.

协商失败以 scope=peer 的 sender-signed `OPERATION_ERROR` 结束该精确 operation：`0x5001` negotiation、
`0x5002` timeout、`0x5003` candidate-limit、`0x5004` channel-admission。该 operation 不得重开，因此 wire 上
`Retryable=false` 且 `RetryAfter=null`；这不禁止 connectivity policy 使用新的 AttemptID 和 OperationID 恢复
瞬态网络失败。健康 relay/lane 与 ProtocolSession 不受影响，只有已认证的 session 不变量失败才能扩大作用域。

本地错误分类、日志或残缺 callback graph 不能制造 ProtocolSession terminal。只有精确 operation evidence 或
已认证 session 不变量失败才能扩大故障作用域；receiver-local publication 与 cleanup 继续受 §9 边界约束。

这些消息始终在 OperationEnvelope/WS2O 内，relay 不见 SDP、candidate 或 peer identity。PeerPathID/AttemptID
不授权内容，也不参与 ProtocolSession、block/cache/output 身份；DataChannel Open 后仍须先取得 lane grant，
完成 WS2A/WS2B，才以 LaneID/LaneEpoch 附加到现有 ProtocolSession。provider、TURN 与路径成本不进本合同。

### 6.4 新 FrameChannel attach

receiver 必须先在已认证 lane 取得上面的 sender-signed grant；grant 按 sender 的有界本地策略过期且只消费一次，
receiver 不假设固定寿命并应尽快使用。新 channel 的
第一帧不是 OperationEnvelope，而是固定 LaneHello：

```text
"WS2A" || wire:u8(2) || ShareInstance(16) || ProtocolSessionID(16) ||
LaneID(u32) || LaneEpoch(u32) || GrantOperationID(16) || AttachNonce(16) ||
Proof(32)
Proof = HMAC-SHA256(receiverToSender,
        "windshare/v2 lane-hello\x00" || all preceding LaneHello bytes)
```

sender 在任何 queue/reassembly admission 前验证 session、epoch 严格大于该 LaneID 已接受值、未消费 grant、
nonce 与 proof，原子消费
grant，再返回：

```text
body = "WS2B" || wire:u8(2) || SHA-256(LaneHello) || SenderNonce(16)
ack  = body || Ed25519.Sign(senderKey,
       "windshare/v2 lane-accept\x00" || SHA-256(body))
```

通过 HMAC 认证但不能接纳的 candidate 返回固定 signed rejection；HMAC 无效、畸形或未知 key material 只能
silent-close，不能反射 attacker 字段：

```text
body = "WS2N" || wire:u8(2) || code:u8 || reserved:u16(0) ||
       SHA-256(LaneHello)(32) || retryAfterMilliseconds:u32
reject = body || Ed25519.Sign(senderKey,
         "windshare/v2 lane-reject\x00" || SHA-256(body))
```

当前已定义 code 为 1 unknown-session、2 stale-epoch、3 grant-expired、4 grant-consumed、5 admission-limited、
6 stopping、7 grant-mismatch；只有 code 5 可携非零 u32 retry hint，其余必须为 0。receiver 可以采用更长的
本地 backoff。未知 code 只有在 retry hint 为 0 时可作为不透明、不可重试的 candidate rejection；未知 code 携
非零 hint 不得创造重试 authority。WS2A/WS2B/WS2N 长度分别 109/117/108B；所有 reserved、尾字节与全零
identity/nonce 均拒绝。

DataChannel Open 只转移 phase，不建立 admission settlement authority。sender 只有在完整 LaneHello 通过 HMAC
及 exact ProtocolSession routing 后，才能原子决定是否消费或拒绝 grant；若 timeout/cancel 已先结束该 attempt，
不得消费 grant 或签 response。有效 hello 已取得 settlement authority 后，authenticated accept/reject 胜过并发
timeout、cancel 或 transport close。receiver 验证 exact hello digest 与 sender signature 后同样保留 WS2B/WS2N；
WS2B 还必须与对应 lane/content route 一致发布，才能把 channel 视为 admitted。

每个 replacement attempt 重新取得新的 grant OperationID 与 one-use grant；不得复用旧 grant、proof 或 candidate
channel。authenticated WS2N `admission-limited` 的 `RetryAfter` 是不可绕过的最早重试时刻。rejection 结束精确
candidate/attempt；是否创建新 attempt 由有界 connectivity policy 根据已认证原因决定。只有精确绑定该
ProtocolSession 的 authenticated terminal authority 能产生 `stop-session`。

receiver 验签后双方才把 channel 绑定到该 LaneID/Epoch，两个方向 sequence 从 0 开始。错误只关闭候选
channel；消费或过期的 grant 保留有界 replay evidence，重复 hello 必须得到 signed grant-consumed/expired
rejection 或 silent-close，不能再次绑定。base profile 在没有仍有效的既有 lane 或预取 grant 时建立新
ProtocolSession；未来可以协商由 session secret 保护、单次消费的 reconnect ticket。RelaySessionID 单独永远不能
复活旧 session。

实现必须有界限制待发送 control/data work，并保证 control、terminal 与 CANCEL 不被数据背压无限饿死。terminal
一旦被接受，就不得再发送会被误解为 terminal 之后的新业务数据，并应在关闭 transport 前尽力使其可见。队列数量、
预留容量、调度比例、pump/actor 结构与 `SendTerminal` 的具体实现属于本地策略。

## 7. BLOCK_FRAGMENT 与重组

BLOCK_FRAGMENT 解密后的 plaintext 不用 CBOR，固定为：

```text
codec:u8(1) || kind:u8(8) || flags:u8(bit0=last) || reserved:u8(0) ||
OperationID(16) || RecordID(16) || FragmentIndex:u32 || FragmentCount:u32 ||
TotalLength:u32 || PayloadLength:u32 || Payload
```

头 52B；结合 envelope/GCM，每片 `PayloadLength ∈ [1,65,440]`。`FragmentCount ∈ [1,128]`，
`TotalLength ∈ [1,4,194,816]B`；sender 可以根据链路和调度使用小于上限的分片，count 只需等于本 record 实际片数。
last 仅能出现在 `index=count-1`，所有 payload 长度之和必须精确等于 TotalLength。在 envelope AEAD、所有整数、
count 与 TotalLength 上限通过前不得分配重组缓冲。

重组 key=`ProtocolSessionID + OperationID + RecordID`。相同 index+bytes 幂等；相同 index 不同 bytes、
两个 last、总长/count 冲突或完整长度不符只终止 block operation。已认证有效新分片才算 progress；inactivity
timeout 与 CANCEL/完成后的 replay-evidence 时长是 receiver 的有界链路策略，不能形成 suite 隐含最低带宽。
重复分片不刷新 inactivity deadline；详细证据回收后旧 OperationID 仍不得重新 admission，必要时换代 session。
完整 object 的
SHA-256 前 16B 必须等于 RecordID，再验 sender object signature。

## 8. 错误域与资源预算

### 8.1 error code

| 范围 | code | 语义/作用域 |
|---|---|---|
| session | `0x1001..1008` | auth、replay/sequence、malformed、version、budget、sender signature、illegal terminal、sender stopped；结束 ProtocolSession |
| directory | `0x2001..2008` | stale、permission、collision、too-wide、budget、permanent-io、transient-io、cancelled；跳过该 subtree |
| revision | `0x3001..3008` | stale、not-found、unreadable、unsupported-stability、quota、lease-expired、drift、invalid-lease；只结束 file revision |
| block | `0x4001..4006` | invalid-ref、out-of-range、object-auth、fragment-conflict、timeout、cancelled；只结束 block/range operation |
| peer | `0x5001..5004` | negotiation、timeout、candidate-limit、channel-admission；结束精确 peer negotiation operation |

表中列出 suite-02 已定义的 code。已知 scope 内的未知 u16 code 只有在 `Retryable=false` 且 RetryAfter 为 null 时
可以作为不透明的永久错误，并按该 scope 的最小作用域结束；实现可以记录 raw code，但不能从它推断新行为。
未知 code 若声明 retryable、携带 delay 或试图扩大 authority，必须拒绝。未知 session terminal code 仍只结束其
已认证的精确 ProtocolSession。未知 scope、错误消息形状或 schema version 继续严格拒绝。

Directory errors are signed and carry attempt/retry fields; revision and block errors are signed whenever
they are sender controls. A retryable revision item or `OPERATION_ERROR` carries an integer
`RetryAfterMilliseconds ∈ [1,30,000]`; a non-retryable result carries `null`. Both runtimes reject zero,
values above that bound, and delay fields on permanent results. Receivers may always wait longer than the
authenticated earliest-retry hint under their bounded wait/backoff policy.

Only the sender's typed stable-handle or active-lease capacity-busy outcome may become the authenticated
`OPEN_RESULTS` tuple `[FileID, 1, 0x3005, true, RetryAfterMilliseconds]`. The receiver validates the signed
control, exact quota code, `Retryable=true`, and present bounded hint before constructing capacity retry authority,
and does so before generic source/fault normalization. A generic quota error, an error string, local metadata or
seal exhaustion, missing/unreadable source, revision drift, and any non-retryable `0x3005` cannot mint that
authority or enter a capacity retry loop.

Receiver-local output errors never go on wire. Revision stable-handle pressure may retire only eligible idle
detached recovery state as described below; it never evicts an active lease or reader. If safe reclamation cannot
satisfy the request, the owning operation returns its exact typed denial instead of misreporting the source as
unavailable.

### 8.2 Wire 上限与本地预算

只有影响互操作或对端分配的值属于 wire 上限：

| 名称 | 值 |
|---|---:|
| selected roots / root names total | 4,096 / 1 MiB UTF-8 |
| entry name / canonical root-relative path / depth | 255B / 32 KiB / 256 segments |
| CatalogPage entries / sender-object bytes | 256 / 60 KiB |
| OPEN batch / initial ranges per file/request / block indices | 64 / 256 / 1,024 / 256 |
| BlockRecord / reassembled record | 4,194,816B |
| relay opaque ciphertext / OperationEnvelope | 1..65,536B / ≤65,536B |

ICE candidate count、operation/ClientHello/grant/RelaySessionID tombstone、fragment inactivity、route grace、
join-starting window 与 receiver retry/backoff 都必须有界，但不是 wire 常量。只有消息中签名或认证的 ExpiresAt、
TTL、RenewAfter 和 RetryAfter 值参与对应一次 exchange；接收方仍可使用更保守的本地资源与调度策略。

Process/share/operation concurrency, memory, disk, handles, workspace, cache, retries, and backoff remain bounded
implementation/deployment policy. Admission must reserve capacity before publishing ownership, and settlement must be
idempotent, but suite 不规定 coordinator 数量、锁顺序、queue/worker 结构、victim 选择或容量交接算法。

已发布且仍有效的 active reader/lease authority 不能因本地资源压力被静默回收。只为 best-effort recovery 保留、
当前没有 reader 或 active lease 依赖的 idle source 可以按本地策略回收；回收只降低后续恢复成功率，不能改变既有
revision 身份、伪造 invalidation 或删除 receiver checkpoint。无法安全取得容量时，sender 返回对应 typed capacity
结果；receiver 是否等待、采用何种公平性、jitter、worker 数量和累计预算属于有界本地策略。strict FIFO、跨 share
回收或 ticket fairness 都不是 suite 承诺。

Relay route/session quotas remain positive with per-share ≤ total. Active state, short anti-replay tombstones, and
durable stop history may use different bounded quotas; their accounting, compression, and reclamation are
deployment policy, and exhaustion returns the applicable typed admission error.

## 9. Receiver-local 边界

选择、产物规划、目标权限、checkpoint、publication、恢复与 UI 生命周期完全属于 receiver。它们不得增加
sender、relay、signaling、WebRTC 或 content wire 字段，也不得进入 ShareInstance、ProtocolSession、catalog、
BlockRef 或 sender-object 身份。route、lane、projection、progress 和 UI state 只能描述一次观察或运行，不能制造
本地输出 authority 或 durable have-state。

Receiver 只能从 §8 的精确 authenticated capacity 结果取得 capacity-retry authority；普通 I/O、错误文本或本地
metadata 不能制造该 authority。是否重试、等待多久、如何排队、使用多少 worker、如何呈现进度都属于有界本地
策略。receiver 必须遵守 sender 给出的最早重试时间，且旧 ProtocolSession generation 不能继续发请求；重连后
建立新的 authenticated session。capacity retry 不得重复取得输出 authority，也不得把已经验证的范围倒退为未验证。
预算耗尽时可以暂停、失败或要求用户继续，但必须如实保留已经提交的本地证据，不能把等待伪装成文件损坏。

本地持久恢复必须把 verified ranges 绑定到精确 operation、frozen receive intent、materialization binding、FileID、
FileRevision、canonical logical path、exact size、目标 authority 与 WindShare-owned object。revision、ownership 或
checkpoint 冲突只阻塞依赖该证据的最小作用域；cleanup 只能删除 ownership-proven unfinished state。

为支持页面刷新，browser receiver 可以在本地保留重新取得同一 capability 所需的 secret-bearing record。恢复时必须
重新验证 URL/local record 的 `shareId`、fragment `pkHash`、descriptor sender key 与 ShareInstance，并建立新的
ProtocolSession；只有同时匹配上述持久 checkpoint 的输出后端才能续用 verified ranges。capability record 本身不授予
目标文件系统、publication 或 cleanup authority。存储介质、加密方式、保留期限、跨 tab 协调和 UI 均属于 receiver
策略；不具备可靠本地恢复能力的输出方式必须明确降级，不能宣称刷新后可续传。

上述安全性质由[威胁模型](威胁模型.md)定义；当前 artifact、命名、降级和恢复体验见
[功能变化](重构功能变化.md)。Go/TypeScript 共享的 receiver-local canonical bytes 由

文件系统、数据库版本、picker 流程、容量默认值和恢复期限不得成为 wire compatibility 或密码身份的一部分。

## 10. 当前在线生命周期

当前生产只实现 `LiveOnly`：

```text
Preparing -> LiveOnly -> Stopping -> Stopped
```

- Preparing 失败从未 REGISTER；LiveOnly 的服务源是在线 sender。
- 显式 Stop/退出拒绝新 join，发送 sender-signed SESSION_TERMINAL，取消 scan/revision/lanes，完成
  `WS2X -> WS2Q(purpose=2) -> WS2V -> WS2Y`。收到 WS2Y 才能报告 relay-confirmed stop；退出路径不能因网络
  无限等待，未确认时必须持久保留本地 stop intent、绝不 resume 该 instance，并允许 relay 的短期 route grace 收敛。
- 意外网络/进程消失或未确认 stop 可以保留部署配置的短期、有界 relay route grace；期间 join 返回
  starting/not-found，不把旧 sender object
  冒充活动 sender，并立即结束/墓碑化既有 RelaySessionID。恢复仍需 purpose=1 新 challenge、resume token 与
  私钥 proof；已提交或本地持久标记为显式停止的 instance 永不走 resume。
- `Stopped` 是精确 ShareInstance 的终态。当前产品重新执行分享时生成新 capability link，但这不是 suite 不变量；
  未来可以通过 fresh proof 在同一 capability 下显式建立新的 ShareInstance。receiver 页面刷新只会为仍处于
  LiveOnly 的同一 instance 建立新 ProtocolSession，不创建 refresh；观察到新 ShareInstance 时必须按新内容实例处理。

当前 suite 没有 offline uploader、inventory commit、账户或寄存交付路径。M4 必须在需求和信任边界明确后
独立设计；可以引入新 suite，而不受当前未使用 flag、capability bit、对象 schema 或 Merkle 形状约束。

### 10.1 可执行证据

跨运行时合同向量由 `core/internal/protocolcontract` 生成，TypeScript 独立重建并验证。wire 向量覆盖
suite/link/shareId、HKDF、sender objects、registration/resume/stop、WS2O、WS2A/B/N、operation terminal、重组、
PeerPathID/AttemptID、hostile canonical CBOR 与线资源边界；修改任一身份轴必须失败。

receiver-local canonical contracts 与 wire vectors 共用生成/校验入口，但在 inventory 中分组，不能被解释成 suite
消息。平台 source/output/catalog、真实浏览器、文件系统 crash cut 与进程网络属于[Validation](validation.md)；
测试证据可以收窄当前产品承诺，不能扩大或重定义本文 wire authority。
