# WindShare 协议规范

> 本文概述当前 suite `0x02` 的协议语义和信任边界。WindShare 处于快速开发阶段，协议可随实现调整，
> 暂不承诺旧版本兼容。字段布局、编码常量和错误码以当前 codec 与跨运行时测试向量为准。

## 1. 范围与设计原则

WindShare 是在线 sender 驱动的端到端加密分享协议：先生成链接，再按接收方需求浏览目录和读取内容。
分享准备不递归扫描、预读、哈希或上传文件内容。

协议围绕以下语义组织：

- 能力链接授予读取能力；sender 私钥证明分享所有权和内容来源。
- 目录、文件版本和内容块具有独立于网络连接的身份，切换 relay/WebRTC 不改变它们。
- 接收方按目录和文件范围请求数据，无需先得到整份分享的文件数、总大小或全局块表。
- 认证完成后才使用远端数据；重放、重连和局部失败不能混用不同分享、版本或会话的状态。
- 输出位置、文件命名、ZIP、恢复记录和 UI 属于 receiver，本地实现可以独立演进。

协议变更时同步更新受影响的 Go/TypeScript codec、测试向量和本概览即可；开发期不为兼容旧实现保留分支，
也不预先规定未来功能的扩展槽位。当前解码仍按已支持的 suite/schema 校验，不能把无法识别的数据猜成已知语义。

## 2. 能力链接与身份

```text
https://<frontend>/<shareId>[?r=<relay-base>]#<fragment>
fragment = base64url-no-pad(suite(0x02,1B) || readSecret(16B) || pkHash(16B))
```

`pkHash` 由 sender 公钥派生，`shareId` 由 `pkHash` 派生。接收方解封 descriptor 后校验这条绑定关系，
再使用其中的 `ShareInstance`。具体派生字节见[链接实现](../core/link/link.go)。

`?r=` 可以重复，只提供非秘密 relay 地址提示。省略时，Go 与浏览器都使用能力链接自身的 origin（协议、主机、端口）作为 relay 基址；单独输入密钥时使用当前页面的提示或 origin。生成链接时，单个 relay 与该 origin 的根端点等价（`https`/`wss`、`http`/`ws`）就省略 `r`；非默认端点、子路径、查询参数和多 relay 列表仍显式保留。`trace=1` 独立控制浏览器诊断。

fragment 承载读取秘密，不随 HTTP 请求发送；浏览器捕获后
从地址栏移除。sender 私钥和 relay resume token 不进入链接。本地保存 capability 以支持刷新或恢复属于 receiver 策略。

| 身份 | 含义 |
|---|---|
| `shareId` / `pkHash` | 能力链接及其 sender 公钥绑定；relay 保存完整 `pkHash`，避免截断路由碰撞 |
| `ShareInstance` | 一次内容实例，贯穿 descriptor、catalog、revision 和 session；网络重连不改变它 |
| `DirectoryID` / `FileID` | 已认证目录树中的节点身份，类型由目录 entry 确定 |
| `DirectoryGeneration` | 一次目录扫描提交的不可变结果 |
| `FileRevision` | 文件的已验证源版本；由 share 私有 key 和 source evidence 派生，不靠预读内容哈希 |
| `LeaseID` | 一次成功打开文件后取得的临时读取资格 |
| `ProtocolSessionID` / `OperationID` | 已认证会话及其中的请求关联身份 |
| `LaneID` / `LaneEpoch` | 会话中的逻辑通道及其连接代际 |
| `RelaySessionID` / `PeerPathID` / `AttemptID` | relay 路由或直连协商身份，不授予内容或本地输出权限 |

诊断身份和本地恢复身份不代替以上协议身份。新内容实例或文件版本不能继承旧实例或旧版本的 lease、缓存证明和已验证范围。

## 3. 认证、加密与编码

suite `0x02` 使用 AES-256-GCM、HKDF-SHA256、Ed25519、临时 X25519、SHA-256 和 HMAC-SHA256。
AES-GCM 每次加密使用新的 96-bit 随机 nonce 和 128-bit tag；X25519 拒绝全零 shared secret。
密钥派生按用途分域，并绑定相应分享、文件、版本或会话上下文。

固定二进制头使用 big-endian 整数，结构消息使用 RFC 8949 Core Deterministic CBOR。
解码验证 schema、长度、整数范围和确定性编码；只有 schema 明确允许的可选能力或扩展才可忽略未知值。
文件大小和本地 offset 上限为 `2^53-1`，以便 Go 与浏览器精确表达同一字节范围。

Descriptor、CatalogPage、DirectoryError、FileRevisionDescriptor 和 BlockRecord 共用
[发送方对象外壳](../core/senderobject/codec.go)：版本头、nonce、密文与 GCM tag、sender 签名。
AAD 和签名绑定对象用途与语义上下文，不绑定 relay、lane 或接收方输出状态。

Sender object **wire version 3** authenticates a sealed-object commitment with ordinary Ed25519:

```text
prefix    = header || nonce || ciphertext || GCM-tag
signature = Ed25519.Sign(senderKey, UTF8(domain) || 0x00 || SHA256(context) || SHA256(prefix))
AAD       = UTF8(domain) || 0x00 || SHA256(context) || header
```

The header carries object version `3`; application/session version `2`, suite `0x02`, domain strings,
context encodings and the 64-byte signature width remain unchanged. Object version `2` is rejected;
senders, receivers and relays must upgrade together. The two 32-byte digests are computed locally,
not added to the wire object. The signed input is short (97 bytes for a BlockRecord). This is not Ed25519ph.
Object authentication additionally relies on SHA-256 collision resistance, matching the protocol's
128-bit signature security target; every prefix byte and every context axis is authenticated.

Every sender signature (objects, handshake, lane responses, control messages and relay proofs) uses
canonical 32-byte Ed25519 public keys in the prime-order subgroup, excluding the identity. A signature
is exactly 64 bytes: canonical curve point `R` of non-small order, and scalar `0 <= S < L`. Verification
requires the cofactorless equation `[S]B = R + [SHA512(R || A || message) mod L]A`.
[Shared acceptance vectors](../core/testvectors/ed25519-acceptance.json) cover malformed, noncanonical,
small-order and mixed-order inputs in Go and browsers.

Browser implementation: one verifier owns the sender key snapshot and imported key across message
kinds. Qualified WebCrypto is preferred; Noble additionally checks prime-order `R` so its cofactored
check has the same acceptance set. Capability probes detect known backend faults, not arbitrary
incorrect implementations. Native `NotSupportedError`, timeout (2 seconds) or `OperationError` disable
that backend for the identity and fully reverify with Noble; a native `false` remains an authentication
failure. Backend decisions enter the structured `sender_verification` trace. Opening an object owns
one byte snapshot and computes context/prefix hashes concurrently; verification and decryption reuse it.

接收方先验 sender 签名再解密。Descriptor 是引导例外：在大小限制内解密得到公钥，核对链接中的 `pkHash`，
再验签后使用。持链者知道读取秘密，仍不能伪造 sender 对象或 sender 控制消息。
同一对象的密文字节可重传；重新密封使用新 nonce，语义身份保持不变。

## 4. 分享与接收流程

1. **准备分享**：sender 打开用户选择的根对象，仅取得根自身元数据，提交 synthetic-root generation 后构造 descriptor。
2. **注册 relay**：sender 完成一次性 challenge 和私钥 proof，relay 校验 descriptor 后发布路由并确认，sender 才报告链接就绪。
3. **加入分享**：receiver 用 `shareId` 获取 descriptor，验证链接、公钥和内容实例绑定，完成端到端会话握手。
4. **浏览与读取**：receiver 按需请求目录页，打开文件版本取得 lease，再请求所需块；数据可以经 relay 或已认证的 WebRTC lane 传输。
5. **结束分享**：sender 停止服务并通过独立的 STOP challenge/proof 撤销 relay 路由；明确停止的 `ShareInstance` 不再 resume。

Relay endpoint 由 base hint 规范化后追加 `/v2/ws`。拨号 URL 可含 admission query，长期 `RelayIdentity`
不含 query。注册、resume 和 STOP 的证明绑定具体实例、relay identity 和一次性 challenge，不能相互重用。
Resume 还需要节点本地 token，但 token 不能替代 sender 私钥证明。

Each share retains its identity, `ShareInstance`, keys, and exact sealed descriptor bytes across relay
connections. Per-relay resume credentials exist before the first dial. If a publication acknowledgement
is lost, the sender authenticates resume with those credentials; a dial failure does not prove that
registration is absent. During recovery, only an authenticated `NotFound` permits fresh publication of
that material, without rebuilding the share or rescanning its sources.

Relay 保存 descriptor 和路由状态，转发不透明的端到端消息，不保存 catalog 或内容。
`RelaySessionID` 只用于连接角色授权的精确路由；旧路由消息不能命中新 session。

## 5. 目录与文件内容

### 5.1 Descriptor 与 catalog

Descriptor 提供 `ShareInstance`、synthetic-root ID、chunk size、capabilities、sender 公钥、创建时间和路径策略。
它不包含整棵目录树或分享总量，同一实例内可复用。

Catalog 按目录分页。Entry 描述节点类型、ID、名称、预期大小和可选修改时间。路径策略
`windshare/path/v2-exact-utf8` 保留原始 UTF-8 名称，按原始字节比较和排序，不隐式做 Unicode 规范化或大小写折叠。
名称是单一 segment，拒绝空段、NUL、路径分隔符及 `.`、`..`；完整逻辑路径由已认证的父子关系派生。
目标文件系统的命名兼容由 receiver 处理，不改写 catalog 身份。

每页绑定目录和 generation，并通过前页完整对象的 digest 串联。唯一 Terminal page 提交完整 generation；
此前的认证页可用于渐进浏览，但不能证明目录完整。重扫生成新的 generation，不能冒充旧页。
不支持的 child 可计为 omitted；无法确认目录对象或父子关系稳定时，该次扫描失败。

### 5.2 Revision、lease 与范围读取

`OPEN_REVISIONS` 逐项返回签名的 revision descriptor 和独立 lease，或明确的文件错误。
Sender 打开并验证 catalog 对应的稳定源对象，确认身份、版本、大小等证据后才授予读取资格。
源对象的稳定性可以由平台句柄、版本证据或 snapshot 等能力提供，具体机制由 source provider 决定。

Lease 的 TTL 和续期间隔由 sender 返回，sender monotonic clock 决定到期。续期、释放、到期与 revision
失效是不同事件；释放 lease 不表示接收方已经成功保存文件。闲置源保留和恢复宽限属于本地策略。
重新打开时，证据一致可复用同一 revision 并发放新 lease；确认源变化后旧 revision 失效，证据不足则返回相应错误。
Receiver 的文件读取句柄绑定不可变 revision，独立于 wire lease。正常会话内的 lease 到期（包括累计寿命上限）触发透明重新打开；
新 descriptor 的分享、文件、版本和 geometry 必须一致，才可保留已交付范围继续读取。换租约不重建输出或会话，先取得新租约再释放旧租约；
配额不足沿用现有等待机制，源变化不允许透明重试。

```text
BlockRef  = (FileID, FileRevision, LocalBlockIndex)
BlockCount = ceil(ExactSize / chunkSize)
```

块只属于一个文件版本，末块长度由精确文件大小派生，空文件没有数据块。
范围使用排序、合并后的 `[offset, end)` 集合，只读取相交块。
BlockRecord 绑定分享、文件、revision、块序号和数据长度；重新读取或使用缓存仍需要有效 lease 和版本校验。

## 6. 会话、操作与传输

握手由 receiver 的读取能力 HMAC 和 sender 签名认证，结合双方临时 X25519 密钥与 nonce 派生 transcript、
`ProtocolSessionID` 和双向 traffic key。新会话重新建立 operation 与 lane 状态；relay 路由 ID 不参与密钥派生。

业务消息封装在 `OperationEnvelope` 中，以 AEAD 绑定分享、会话、方向、lane、epoch 和 sequence。
每个 FrameChannel 提供可靠有序帧语义；每方向、每 epoch 的序号递增，重放或跨代混用被拒绝。
Sender 控制消息另带签名，接收方不能仅凭共享读取秘密伪造 sender 的结果或终止通知。

| 消息组 | 用途 |
|---|---|
| `LIST_CHILDREN` / `CATALOG_RESULT` / `SCAN_PROGRESS` | 按需浏览目录并报告扫描进度 |
| `OPEN_REVISIONS` / `OPEN_RESULTS` | 批量打开文件，逐项取得 revision 与 lease |
| `RENEW_LEASE` / `LEASE_RESULT` / `RELEASE_LEASE` | 续期或释放读取资格 |
| `REQUEST_BLOCKS` / `BLOCK_FRAGMENT` | 请求和传输文件块 |
| `OPERATION_COMPLETE` / `OPERATION_ERROR` / `CANCEL` | 明确结束或取消对应操作 |
| `SESSION_TERMINAL` | 结束已认证会话 |
| `LANE_ATTACH` | 授权新通道接入已有会话 |
| `PEER_OFFER` / `PEER_ANSWER` / `PEER_CANDIDATE` | 在端到端会话内协商 WebRTC |

`OperationID` 在会话内不复用。操作具有明确的完成、失败或取消结果；传输成功不代表接收方输出完成。
精确重放幂等处理，迟到消息不能重开已结束操作。Peer answer 后仍可交换 candidate，answer 本身不结束协商。

Operation admission reserves capacity for completion and cancellation.
When capacity is exhausted, new requests wait without blocking admitted operations.
Browser operation IDs use a session-local prefix and per-request-kind issuance counters. Detailed replay
records expire independently of this bounded issuance history: retired responses are discarded after
kind/scope validation, while never-issued identities remain session errors. Active operations and peer
attempt bindings retain their exact checks; the sender continues treating operation IDs as opaque.

WebRTC 当前由 receiver 发 offer，answer/candidate 绑定同一 `PeerPathID`、`AttemptID` 和递增 `AttemptSequence`。
Peer-scoped `OPERATION_ERROR` uses schema 2: fields 0–5 retain the failure metadata; field 6 is `[PeerPathID, AttemptID, AttemptSequence]`. Other scopes retain schema 1 without field 6. Peer bindings must match the active operation exactly. After the 30-second operation tombstone expires, a bounded per-path retirement boundary drops authenticated obsolete peer traffic without granting authority over fresh operations.
Peer code `0x500c` means connection resources were unavailable before ICE started. Authenticated capacity
deferrals preserve negotiation-attempt allowance without resetting elapsed recovery budgets or actual-start
rate limits. Native admission reserves mandatory UDP capacity before granting an attempt; optional TCP
listeners share that capacity. Waiters wake on release and remain cancellable. Automatic relay content
continues independently; P2P-only mode never falls back to relay content.
Sender resource admission has an 8-second subdeadline within the unchanged 10-second signaling-preparation
window. Its phase owner cancels the subdeadline on admission or teardown. Process-budget expiry reports
an attempt timeout; known socket-capacity deferrals retain code `0x500c`.
DataChannel 建立后，仍需 sender 签名的一次性 lane grant 和 LaneHello/LaneAccept 认证才能承载业务。
Lane epoch 由会话全局递增分配，各 lane 按自身已接受的 epoch 校验，允许并发建立时乱序到达。
直连失败可以继续使用健康 relay；既无可用 lane，也无有效 grant 时重新握手建立会话。
`PEER_PATH_CONTROL` demand with a zero content hold makes a path idle and reusable; revoke permanently retires its identity. Lane retirement releases admission after its pump and writer stop, while transport cleanup remains owned until lane/runtime completion.

较大的 BlockRecord 经 `BLOCK_FRAGMENT` 拆分，按会话、operation 和 record 身份重组。
接收方先校验认证、片数和长度再分配缓冲，完整重组后核对 record digest 和 sender 对象签名；缺块不能当作成功。

Receiver response waits distinguish first-fragment queueing from assembly inactivity. Before the first
fragment, unique authenticated fragments from earlier outstanding requests on the same lane renew the
wait. After the first fragment, only that operation's new fragments renew it. Heartbeats, duplicates,
later requests and other lanes cannot extend the wait; cancellation and lane retirement remain immediate.

## 7. 故障、资源与本地边界

错误按 session、directory、revision、block 和 peer 区分。能可靠定位的失败只影响对应操作或对象；
只有会话身份、认证、顺序或 framing 不再可信时才终止整个会话。重试依据结构化的认证结果和 retry hint，
不从错误文本推断。接收方遵守 sender 给出的最早重试时间，也可按本地策略等待更久。

线上消息和重组对象需要大小、批量与长度上限，具体值集中在 codec、共享常量和测试向量中。
并发、缓存、句柄保留、队列、超时、backoff、磁盘布局和调度公平性属于本地策略，不在本文逐项固定。
实现保持资源有界、取消和终止可推进；容量不足时返回相应错误，不静默撤销仍有效的读取资格。

An authenticated resume may replace a published live or grace route. The relay binds the route version
and owner before issuing the challenge, then checks both when committing the replacement. A changed
version returns `ResumeStale`; the sender retries resume. An unpublished starting route returns `Starting`.
Invalid credentials or identity do not authorize republishing. Cleanup retires only the replaced
connection generation and its relay sessions, preserving unrelated relay and direct paths.

STOP is irreversible for the stopped `ShareInstance`, including when no route is currently present.
The relay confirms it only after durable stop recording and exact participant cleanup. Pending or
uncertain stop state blocks resume and publication; the sender retains stop intent if confirmation is
lost. Recovery never changes source availability or authorizes reuse of a changed file revision.

The relay grants `WS2W` credits to both endpoints for outgoing opaque frames. Each grant carries independent
frame and byte deltas; at least one must be positive. Available credit is bounded to 64 frames and 4 MiB
per session. Each send reserves one frame and the full encoded `WS2O` size, including its route header.
Senders start with that window; receivers start with zero credit and receive fair allocations from the
shared destination capacity. Outstanding grants, queued frames, and physical writes share the same bound.
Credit applies only to its exact session and cannot recreate a retired session.

Receiver ingress has a separate, initially empty delivery window. After descriptor delivery, browser and
native receivers send `WS2B`: the reserved 8-byte prefix, 8-byte relay session ID, then big-endian u32
frame and encoded-byte credit deltas. Available credit is bounded to 256 frames and 16 MiB; at least one
delta is positive. Each outgoing `WS2O` consumes one frame and its complete wire size. Only application
consumption returns this credit, in batches of 64 frames; a relay socket write does not. This preserves
pipelined default-size block responses while stalled receivers backpressure only their own session.
Late grants cannot recreate retired sessions. Relay control traffic bypasses the delivery window.

Native relay connections use WebSocket Ping/Pong. Browsers send connection-local `WS2H` probes and the
relay directly echoes their nonce in `WS2A` acknowledgements; these frames never enter E2E session
routing. Probes, acknowledgements, and credit updates bypass content-credit waits and queued forwarding.
Heartbeats remain active during healthy direct transfers. Probe deadlines cover bounded physical writes,
and failure closes only that connection. Connection lifecycle owners schedule bounded attempts and slower
retries; heartbeat handlers do not initiate recovery.

Receiver 自行管理选择、输出权限、命名映射、产物发布和 checkpoint。
续传复用的已验证范围绑定精确分享实例、文件版本及本地输出证据；网络进度、lease 释放和 capability
本身都不能证明输出完成，也不能授予本地清理权限。
