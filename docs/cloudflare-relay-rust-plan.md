# Cloudflare 原生中转与 Rust 统一计划

状态：架构评估草案
最后更新：2026-08-09

## 目的

WindShare 应允许每位用户将私人中转部署到自己的 Cloudflare 免费账户，并把它作为个人中转配置导入。

在当前协议中，中转并非仅在 P2P 失败后才建立：它先承载发送端注册、接收端加入、ProtocolSession 初始通道和 P2P 信令，再作为加密内容帧的后备传输 Lane。它不是标准 TURN，也不参与 ICE 候选中继，因此不会提高 WebRTC 本身的 NAT 穿透成功率；但它能在直连不可用时独立完成 WindShare 传输，所以当前生产架构不依赖 TURN。

长期设计还应消除分别维护 Go 与 Cloudflare 中转语义的成本。建议采用一个 Rust 中转语义内核和两个平台宿主：

- TypeScript Cloudflare 平台壳调用 Rust/Wasm 语义内核，用于个人低流量部署。
- 原生 Rust 二进制程序，用于项目运营的中转、自托管和 Cloudflare Tunnel 部署。

Cloudflare 默认显式维护一个薄 TypeScript 平台壳：它直接使用 Worker、Durable Object、WebSocket 休眠、SQLite 和 Alarm 的平台 API，并通过窄 ABI 调用同一个 Rust/Wasm 引擎。当前高层 `workers-rs` 路径保留为可行性对照；只有它针对固定的 Cloudflare compatibility date 覆盖全部必需 API，并证明不透明载荷热路径没有额外整帧复制时，才可以替代默认平台壳。独立重写 TypeScript 控制逻辑不属于方案，因为它会重新形成两套服务端语义。

## 设计原则

- **Cloudflare 纯属可选能力。** 未配置个人中转时，创建分享、打开链接、P2P 协商和项目中转后备的体验必须保持不变。接收者不需要 Cloudflare 账户、额外安装或手动选择中转。
- **原生服务器是功能与性能基准。** Cloudflare 的单对象吞吐、休眠、Wasm、配额和队列限制不得进入原生服务器的默认值、热路径或依赖图。原生二进制程序不得依赖 Wrangler、JavaScript、Wasm 或 Cloudflare API。
- **统一决策，不统一 I/O 机制。** Rust 引擎统一认证、所有权、会话、恢复、停止和截止时间；原生与 Cloudflare 适配器分别实现最适合平台的转发、排队、背压和并发。不能为了复用代码把原生数据面降到最低共同能力。
- **Cloudflare 载荷由宿主持有。** 已获许可的不透明数据帧必须保持为 Cloudflare JavaScript 宿主持有的 `ArrayBuffer`；默认平台壳只读取固定信封头并直接调用目标 `WebSocket.send()`，不得把载荷复制进 Wasm linear memory，也不得让它进入 SQLite、结构化日志或无界应用队列。若后续协议协商有界批处理，批处理字节仍只能留在宿主内存并受明确字节预算约束。
- **平台壳执行，不裁决。** TypeScript 只能安装 Rust 引擎产生的下一状态，并执行其持久化增量、许可变更和提交后动作，再把平台结果规范化为事件返回引擎。它不得自行授权、恢复、替换、停止、退役会话或改变生命周期。这个边界是受测试和模块依赖约束的代码架构，不被描述成 TypeScript 与 Wasm 之间的安全隔离。
- **默认流程零新增操作。** Rust 重写本身不构成用户功能。个人中转只允许增加一次性的部署和导入步骤，此后的发送与接收流程不得新增技术选项。
- **信任切换必须显式。** 项目中转只有在发送者选择的 RelayPolicy 中才可作为后备；系统不得把“仅个人中转”静默降级为项目中转。运行时自动执行已选策略，不在传输过程中打断用户作技术决策。
- **部署准入不等于分享所有权。** 部署凭据只允许消耗该部署的资源。注册、恢复、替换和永久停止仍必须由分享级密码学证明授权，任何部署级凭据都不能单独接管分享。
- **持久化不进入载荷热路径。** SQLite 只保存有界生命周期状态、密封描述符和永久停止标记；不保存、排队或检查不透明内容帧，原生与 Cloudflare 数据帧转发都不执行数据库操作。
- **以测量决定切换。** 删除 Go 服务端之前，原生 Rust 必须完成相同互操作场景，并相对当前 Go relay 证明没有实质性的吞吐、延迟、内存或并发退化。如果共享边界造成退化，应继续拆分；不能以代码统一为理由接受产品降级。

### 用户可见结果

| 用户场景 | 预期变化 |
| --- | --- |
| 未配置个人中转 | 无变化；继续使用当前默认中转策略。 |
| 配置个人 Cloudflare 中转 | 仅首次增加部署和导入；之后仍创建一个普通分享链接。 |
| 接收分享 | 无变化；打开链接后自动尝试 P2P 和已发布的中转候选。 |
| 普通服务器自托管 | 继续运行独立原生二进制程序；功能不减少，性能不受 Cloudflare 限制。 |
| 中转故障 | 按创建分享时已明确选择的 RelayPolicy 自动尝试下一个候选，或在仅个人中转策略下明确失败。 |

因此，这不是面向所有用户的速度升级：对未启用者应是零变化；对启用者是信任边界和部署控制权升级，不承诺比项目中转更快。选择“仅私人中转”会主动以可用性换取更窄的信任面，必须在配置策略时说明，不能包装成无代价的自动优化。

## 当前建议

结论：**方案有条件可行，建议继续验证，但不能按“一个跨平台 Rust I/O 实现加部署页自动回传配置”的思路直接开工。** 可行的边界是让 Rust 承载中转服务的唯一控制面领域逻辑，Cloudflare 默认由 TypeScript 平台壳承接原生 API 与不透明数据面，原生服务器直接调用同一个 Rust 引擎；Cloudflare 上线和原生服务器迁移分别作发布决策。

采用 Rust 并不意味着可以立即删除 Go 中转。只有原生 Rust 在路由、所有权、生命周期、准入、持久化、可观测性和性能上独立通过验证后，才能退役 Go 服务端；Cloudflare 的原型或上线不能代替这些证据。平台代码不得重新实现共享决策，但必须拥有自己的高效 I/O、背压和转发机制。

引擎在会话建立后签发绑定 `relay_identity`、分享、会话、来源与目标连接、连接代次、方向和协议版本的 `ForwardPermit`。适配器对每个不透明帧做严格固定头检查和许可查找后直接转发，不把载荷送入状态机，也不为每帧产生持久化效果。许可的创建、替换和撤销仍完全由共享引擎决定。

原生适配器是性能参考实现，可以使用 Tokio、多核 Actor、有界公平队列和原生 WebSocket 背压。Cloudflare TypeScript 平台壳使用休眠和平台发送语义；只有测量证明必要时，才增加经过协商的有界批处理。平台差异只能改变内部容量和故障触发点，不能改变帧顺序、会话隔离、所有权或客户端可见的安全语义。

Cloudflare 与原生适配器必须承接现有中转的完整职责，包括注册、加入、密封描述符交付、初始 Relay Lane、P2P 信令承载、Relay Lane 恢复和不透明帧转发。不能把它建模成 P2P 失败后才临时创建的可选数据连接。

浏览器应继续使用 TypeScript 协议代码，Go 发送端和接收端应保留 Go 客户端编解码器。通过跨语言规范向量保持这些编解码器一致。除非后续测量证明存在明确收益，否则把浏览器协议代码迁移到 Wasm 不在本计划范围内。

TypeScript 平台壳是 Cloudflare 默认组成，不是发现 `workers-rs` 绑定缺口后的临时后备。低层 `worker-sys`、原始 `JsValue` 或未来高层 `workers-rs` 可以在证明必需 API 完整且热路径没有额外整帧复制后替换其部分或全部实现，但不能改变宿主持有载荷和 Rust 唯一产生控制决策的边界。若 Rust 引擎本身无法在 Workers 中可靠运行，而 Cloudflare 需要独立重写控制逻辑，则应把它作为新的架构决策重新评估，默认暂不交付，而不是削弱原生服务器或悄悄接受两套语义。原生功能和性能优先于服务端代码复用。

## 产品边界

个人 Cloudflare 中转面向单个发送者及其信任的接收者，不应被定位为无限容量的公共中转服务。配置个人中转只改变分享创建时使用的中转策略，不改变链接的打开方式、接收端交互或 P2P 优先级。每个部署应具备：

- 写入能力链接的公共中转端点。
- 仅由发送端保存、只用于新建路由资源准入的部署凭据。
- 独立于部署凭据的分享级注册、恢复、替换和停止证明。
- 部署级以及每个分享的连接数、会话数、消息大小和资源限制。
- 清晰且可分类的配额与容量错误，使客户端能够执行创建分享时已经选定的策略。

WindShare 应提供至少两种可理解的策略：按已配置顺序自动后备，以及只使用指定的私人中转。前者只会尝试用户预先纳入策略的候选；后者在私人中转不可用时明确失败，不会静默切换到项目中转。策略在中转配置阶段选择并成为后续分享的默认值，普通分享流程不增加技术选项。

Cloudflare API 令牌是基础设施管理凭据，与 `DeploymentAdmissionCredential` 不同。Deploy Button 使用 Cloudflare 自身的授权流程；只有高级 GitHub Actions 部署才需要把最小权限令牌保存在仓库密钥中。令牌绝不能粘贴到 WindShare、提交到 fork、写入分享链接或发送给接收者。

中转可能观察到网络元数据、时间、大小和访问模式。它不得接收能力片段、内容密钥、明文路径、文件元数据或文件内容。持久化状态仅限于路由生命周期数据、不透明的密封描述符、有界连接元数据、截止时间和永久停止标记（tombstone）。

## 目标架构

```text
Go CLI / 浏览器 / 未来客户端
              │
              └── 中转线协议
                    ├── Cloudflare TypeScript 平台壳
                    │     ├── 边缘 Worker：路由、升级与部署准入
                    │     ├── DeploymentControl DO：部署准入与总量预留
                    │     ├── ShareRelay DO：持久化执行与平台数据面
                    │     └── Rust/Wasm：严格控制协议与唯一语义内核
                    │
                    └── 原生 HTTP/WebSocket 路由器
                          ├── 进程级准入控制：部署总量与新建速率
                          ├── 每分享 Actor：生命周期与原生数据面
                          └── 原生 Rust：直接调用同一协议与语义内核

两条路径共享 Rust 严格协议实现和纯控制面引擎，但不共享平台 I/O 实现
```

客户端首先通过中转建立应用层会话，并经该会话协商 WebRTC Peer Lane。直连成功后，内容可以优先走 Peer Lane；直连失败、不可用或未在策略窗口内就绪时，内容走 Relay Lane，而中转控制通道仍保持可用。

### 共享控制面与平台原生数据面

共享引擎只决定部署资源能否准入，谁可以建立、恢复、替换和停止分享，哪些会话可以互通，以及许可何时失效。它不拥有 WebSocket，不保存载荷，也不规定队列实现。身份验证成功后，引擎签发绑定 `relay_identity`、分享、会话、来源与目标连接、连接代次、方向和协议版本的 `ForwardPermit`；适配器只在许可有效时转发符合帧边界的加密载荷。

控制消息、许可变更、断开、过载和截止时间进入引擎。已获许可的数据帧直接经过平台数据面，不逐帧进入状态机、结构化日志或持久化层。原生适配器可以使用多核 Actor 和异步背压；Cloudflare 适配器使用 Durable Object 的连接模型和发送语义。两者共享安全与顺序不变量，不共享平台容量上限。

### Cloudflare 热路径边界

当前 `OpaqueRoute` 是唯一的加入后中转信封，由 20 字节固定头和不透明密文组成：固定头包含 magic、版本与保留位、`RelaySessionID` 和密文长度。Cloudflare 平台壳必须以不产生载荷副本的视图检查完整固定头，验证协议版本、保留位、非零会话标识、长度上限和消息总长，再用来源连接及其 attachment 中的稳定连接 ID、角色和代次查找精确 `ForwardPermit`。只检查 magic 或仅按目标会话是否存在转发都不充分。

未协商批处理时，许可命中后的处理必须是同步热路径：不 `await`，不调用 Wasm，不访问 SQLite，不序列化 JSON，不记录载荷，也不创建持有密文字节的长期对象；目标套接字接收原始 `ArrayBuffer`。平台运行时内部是否复制不由 WindShare 保证，因此验证目标是消除应用可见的 JS→Wasm→JS 整载荷复制，并测量真实 CPU、内存、吞吐和失败行为，而不是宣称绝对零复制。

控制帧和许可不存在、失效或不匹配的帧走控制/失败路径。TypeScript 可以把有大小上限的控制帧交给 Rust/Wasm 严格解析和验证；Rust 返回版本化的状态转换、持久化增量、许可变更、提交后动作和 trace decisions。TypeScript 只执行这些结果。固定头的 Go、Rust 和 TypeScript 实现必须由同一规范常量和跨语言向量锁定；若未来信封无法在不读取密文的情况下完成分类和许可查找，应重构信封，而不是让不透明载荷进入 Wasm。

### WebSocket 升级前的寻址

Cloudflare 必须在升级 WebSocket 之前选定 Durable Object。因此，规范端点需要在 HTTP 路径中包含分享标识和请求角色，例如：

```text
/v2/shares/{share-id}/sender
/v2/shares/{share-id}/receiver
/v2/shares/{share-id}/stop
```

具体路由名称仍待确定，但升级前必须能够取得分享标识。第一条经过身份验证的协议消息必须重复相同的标识和角色，引擎必须拒绝任何不一致。这会把边缘路由与经过签名的协议意图绑定，而不是仅仅信任 URL 数据。

角色路径不能充当中转身份。配置和能力链接中的公共基础端点应先规范化为稳定的 `RelayIdentity`，再派生分享和角色 URL；第一条身份验证转录同时绑定 `RelayIdentity`、分享标识和角色。这样，同一部署的 sender、receiver 和 stop URL 不会被误认为不同中转，也不能把一个端点取得的证明转放到另一个端点。

### Cloudflare 适配器

Cloudflare 适配器默认是 TypeScript 平台壳加 Rust/Wasm 语义内核。TypeScript 拥有 Worker 与 Durable Object 类导出、WebSocket upgrade、休眠 API、attachment、存活套接字枚举、SQLite、Alarm、平台错误分类、结构化平台日志、`ForwardPermit` 执行缓存和不透明数据帧直转。Rust/Wasm 拥有严格控制帧解析、密码学验证、部署/分享/会话状态转换、许可变更、持久化逻辑增量、提交后动作和语义决策日志。平台日志可以补充运行时信息，但不能伪造或改写引擎决策。

无状态边缘 Worker 应负责：

- 规范化并验证请求路由。
- 应用 Origin、请求大小和明显滥用过滤。
- 把新路由的 `DeploymentAdmissionCredential` 交给 Rust/Wasm 验证，并按部署级引擎转换从控制对象取得短期、分享绑定且幂等的准入租约。
- 通过分享标识的稳定派生方式选择 `ShareRelay` Durable Object。
- 转发升级、恢复或停止请求，但不持有分享生命周期状态。

每个部署还需要一个 `DeploymentControl` Durable Object。无状态 Worker 加每分享对象无法原子执行部署级活动路由数、预留数和墓碑总量限制，因此这些职责不能散落在 Worker 实例中。部署级 Rust 引擎决定凭据代次、配额预留、幂等且会过期的准入租约及其确认或释放；TypeScript 对象持久化这些结果并附加构建和协议元数据。它不处理接收者加入、会话控制或内容帧。每分享对象在持久转换提交后执行确认或释放预留动作，结果不确定时把幂等操作结果返回引擎重试并对账。

每个分享由一个 `ShareRelay` Durable Object 独占管理。Rust 引擎决定发送端、接收端、活动会话、密封描述符、连接代次、意外断开宽限期、许可和永久停止标记的逻辑状态；TypeScript 对象执行持久化和平台动作。部署控制对象与分享对象之间只有稀疏的资源生命周期通知；它们不串联在数据路径上。

发送端首次注册会自然创建对象，不需要单独的预创建流程。对象创建后的放置位置具有粘性，因此部署文档应说明：发送端的首次注册位置会影响中转所在区域。

必须使用可休眠 WebSocket（Hibernatable WebSockets）。套接字附件只保存稳定连接 ID、角色和代次等恢复索引，不能复制完整会话状态或保存可独立授权转发的许可。对象被唤醒后，TypeScript 应把版本化、有大小上限的 `ShareRecord` 与平台仍存活的套接字观察结果交给 Rust 引擎，由引擎产生对账转换和新的完整许可快照；平台壳据此重建内存索引与 `ForwardPermit` 缓存，并把不一致显式转换为断开或清理事件。

需要跨驱逐存活的生命周期状态保存在 Durable Object SQLite 中。单个对象只使用一个 Alarm：持久状态保存所有逻辑截止时间，Alarm 始终指向最早一项，触发后把当前时间和已提交状态输入 Rust 引擎，再按其结果处理到期项目并重新调度。内存计时器和套接字附件都不能成为事实来源。数据帧不写入 SQLite。Cloudflare output gate 是运行时对存储写入的保证，平台壳负责按引擎计划正确发起事务和提交后动作，而不是自行实现或绕过 output gate。

### 原生适配器

原生进程应使用相同的引擎状态转换和线协议编解码器。进程级路由器把分享标识映射到每个分享的 Actor，Tokio 运行时跨核调度分享；每个连接使用有界队列，调度器必须在慢接收者之间保持公平，过载结果作为控制事件返回引擎。帧转发只做边界检查和 `ForwardPermit` 查找，不执行 SQLite 操作。

进程级准入控制器使用相同的部署准入状态转换，执行原生部署的活动路由总量、新建速率和幂等预留。它可以利用进程内并发原语和原生存储，不需要模拟 Durable Object，也不参与内容帧转发。

原生持久化适配器只保存与 Cloudflare 相同的逻辑生命周期事实，而不复制 Cloudflare 的表结构、Alarm 或容量限制。默认后端优先考虑 SQLite；持久提交在事务中完成，提交后的网络动作在事务外执行。重启后，任何已持久化但没有对应套接字的活动连接都必须经对账转换为断开状态，不能被当作仍然在线。

原生二进制程序及其默认配置不得依赖 Cloudflare SDK、JavaScript、Wasm 或部署工具。当前 Go 中转在原生 Rust 完成功能与性能对照之前继续作为发布路径；Cloudflare 适配器的限制不能成为替换 Go 的理由。

原生二进制程序覆盖：

- 项目运营的公共中转。
- 在 VPS 或本地服务器上的直接自托管。
- Cloudflare Tunnel；它仍是有用的部署方式，但依然需要一个源站进程。

### Rust 工作区边界

建议的模块拆分如下：

```text
windshare-relay-protocol     线协议编解码、规范转录和严格验证
windshare-relay-engine       纯部署/分享/会话控制状态、许可和提交计划
windshare-relay-engine-wasm  面向平台壳的版本化窄 ABI，不依赖 Cloudflare API
windshare-relay-native       Tokio HTTP/WebSocket、Actor、背压和进程生命周期
cloudflare/relay-host        TypeScript Worker、Durable Object、SQLite、Alarm 和休眠
```

原生适配器和 Cloudflare 平台壳是同级消费者，彼此不得依赖。`engine-wasm` 只包装 `protocol` 与 `engine`，不拥有 Worker、Durable Object、WebSocket、数据库或 Cloudflare 错误语义；默认发布路径不依赖高层 `workers-rs`。`protocol` 和 `engine` 不依赖 Tokio、`workers-rs`、WebSocket 或数据库；原生依赖图中不得传递引入 Cloudflare、Wasm 或 JavaScript 构建依赖。这样 Cloudflare 功能的构建、升级和失败不会改变原生二进制程序。

Wasm ABI 必须版本化、大小有界且穷尽表达输入和结果，至少覆盖严格控制帧验证、确定性转换、休眠恢复对账和平台执行结果回灌。它不得暴露“是否允许”之类需要 TypeScript 再解释的松散布尔值，也不得接受普通数据帧。TypeScript 只能消费引擎返回的类型化 `next_state`、`durable_delta`、完整许可快照或许可增量、提交后动作和 trace decisions；未知版本、未知枚举或不完整结果必须失败关闭。ABI 编码和生成绑定由 Rust/TypeScript 向量验证，不能以手写 JSON 结构作为隐式协议。

引擎应暴露形如以下形式的确定性转换：

```text
prepare(state, verified_event) -> PreparedTransition

PreparedTransition
  next_state
  durable_delta
  forward_permit_delta
  after_commit_actions
  trace_decisions
```

经过严格解析和密码学验证的事件描述注册、连接、断开、许可变化、截止时间、停止、过载和适配器故障；普通数据帧不是引擎事件。`durable_delta` 包含逻辑截止时间以及仍需完成的幂等跨对象工作，`forward_permit_delta` 绑定来源与目标连接代次并以单调许可代次防止旧结果复活。适配器先原子提交持久变化，在同一事件轮次内替换许可缓存，再执行控制消息发送、关闭、平台计时器同步和部署级配额通知等 `after_commit_actions`。撤销必须先失败关闭相应热路径；授予只有在持久变化已经交给平台事务且许可快照完整时才能可见。任何影响持久外部事实的动作都必须能从已提交状态重新推导，或作为有界待办持久化，不能只存在于内存效果列表中。

执行失败重新作为事件输入；提交结果不确定时必须重新加载持久状态并对账，不能猜测提交成功与否。原生适配器使用 SQLite 事务落实这一边界；Cloudflare TypeScript 平台壳使用 Durable Object 存储事务和运行时 output gate 落实相同的先后关系，Alarm 始终从已提交的最早逻辑截止时间派生。时间、随机数和密码学输入由共享的狭窄端口提供，测试使用确定性实现。平台适配器不得自行解释授权结果或重排提交阶段。

这一边界是实现统一的核心：共享的是可验证的控制语义，不是最低共同能力的数据面。

## 安全与准入

权限模型必须使用语义不同的类型，不能把一个 bearer token 同时称为注册、恢复和停止凭据：

- `DeploymentAdmissionCredential`：允许在一个部署上预留新分享资源，轮换后只影响新建路由。
- `SenderAuthority`：分享级发送端身份，用于首次建立所有权和替换当前发送端连接。
- `ResumeCapability`：绑定分享与连接代次的短期恢复能力。
- `StopAuthority`：永久停止该分享的不可混用授权。

新建路由同时需要部署的准入决策和分享级所有权证明。私人部署的准入决策必须验证 `DeploymentAdmissionCredential`；公共项目中转可以采用受限的匿名准入策略，但不能省略分享级证明。恢复、替换和永久停止只依赖相应的分享级授权，不能因部署凭据轮换而失效；部署凭据本身也永远不足以接管已有分享。具体密钥可以从同一分享根秘密做域分离派生，但协议、存储和日志必须保持这些权限类型独立。

每个私人 Cloudflare 部署都应使用高熵部署准入凭据。WindShare 只在发送端本地配置中保存它；Worker 通过平台密钥管理保存验证材料。接收者只需要分享链接携带的公共端点，链接不包含任何部署或分享私钥。

浏览器 Origin 策略应允许官方网页接收端和明确配置的自托管来源。CLI 客户端通常没有 `Origin`；应把这种情况作为独立且有意设计的策略处理，而不是直接关闭浏览器检查。

所有限制都应是有名称的配置值。部署活动路由数和新建速率由边缘 Worker 与 `DeploymentControl`，或原生进程级准入控制器执行；每分享接收者数、并发会话数、帧大小和许可由 `ShareRelay` 或原生 Actor 执行；排队字节数由各自数据面执行。平台限流能力可以补充这些控制，但不能替代协议级所有权检查。

## 部署体验

首版首选流程是提供 **Deploy to Cloudflare** 按钮，但不能假定 Cloudflare 部署页能把生成的秘密安全回传给本地 WindShare：

1. WindShare 在本地生成高熵 `DeploymentAdmissionCredential` 并暂存，不生成 Cloudflare API 令牌。
2. 用户打开部署页，在 Cloudflare 控制的界面中把该值录入为 Worker secret；若 Deploy Button 不支持 secret 输入，则部署页必须明确引导一次 Dashboard 设置。
3. Cloudflare 创建 Worker、两个 Durable Object 绑定、迁移和 `workers.dev` 地址。
4. 用户把公开基础端点复制或导回 WindShare；WindShare 将它与本地暂存的凭据组成 `RelayProfile`，并完成一次带证明的连通性检查。
5. 以后创建分享沿用已经选择的 `RelayPolicy`，接收者不参与部署或配置。

部署流程不显示、导出或回传 Cloudflare API 令牌。将来若要省略复制端点这一步，必须先设计有明确来源绑定、一次性状态和超时的 claim 回调，不能用未认证的浏览器回跳猜测部署结果。

fork 加 GitHub Actions 是面向高级用户的后备方案。它只应使用权限范围尽可能小的 Cloudflare API 令牌和账户标识，并且只能存储在仓库密钥中。文档不得引导用户使用全局 API 密钥。

Deploy Button 对单体仓库子目录和构建上下文存在约束，因此发布物应包含独立的最小部署模板。模板固定 TypeScript 平台壳、`engine-wasm` 产物、ABI/协议向量、迁移和 lockfile 的版本，并由同一发布流水线从规范源码生成和验证；不得复制一套可以独立漂移的引擎源码或手工改写 Wasm ABI。fork 加 GitHub Actions 只作为需要自定义域名、版本固定或受控升级的高级路径。

初始产品只部署中转。在中转生命周期与升级路由稳定后，再评估是否由同一个 Worker 同时提供网页接收端和中转。

## 中转配置与故障切换

WindShare 应显式建模中转配置，而不是增加彼此松散的端点和令牌参数：

```text
RelayProfile
  id
  publicEndpoint
  deploymentAdmissionCredential?  // 仅发送端本地保存；公共项目中转可以没有
  trustLabel

RelayPolicy
  orderedProfileIDs
  onCandidateUnavailable          // try_next 或 fail_share
```

凭据只属于发送端，绝不能进入能力 URL、日志或接收端状态。`RelayPolicy` 是发送端配置；能力链接继续只携带有序的公共端点。当前链接已经支持重复的 `r` 参数，协议工作重点是候选生命周期，而不是再增加一套链接字段。

创建分享时，发送端必须在有界准备窗口内并行向策略允许的候选建立分享级路由，并只把已完成所有权证明且可恢复的候选写入链接。发送端监督器维护每个候选独立的预留、发布、连接代次、恢复能力和停止结果，不能用一个“已注册”布尔值代表整组中转。若策略为 `fail_share`，首选候选失败就明确终止创建；若为 `try_next`，链接包含按策略排序的所有就绪候选。未在窗口内就绪的可选候选不得无限拖延分享创建，其迟到或不确定的路由必须被继续跟踪并清理。

接收端按链接顺序自动尝试，不弹出中转技术选择。项目中转只有在发送端策略中存在、发送端也已成功注册时才会进入链接。永久停止必须向所有曾成功创建过路由的候选扇出，包括未写入链接的迟到候选，并向用户区分全部完成、部分失败和结果不确定；不能因为一个候选返回成功就宣称分享已完全停止。

首版不做跨中转带宽聚合。每个会话在任一时刻只采用一个 Relay Lane；确定性的故障切换更容易保持顺序、控制成本并诊断信任边界。

## 实施顺序

### 0. 固化用户流程与原生基线

重写前先把当前默认用户流程记录为产品行为轨迹：未配置个人中转、个人中转优先、仅个人中转、P2P 成功、Relay Lane 后备、候选不可用和永久停止。记录的是用户应感知的语义，不把当前实现缺陷固化为规范。

在同一机器和网络拓扑上测量当前 Go 中转的单连接与多分享吞吐、控制消息延迟、端到端 p95 延迟、常驻内存、连接建立速率、公平性以及慢接收者下的有界内存行为。测试数据集应覆盖现有最大帧、持续大文件、许多空闲连接和接收端停读。原生 Rust 的切换预算在实现前根据该基线确定，Cloudflare 的结果单独记录，不能用来放宽原生预算。

### 1. Cloudflare 宿主与 Rust/Wasm 可行性原型

构建并实际部署一个最小但纵向完整的 TypeScript 平台壳加 Rust/Wasm 语义切片：一个发送端和至少一个接收端进入同一分享对象，完成二进制可休眠 WebSocket、附件恢复、存活套接字枚举、Durable Object SQLite、运行时 output gate、单 Alarm 调度、密码学证明验证、许可签发和当前最大帧转发。强制休眠或驱逐后继续验证断开、恢复、许可缓存重建、永久停止和状态对账。

在同一 compatibility date、部署区域、协议帧、许可检查和负载下比较三条路径：

1. 高层 `workers-rs` 休眠 handler 的 `Vec<u8>` 接收与 `send_with_bytes` 转发。
2. TypeScript 只用无复制视图读取固定头并把原始 `ArrayBuffer` 交给 `WebSocket.send()`；这是默认基线。
3. 可选的低层 `worker-sys`/原始 `JsValue` 路径，保留宿主缓冲区且不经过高层二进制转换。

对照必须先使用不批处理的完全相同帧序列，并包含当前最大帧、持续大文件、许多空闲连接、停读或极慢接收端以及至少一个不受慢端影响的其他接收者。记录构建产物大小、冷唤醒、应用可见的 JavaScript/Wasm 边界字节数、CPU、内存增长、持续吞吐、请求速率、端到端 p95 延迟、平台发送失败和关闭分类。随后才分别测量可选的有界批处理。批处理不是流量控制；只有现有请求窗口不足以约束在途数据且测量显示明确收益时，才进入协议设计。

原型同时维护一份固定 compatibility date 的必需平台 API 清单，覆盖 Worker/DO 类导出、升级、休眠 handler、attachment、套接字枚举、SQLite、Alarm、事务与平台故障行为。选定的 Cloudflare 发布路径必须证明普通不透明帧没有进入 Wasm linear memory；测试计数器应对这些帧保持 `wasm_payload_bytes == 0`。高层或低层 Rust 宿主只有同时满足这一热路径约束和必需 API 清单时，才可以替代默认 TypeScript 平台壳。这个比较决定平台宿主实现和容量参数，不允许产生第二套控制语义。

### 2. 规范中转语义

把预期行为提取为平台无关的状态转换向量。覆盖部署准入、分享级挑战/证明、描述符发布、加入、初始 Relay Lane、P2P 信令、许可签发与撤销、重连代次、意外断开宽限、替换竞争、会话退役、过载、截止时间、停止和永久停止标记。规范同时定义 `decide -> durable transition -> after-commit action` 顺序，以及提交或动作结果不确定时的重载对账。

定义升级前的路由约定、稳定 `RelayIdentity` 和分享标识编码，并更新协议转录，确保端点身份、路由角色与经过身份验证的意图不可能分离。同步定义多中转的发布、恢复、故障切换和停止聚合语义。项目尚处于 1.0 之前，应采用一次语义完整的协议切换，而不是维护兼容分支。

### 3. Rust 协议与引擎

把严格解析、密码学转录、权限类型、`ForwardPermit` 和确定性控制状态机实现为独立 crate。在没有套接字、数据库和平台运行时的情况下测试状态转换；时间和随机输入由测试显式提供。复用 Go 与 TypeScript 的规范字节向量和行为向量，使语义漂移能够被及时发现。引擎 crate 不得引入 WebSocket 队列、载荷缓冲或平台数据库抽象。

为 Cloudflare 增加独立的 `engine-wasm` 窄包装，只导出版本化控制事件、恢复观察和平台结果接口。它与原生 Rust API 必须调用同一状态转换函数，不能复制状态机。Wasm 包装的构建应生成或验证 TypeScript 类型、ABI 版本和规范向量；普通 `OpaqueRoute` 数据帧不属于其输入类型。

### 4. 原生 Rust 中转

先实现原生适配器，在常规运行时中验证引擎，并在迁移期间始终保留当前 Go 中转。使用现有 Go CLI 和浏览器接收端验证注册、传输、重连、慢接收者、并发分享和进程重启；用存储端口计数确认不透明帧热路径没有数据库操作。按第 0 阶段的相同工作负载与 Go 对照，发现实质性退化时继续拆分数据面或保留 Go，不能先切换再补性能。

### 5. Cloudflare 中转

把经过验证的 `engine-wasm` 连接到 TypeScript Worker、`DeploymentControl` 和 `ShareRelay` 平台壳。增加休眠恢复、由引擎驱动的状态与套接字对账、Alarm 截止时间、迁移、部署级准入租约、平台错误结果回灌、结构化诊断，以及针对一次性部署环境的远程互操作测试。`ForwardPermit` 缓存只执行引擎结果并在每次唤醒后重建；不透明数据热路径继续绕过 Wasm 和 SQLite。Cloudflare 的容量参数只属于该适配器。

### 6. 产品集成

增加 `RelayProfile`、`RelayPolicy`、安全的本地凭据存储、发送端多候选监督器、只发布就绪候选、接收端有序故障切换、停止结果聚合、可操作的配额错误和导入体验。随后发布版本锁定的 Deploy Button 模板和面向高级用户的 fork 工作流。诊断界面可以展示实际采用的候选与后备原因，普通传输流程不增加选择步骤。

### 7. 单次切换与删除 Go 服务端

Cloudflare 上线与原生替换是两个独立发布决策。Cloudflare 适配器可在 Go 仍承担项目中转时先作为可选功能发布；Cloudflare 的成功、配额或限制不能替代原生验证。

只有原生 Rust 在相同客户端、行为轨迹和基准工作负载下满足既定功能与性能预算，才把项目中转和普通自托管路径切换到 Rust。切换决定成立后，在同一变更中删除 Go 服务端实现，避免长期维护重复运行时；若原生路径未满足预算，则不切换也不删除。

预计退役的服务端包包括：

- `relay/cmd/wsrelay`
- `relay/signaling/v2endpoint`
- `relay/signaling/v2route`
- `relay/httpapi`
- `relay/connectionlimit`

客户端使用的 Go 线协议编解码器应保留；如果服务端命名空间不再准确表达其边界，应将其移出该命名空间。`transport/relayv2` 继续作为客户端传输适配器。

## 验证方法

验证应分层设计，使普通本地检查保持快速：

- 针对状态转换、竞争、截止时间和不变量的纯引擎模型测试。
- Go/Rust/TypeScript 规范字节向量、固定头拒绝向量、Wasm ABI 向量和行为轨迹。
- 部署级预留的幂等、过期、确认、释放和故障对账测试。
- 由原生与 Cloudflare 工具共享的数据面语义测试：帧顺序、会话隔离、许可撤销、断开、过载分类和慢接收者隔离；平台容量数值与队列实现不要求相同。
- Cloudflare 热路径检查：未协商批处理的普通 `OpaqueRoute` 不调用 Wasm、SQLite、JSON 序列化或载荷日志，不创建整载荷副本，并在错误 magic、版本、保留位、会话、方向、连接代次和长度下失败关闭；任何有界批处理也不得把载荷送入 Wasm。
- 许可缓存检查：授予、替换和撤销顺序，提交失败后的重载，以及休眠后依据已提交状态与存活套接字由引擎重建完整快照。
- 原生进程与 Go CLI、浏览器之间的互操作测试。
- 原生 Rust 与当前 Go 在相同硬件、客户端和负载下的吞吐、p95 延迟、内存、公平性和连接扩展性对照。
- 原生 Cargo 依赖图、feature 集合和发布产物检查，防止传递引入 Cloudflare、Wasm 或 JavaScript 工具链；Cloudflare TypeScript 模块依赖检查防止数据热路径导入引擎、存储或载荷日志模块。
- 通过可观测存储端口或计数器证明正常不透明帧转发不触发持久化，并证明控制状态先提交、网络动作后执行。
- 在一次性 Cloudflare 部署上验证休眠、驱逐、Alarm、重连和停止状态持久化的冒烟测试。
- 针对单对象请求速率、扇出、停读接收者、队列压力和大型二进制帧的专项负载测试，并保留高层 `workers-rs`、TypeScript `ArrayBuffer` 与可选低层 `JsValue` 路径的可复现实测结果。
- 多候选部分注册、运行时故障切换、恢复和部分停止的产品级测试。

远程 Cloudflare 场景和持续负载场景应放入定时或显式触发的工作流，不能显著拖慢普通本地测试。新增 Rust 工作区的 CI 覆盖率策略应随 crate 一同定义，不能直接套用 Go 阈值。

## 可观测性

两个适配器应使用相同的结构化决策词汇。适合记录的字段包括部署 ID、构建版本、平台、操作 ID、非秘密诊断形式的分享标识、连接 ID、会话 ID、代次、许可代次、事件、决策、结果和拒绝原因。客户端监督器还应记录 RelayPolicy、候选配置 ID、候选顺序、当前 Lane、后备原因和每候选停止结果。

日志绝不能包含能力片段、注册授权凭据、证明密钥、密封描述符字节或不透明传输载荷。系统应暴露足以诊断部署的构建和协议能力元数据，但不能泄露私人配置。

正常用户流程只显示最终分享或明确错误；诊断详情按需展示“正在使用哪个中转、为何发生后备、哪些候选停止失败”，不能用底层 Worker、Durable Object 或 Actor 术语要求用户作决定。

## 免费套餐假设

本设计依赖 Cloudflare 免费 Workers 套餐提供 Durable Objects、SQLite 支持、WebSocket 休眠以及适合个人轻量使用的计费方式。这些限制和价格属于外部政策，不是协议保证，必须在实施前和发布前重新确认。

休眠十分关键，因为中转连接可能长时间空闲。当前帧大小明显低于 Cloudflare 文档中的 WebSocket 消息上限，但单个 Durable Object 的请求速率上限可能成为高吞吐传输的实际瓶颈。可行性原型应确定线协议是否需要经过协商且有明确上限的批处理信封；增加无界队列不能替代流量控制。

Cloudflare 的消息大小、对象吞吐、CPU、休眠和配额只能出现在 Cloudflare 适配器配置与部署诊断中。共享引擎只表达协议安全上限和过载结果，原生默认值不得引用免费套餐数值。Cloudflare 调整政策时，普通服务器部署不需要修改配置或重新发布。

产品应把免费部署描述为适合个人及轻量使用，不应承诺无限传输量、公共服务容量或 SLA。

## 风险与应对

| 风险 | 架构应对 |
| --- | --- |
| 共享引擎把原生数据面降到最低共同能力 | 共享控制决策和许可，不共享套接字、队列、持久化实现或平台容量值。 |
| 原生 Rust 相对当前 Go 性能退化 | 先建立 Go 基线；在相同负载下对照，未满足预算就继续拆分或保留 Go。 |
| 扁平效果列表造成“网络已发送但状态未提交” | 使用准备、原子持久转换和提交后动作三阶段；不确定结果必须重载对账。 |
| 无状态 Worker 和每分享对象无法执行部署总量限制 | 使用不在数据路径上的 `DeploymentControl` 管理幂等预留和部署级计数。 |
| TypeScript 平台壳逐渐复制控制语义 | 只允许其执行版本化引擎结果；用窄 ABI、穷尽类型、依赖边界和跨语言行为向量阻止平台代码自行裁决。 |
| `workers-rs` 或生成的绑定落后于所需 API | TypeScript 默认直接使用固定 compatibility date 的平台 API；Rust 宿主候选必须持续通过必需 API 清单。 |
| Wasm 二进制处理产生整载荷复制 | 普通不透明帧由宿主持有并绕过 Wasm；对三条宿主路径做远程实测，以 `wasm_payload_bytes == 0` 和容量数据验证。 |
| 许可缓存跨休眠变旧或旧代次复活 | attachment 不保存授权；每次唤醒由引擎根据已提交状态和存活套接字重建带单调代次的完整许可快照。 |
| 休眠清除内存中的连接状态 | 用最小附件索引套接字，从有界持久状态恢复并强制对账；单 Alarm 驱动所有截止时间。 |
| 原生异步背压与 Cloudflare 发送语义不同 | 数据面各自实现有界背压和慢接收者隔离，只把统一的过载结果返回引擎。 |
| 私人中转故障时静默切到项目中转 | RelayPolicy 明确列出候选和故障行为；链接只发布发送端已建立的候选。 |
| 多中转出现部分发布或部分停止 | 保存每候选生命周期，停止向所有曾创建路由的候选扇出并呈现部分或不确定结果。 |
| 部署页无法安全回传秘密或定位单体仓库子目录 | 凭据由 WindShare 本地生成，端点显式导回；发布独立、版本锁定且不复制引擎的模板。 |
| fork 部署过期或与协议不兼容 | 发布协议/构建元数据、自动化升级，并返回可操作的不兼容原因。 |
| 外部价格或限制发生变化 | 保持中转配置可迁移并支持有序后备，避免把链接绑定到单一提供商。 |
| 迁移造成长期语义重复 | 使用共享行为轨迹，先交付原生适配器，再在切换后及时删除 Go 服务端。 |

## 待评估问题

- 在已部署原型中确认 TypeScript 平台壳、Rust/Wasm 窄 ABI 和可选低层 Rust 宿主分别满足所需的休眠、SQLite、Alarm 与故障顺序。
- 确定 Wasm ABI 的版本化二进制编码、大小预算、生成 TypeScript 类型的方式和不兼容升级流程。
- 确认 Durable Object 存储事务、输出门和 WebSocket 发送在故障时的准确可观察顺序。
- 确定升级前端点的最终形式和规范分享标识编码。
- 判断是否需要批处理；如需要，应在线协议中显式建模。
- 确认 Deploy Button 是否能安全录入 Worker secret，并定义不能录入时最短的 Dashboard 步骤。
- 定义部署凭据验证材料、轮换、丢失恢复和旧准入租约失效方式。
- 确定独立部署模板消费版本化 TypeScript 平台壳、`engine-wasm` 产物、迁移和 ABI/协议向量的具体发布机制。
- 决定原生生命周期存储的默认实现；若提供临时诊断模式，必须明确其重启与永久停止语义，且不能成为项目中转默认值。
- 根据第 0 阶段基线确定原生切换的具体性能预算和基准环境。
- 定义 Rust lint、依赖审计、覆盖率、Wasm 体积和互操作 CI 策略。
- 确定独立 fork 部署所支持的升级与回滚路径。
- 仅在纯中转部署稳定后，重新评估网页与中转的组合部署。

## 明确不在范围内

- 实现或部署标准 TURN 服务；现有公共 STUN 默认配置不属于本计划。
- 服务端文件缓存、离线传输或明文检查。
- 多中转带宽聚合。
- 公共中转市场或用户账户系统。
- 使用 Rust/Wasm 重写浏览器协议栈。
- 在 TypeScript 中独立实现认证、所有权、许可或生命周期状态机。
- 为复用 Rust 代码而让已获许可的不透明载荷进入 Wasm linear memory。
- 让 Cloudflare 成为创建或接收分享的强制依赖。
- 为复用代码而让原生数据面采用 Cloudflare 的队列、配额或执行模型。
- 在私人中转不可用时静默加入或切换到项目中转。
- 仅为向后兼容而保留当前内部中转端点约定。
