# WindShare 威胁模型

> 状态：**suite `0x02` 当前生产安全边界**。目标是抵抗恶意 relay、网络与恶意持链者伪造；
> 可用性拒绝、读取能力转发和本地主机进程的主动篡改是非目标。发送端 revision drift、输出对象替换或 rename 仍按产品正确性处理；已公开 final 在同 native identity 且 continuity token 未变化时的原地修改是已接受残余，不要求额外检测。
> 安全语义须与[协议规范](协议规范.md)、
> [跨运行时向量](../core/testvectors/README.md)和[Validation](validation.md)同步。

## 1. 能力链接流转

能力链接预期经群聊等半公开渠道流转；fragment 是消息文本的一部分，因此聊天平台、预览机器人或截图
取得完整链接后，在密码学上就是持链者。用户可把 `#` 后密钥与不含密钥的 URL 分渠道发送；接收页只在
本地拼接，fragment 必须在网络、日志和持久化工作开始前擦除。持链者被授权读取和再分发全部分享内容，
但不得因此获得 sender 私钥、relay route 所有权或其他 receiver 的 session key。浏览不启动 ICE；preview
或 download 的显式用户手势才可启动 P2P，从而避免自动预览机器人触发地址暴露与带宽消耗。

## 2. 信任边界与可见信息

| 角色 | 信任/能力 | 允许观察或改变 |
|---|---|---|
| relay | 不可信；可延迟、丢弃、重排外层流量 | `shareId/pkHash/ShareInstance`、descriptor digest/resume-token hash 注册头、sender 公钥、RelaySessionID、WS2O 密文长度/时序/总量、IP；不得见内层 kind/direction/terminal/lane/FileID/名称/精确大小/local block/OperationID/ProtocolSessionID |
| 持链者 | 被授权读取；可能恶意且可与 relay 合谋 | 持 `readSecret + pkHash`，能解密 sender objects、创建自己的 session；不得伪造 sender object/control/terminal、注册/恢复/停止 sender route、派生另一 receiver 的 traffic key |
| sender | 内容权威；不受 receiver 信任用于输出路径 | 持 Ed25519 私钥、readSecret、源根；可签名真实对象，不能授权 receiver 越过选择根或覆盖输出根外 |
| receiver 前端 | 使用者选择并信任；持 readSecret | 可读全部授权内容；UI/媒体解析仍按 hostile input 处理 |
| offline delivery | 当前在线模式不存在；未来不可信 | 只存/投递 sender-signed transport-neutral objects/inventory；无 readSecret/private key，不能保存 session envelope |
| 本地源变化/输出既有对象 | 可变的正确性输入；本地进程不是攻击者 | 发送端 revision drift 不能静默换代；输出对象仍须防 symlink/reparse、根外访问和 foreign overwrite；同 continuity token 的原地修改可漏检并接受 |

`pkHash/ShareInstance` 对 relay 可见是注册所有权和多节点路由所需的最小公开元数据；文件身份、请求类型
和精确大小始终在 OperationEnvelope/transport-neutral object 的密文内。operation 类型可能由长度/时序
被概率推断；本阶段不做 padding、固定速率或 ORAM。

## 3. 保护目标与机制

### 3.1 Sender authenticity 与能力持有者隔离

- link `pkHash` 锚定 Ed25519 public key；descriptor 解密后必须先验证 key hash/shareId mapping，再验签。
- shareId 只截断映射 pkHash，故 ShareInstance 刷新不换链接；诚实 relay 保存完整 pkHash，截断碰撞必须
  fail closed，不能覆盖现有 route。
- descriptor/page/directory error/revision/block/offline commit 分属不同签名 domain；签名覆盖 context hash 与
  完整 sealed bytes。持链者能用 readSecret 造 AEAD，但不能产生 sender signature。
- 所有 sender session control 另签 `ShareInstance + ProtocolSessionID + LaneID/Epoch + direction + sequence +
  OperationID + payload hash`；真实对象签名不能剪贴成 terminal/error。
- relay REGISTER/RESUME/STOP 分别使用 purpose 0/1/2 的新鲜一次性 challenge；proof 绑定 RelayIdentity、
  ShareInstance、descriptor digest（注册/恢复）或 StopID（停止）、ChallengeID/nonce/排他 expiry 与 sender
  private key。RelayIdentity 来自运维配置的、无 query 的 canonical
  `ws(s)://authority/base/v2/ws`，拨号 query 只用于 admission，不能让代理 header 或每用户 credential 改写
  relay 密码身份。resume token 只是节点本地附加条件，不能成为替代 authority；已认证连接本身也不能替代
  STOP challenge proof。
- 恶意 relay 仍能拒绝服务或占用自己的路由；这是明确接受的可用性风险。诚实 relay 上持链者不能抢占。

### 3.2 Session confidentiality、PFS 与 replay

- ClientHello 用 readSecret 派生 HMAC proof，在资源 admission 前证明能力；sender-signed X25519 transcript
  防 relay/其他持链者中间人。
- traffic key 同时依赖 X25519 shared secret、readSecret-derived sessionAuthKey 与完整 transcript。
  仅观察 hello 的另一持链者没有 ephemeral private key，不能派生该 receiver 的 traffic key。
- 每方向/LaneEpoch sequence 从 0 严格递增，AAD 绑定 E2E session/lane/方向；RelaySessionID 不进 AAD。
  跨 receiver、跨 lane epoch、跨 session 或方向翻转的 ciphertext 全部失败。
- LaneEpoch 由 session 全局唯一计数器分配，接收时按 LaneID 要求严格增大并允许 gap；跨 lane 乱序不能
  被错误当 replay，一次性 signed grant/LaneHello 仍阻止旧 channel 复活。
- envelope 无法认证时只产生本地无 ID terminal，避免 attacker 让实现签名/反射伪 OperationID。
- offer、answer 与 candidate 只作为 OperationEnvelope 内的 E2E 消息传输；relay 只见 WS2O 密文。
  首个 offer 的非零 `PeerPathID + AttemptID` 绑定本次协商；替换任一身份或在同一 ProtocolSession
  以 fresh OperationID 注入旧 attempt 都必须失败。两者只属于 connectivity 协商；core/content 只在
  channel 建立后接收 `LaneID/LaneEpoch`。
- `OperationID` is correlation only. Receiver lifecycle authority comes from an opaque local binding/generation issued
  before offer creation. Delayed terminal or cleanup work must prove that exact binding; the first transition provenance
  stays stable, consequences only strengthen, and publication waits for in-flight receive plus exact cleanup.
- active peer binding 受 attempt 数量上限约束；结束后进入 30 秒且条目有界的 binding tombstone，
  同 pair 换 OperationID 重放仍拒绝。若 tombstone 容量不足以记录已拒绝 offer，则整段 retention window
  fail closed，不通过驱逐旧 binding 恢复 admission。
  A valid peer-scoped operation error remains attempt-local and cannot impersonate directory/revision/block failure.
  Sender signature proves identity, not cross-scope semantic authority: message kind, failure scope, exact operation,
  envelope lane/sequence, and `PeerPathID/AttemptID` binding are checked independently. Malformed/cross-scope signed
  failures and authenticated answer/final/binding/continuation conflicts seal a session-unsafe consequence.
- Residual error inspection is bounded and diagnostic-only. Only audited exact node types are traversed; unknown,
  hostile, typed-nil, or truncated shapes stay opaque, and an owner-compatible benign leaf cannot erase a genuine
  sibling. Immutable terminal outcomes own immutable diagnostic snapshots; termination traces export only correlation,
  provenance, and classes—not raw error text or shared content—so telemetry cannot become lifecycle authority or a
  disclosure channel.
- 新 lane 的 HMAC 合法后才可返回 sender-signed WS2B/WS2N；畸形或 HMAC 无效 candidate 必须 silent-close。
  accept/reject 都绑定完整 LaneHello digest，一次性 grant 及 30 秒 consumed/expired tombstone 阻止 replay。
- preview/download activation 立即保留 relay 并在后台启动 direct recovery；pure browsing 不启动 ICE。direct path 的
  timeout、retry、quiescence、detach 和预算耗尽都没有关闭 relay 或升级 ProtocolSession terminal 的 authority。
- 每个 ProtocolSession 只有一个 in-flight direct attempt；wave/session attempt 与 active-time budget 在资源创建前
  预扣。PeerPathID 只作稳定关联，每次 attempt、offer operation、grant operation、grant 与重连 epoch 都是 fresh，
  因而 UI rearm 不能重放旧 proof/grant，也不能用新 operation 洗掉永久 exact-operation outcome。
- recovery 只消费 closed typed result。local transient、authenticated `grant-expired`/`admission-limited` 才可重试；
  其余 authenticated rejection、peer operation terminal、local policy/contract 或 unknown input 只能 stop-path。
  `stop-session` 只反映 ProtocolSession 已封存的 terminal，diagnostic/error text 无权扩大作用域。
- connectivity trace 只投影 closed milestone 和有界 correlation。SDP、candidate string/address/port、nonce、proof、
  raw grant/hello/response、capability、content metadata 与 raw error text 均禁止；observer failure/backpressure 不参与
  phase、settlement、retry 或 lane routing。
- 临时 X25519 key 擦除后 session control 获得前向保密；readSecret 加密的长期 sender object 不宣称 PFS。

### 3.3 Catalog、源对象与资源耗尽

- synthetic-root/selected-root NodeRecord/预算在 REGISTER 前原子提交；ready 前零后代枚举是安全与体验共同门。
- receiver 只持 opaque kind-safe NodeID；root slot + root-relative locator + object identity 留在 sender store。
- 每次目录 scan 在枚举前后复核对象身份；replacement/rename/type/reparse/collision 不发布 generation。
  page chain、连续 index、唯一 terminal、ShareInstance/signature 防 gap、splice、旧 instance 与 post-terminal append。
- page/NodeRecord/terminal 一次事务提交；spill 只含 catalog metadata。崩溃/磁盘满/取消不留下可见半 generation。
- 生产 sender 的每个 LiveOnly share 独占带跨进程 owner lock 的 file catalog 根；64 MiB 是可逐出的驻留层而非
  已提交 catalog 总量。registry lock 串行化启动清理与正常关闭；只删除无活动 owner 的遗留根或本 share 根，
  均不能触及源内容。
- protocol-session/share/process 的 scan、entry、memory、spill、lease、handle、lane/cache/reassembly预算在取得
  资源前 charge，重连不重置 share/process，活动 revision 不因新 admission 被逐出。
- 未认证长度通过前不分配 fragment buffer；单 operation、session、share、process 均有 byte/record 上限。
  相同 fragment 幂等，冲突拒绝，取消/完成 tombstone 吸收迟到片。
- relay 的 stopped route 永久占一个配置的 route slot；active 与 stopped 共用 `MaxRoutes`。活动与 60 秒
  ended-ID tombstone 同时计入全局 `MaxSessions` 与对应 `MaxSessionsPerShare`，使单 share churn 不能耗尽全局预算，
  delayed WS2O 也不能命中新复用的 RelaySessionID。意外断线只保留 60 秒 crash grace；显式 STOP 以不持有全局
  route lock 的 per-route transaction 先 durable tombstone、再按 Registry exact participant batch drop session，
  永不进入 grace，且 committed cleanup 不依赖 WS2Y 写成功。definite-not-committed 才可恢复；ambiguous I/O 或
  rollback failure 使 route fail-closed，只有相同 StopID 重新验证并 sync 后可解除。该 60 秒窗口内只有
  exact former sender/receiver 的 late WS2O 可 session-local 丢弃；expired、never-issued 或 non-owner ID 必须
  connection-fatal。
- relay 以固定 16B `WS2F SESSION_RETIRED` 精确回收 client channel；命中只关闭该 ID，本地不存在/重复 ID
  allocation-free 忽略，畸形控制 connection-fatal。无法排队或写出通知时 fail-close peer link；60 秒 tombstone
  仍吸收通知与在途 WS2O 的竞态，不能因通知成功提前回收。

### 3.4 FileRevision 与禁止 sender 内容副本

- catalog private candidate + ExpectedSize 必须在打开时匹配；descriptor 只能在稳定 source/handle/quota 建立后返回。
- 稳定性来自排除写入的句柄，或同一已打开 POSIX 对象的
  `device+inode+size+mtime(ns)+ctime(ns)` MutationToken 前后复核；缺少 object identity 的
  size/mtime/ctime 组合不够。
- sender content temp、完整复制、snapshot/staging 是结构性禁止项；无法稳定读取就返回
  `unsupported_stability`。Catalog spill 与 receiver output staging 不属于 sender 内容副本。
- drift 永久终止该 revision、全部 lease 与 cache；receiver 丢弃该 revision 的 VerifiedDurableRanges/未提交 file
  transaction。其他 file/directory/receiver 不受无条件连带终止。
- file-local key/AAD/signature 绑定 FileID/revision/local index/derived length；BlockCount 不上 wire，块不跨文件。

### 3.5 Receiver output、恢复与本地权限

- `ReceiveIntentV1` 是 receiver-local authority：它绑定 frozen SelectionSpec、显式 ArtifactSpec 和一个合法
  materialization binding，不增加 sender/relay/transport wire field。OperationEnvelope 的 OperationID 只做线请求
  关联，不能重放或替代 persisted receive OperationID、ReceiveIntentDigest 或 lifecycle generation。
- 每次 selection mutation 创建新的 projection epoch。catalog、capability、picker 与 reconnect 的异步结果必须携带
  epoch；stale epoch 被无副作用丢弃。background discovery 不能自动弹 picker，authority acquisition 完成后还要
  复核当前 epoch、artifact offer 与 environment facts，避免 stale action 写入另一 intent。
- Artifact 与 destination/workspace 分离。Direct plan 的 DestinationReservation 绑定 exact certified authority、
  operation identity、规范名称和 no-replace 决策；workspace 只绑定 owned repository，不冒充最终 destination。
  同一 reservation 只能 reopen 同一 owned entry；路径相同、名称相同或 UI state 都不能授权 destination replay。
- `directory-tree` 只在 `native-tree`/`fsa-tree` authority 下 prefix-visible。FSA 的 Web Lock + identity recheck
  不能把 `fsa-tree` 升级为 `managed-atomic`；外部竞争或 ownership 不明转 `needs-attention`
  （reason=`target-ownership-unknown`）。`original-file`/`zip-archive` 只使用 `managed-atomic` target 或
  `browser-handoff`，不能借 precreated/truncating save handle、overwrite 或 path adoption 降级。
- 所有 path segment 在 catalog 与 output 两端按同一 canonical policy 复核；mkdir/open/write/mtime/publish 均从
  retained root/handle 派生。ZIP entry path 来自同一 artifact layout，禁止 absolute、`..`、separator alias、
  重复/conflicting entry 和 ZIP traversal；必要祖先与结果根由 planner 建立，不能接受 writer 自报路径。
- workspace ZIP 与所有 portable artifact 必须先 seal `PreparationManifestV1`。manifest entry/count/metadata、
  generation、artifact path 与 exact catalog size 全部验证并用 checked arithmetic 计算；entry/metadata/artifact/
  workspace limit、generation mismatch 或 overflow 的 rejection 必须证明 revision/block request count 仍为零。
  Workspace `original-file` 同样在首个 content/allocation 前完成 authenticated single-file WorkspaceBudget admission。
- `WorkspaceBudgetV1` 依 canonical 顺序计算 `uniqueRawBytes`、`packageBytes`、`peakTemporaryBytes` 与
  `durableMetadataBytes`，`peakOwnedBytes` 是 checked sum；同一 OwnedObjectID 同时只计一次。quota estimate 不是
  reservation，实际 allocation 重新 admission。underflow/overflow 和 quota race 是 typed rejection 或进入
  `resumable-receive`/`resumable-package`，不能触发 artifact fallback、unbounded allocation 或 partial ZIP。
- `MaterializedManifestV1` 只引用 final FileCheckpoint digest/generation；它不能复制或扩大 verified ranges。
  `SealedMaterializationV1` 绑定 intent、workspace、generations、manifest digests 与 raw ownership receipt；
  `PackagedArtifactV1` 再绑定 exact bytes、layout digest、package object 与 close receipt。任一 digest/object/revision
  substitution 阻止 seal。packager 只能读取 seal，不能重新 discovery 或更换 member。
- ZIP 只有 `store` encoding 与 `complete-only` completeness。共享的 `ZipEncodingPolicyV1`/
  `SealedZipLayoutPlanV1` 负责 UTF-8 path、ZIP32/64、
  header、descriptor、central directory、offset 和 exact byte arithmetic；actual writer layout/length/CRC 在 close
  复核。任一 selected member、discovery、layout 或 writer failure 都阻止 seal/publication；不跳过失败 member，
  取消也不导出 partial ZIP。
- `FileCheckpointV2` 是唯一 durable have-state。record 绑定 OperationID、ReceiveIntentDigest、plan binding、
  FileID/revision/path/size、certified authority、owned object 和 canonical ranges。UI、progress、aggregate manifest、
  preview cache、successful Write 或 error severity 都不能制造 ranges；recovery 必须复核 checkpoint generation 与
  object identity。
- CLI ordinary native output 先从 retained root handle 与认证的 root-owned control namespace 派生
  `DestinationAuthorityID`；display path 只用于定位和提示，不能授权恢复或 mutation。public result 使用普通继承
  ACL/mode，只要求当前操作具备实际 traverse/create/write/publish 权限；严格权限只保护 WindShare-owned control/proof state。
- Native execution mode 只由四项独立事实决定：四项都成立才是 resumable；只有 `SafePublish + CrashCleanup` 时是
  live-only；更弱时在首个 content request 前失败。live-only 不创建 durable operation/checkpoint，崩溃后只清理
  已证明归属的 partial；已发布文件保留，下次 `get` 使用新名称重下 selection。
- Native registry 只对当前目标根做 bounded active lookup。它不扫描 public tree、不维护全局或 terminal history，
  也不从同名 final 推断完成。`item-blocked` 只隔离无法安全判断的文件/子树；root、registry、lease 或 operation
  ownership 不确定才进入 `operation-needs-attention` 并停止整体。discard 永不删除 final 或 identity 不匹配的对象。
- publication 与 receive identity 分离。每个 managed target 或 browser handoff 使用 fresh PublicationAttemptID；
  target 变化不改 package/intent。persist-before/external-mutation/persist-after 边界防重复 publication；结果无法
  证明 committed/not-committed 或 started/not-started 时进入 `needs-attention`（reason=`publication-unknown`），
  禁止自动 retry/overwrite。
  `browser-handoff` 只能证明 `download-started`，不能证明已保存、最终名称或位置，也不等于 `published`。
- Web operation lease 与 lifecycle generation fence 跨标签页 mutation。active receive/package/publication 不过期；只有
  进入新的 `resumable-receive`、`resumable-package` 或 `waiting-to-save` 时写 24 小时 deadline。heartbeat、
  foreground read、failed probe 与 handoff 不续期；workspace `download-started`/redownload 沿用原 deadline。
  `now >= expiresAt` 先禁止 continuation，再做 ownership-scoped cleanup，避免 resume/expiry race。
- Web stop、discard、expiry 与 post-publication cleanup 只能删除 repository 证明属于该 operation 的 unfinished objects、
  package/checkpoint/metadata。`direct-tree` 成功文件和 `published` target 永不删除；unknown ownership/cleanup
  停在 `needs-attention`。v1 checkpoint/paused/partial-ZIP state 不迁移、不双读；certified legacy cleaner 只能在
  app-owned namespace 内删除 ownership-proven records。
- output trace 先经 safe projector，只允许 stable IDs/digests、closed enums/reasons、counts、checked bytes 与 deadline。
  文件/目录名、plaintext/canonical path、handle、AuthorityRef/OwnedObjectID、capability link、object URL、content 和
  raw error text 即使失败也禁止记录，避免 observability 变成内容与本地权限泄漏通道。
- Journal digest/checksum 防 accidental corruption，不防同 OS account 的 hostile process。Native ProcessRestart 只
  覆盖已声明的 kernel/mounted-volume boundary；browser storage 也可能被提前回收。UI 只在 output-owned executor
  复核 receiver-local intent、lease/lifecycle 和 exact preparation/package evidence 后开放 continuation；缺失或歧义进入
  `needs-attention`。portable handoff 的 64 MiB assembly 与 60 秒 URL lease 不构成 durable recovery。
- Signed media remains hostile input: bounded header probing precedes decode, size/memory/codec use is limited, and
  preview object URLs are released on replacement, failure, cancel, and close. Preview cache is never FileCheckpoint
  evidence.

### 3.6 当前在线生命周期与 M4 offline 边界

- 当前生产只实现 `LiveOnly`；Preparing 失败从未注册，`REGISTERED` 才是链接 ready。
- 显式 Stop/退出必须以独立的 `sender-stopped(0x1008)` 签名 terminal，并完成
  `WS2X -> WS2Q(purpose=2) -> WS2V -> WS2Y` 后永久拒绝新 join、取消活动 revision/scan/lane；
  `illegal-terminal(0x1007)` 只表示协议错误，显式停止不能进入 crash grace。
- 只有非预期网络/进程消失保留 60 秒 route grace，恢复仍须新 relay challenge + sender private-key proof。
- 当前没有 offline uploader、inventory commit 或寄存交付路径。若 M4 实现，未提交 inventory 不对 receiver
  可见，只有原子 `COMMIT_ACK` 后才允许 sender 退出而保持链接；只能存 descriptor/page/revision/block/
  OfflineCommit 等 transport-neutral sender objects 及 digest inventory，保存 OperationEnvelope 或取得
  sender key/readSecret 都违反边界。

## 4. 已知泄漏与残余风险

- relay 仍见 share 路由头、sender 公钥、IP、连接图、密文长度/时序/总量，可推断近似文件/操作模式。
- link 仍是读取能力；被转发、截图或聊天平台扫描后，持有者可读取和再分发。分离密钥仍是单渠道泄漏对策。
- sender 签名的真实对象在同一 ShareInstance 内可被原样重放；在线 session/lease/page chain 会限制其作用。
  M4 必须用 signed `expiresAt`/OfflineCommit 关闭过期后复活，当前在线实现不虚构尚未交付的离线保证。
- X25519/Ed25519、WebCrypto、OS locking、persistent handle 与 filesystem durability 的实现/供应链缺陷仍需平台测试。
- Ordinary native output 接受普通共享 permission profile，但不承诺抵抗同 OS account 的 hostile process。每次关键
  mutation 都复核 retained handle、current access、ancestry 与 native identity；正常并发导致的 replacement、rename 或
  ownership drift 必须 fail closed。没有 matching active record 的 final 不被认领、读取或整文件重哈希，新 operation
  直接预留后缀名称。NTFS/ext4 是首批正向 profile；未知本地、network、FUSE、cloud placeholder、reparse 或 nested-mount
  文件系统不能静默获得能力。Sender source revision drift 仍按 §3.4 的稳定性规则处理。
- malicious sender 可提供恶意但签名的文件名/媒体/内容；path policy、root confinement、artifact layout、
  destination/workspace ownership 与媒体 parser bounds 是 receiver 防线，签名不等于“内容安全”。
- 恶意 relay/网络可以永久 DoS；流量分析、padding、匿名性、receiver 身份认证、撤销已泄露读取能力、
  本地主机进程攻击和供应链攻击仍是非目标。

## 5. 安全验收门

1. 持 readSecret 的攻击测试须无法伪造 descriptor/page/error/revision/block/control/terminal 或注册 route。
2. 修改 ShareInstance、DirectoryID/generation/page、FileID/revision/local index、ProtocolSessionID、lane epoch、
   direction、sequence、OperationID、PeerPathID、AttemptID、fragment total 任一轴都必须在 Go/TS 失败。
3. relay-view 测试只能取得公开注册头与密文长度/时序，不能取得 FileID/ExactSize/local index/OperationID。
4. 后代永久阻塞时 root transaction/descriptor 注册仍完成；注册前 descendant FS/content 操作为零。
5. drift、directory stale、fragment flood、lease/lane/cache admission、多个 receiver 取消均保持错误/资源域隔离。
6. Native ordinary crash cut 只能从 matching active `FileCheckpointV2` 与 exact publish identity 恢复；歧义成为
   `item-blocked`，不创建 terminal receipt。Web workspace/package 只恢复最后验证的 checkpoint/seal/receipt；portable
   handoff 不得报告可继续，complete artifact 不得产生 partial output。
7. stale projection/capability/picker event、destination reservation replay、manifest/seal/package substitution、
   duplicate publication attempt、expired lease 与 ownership-unknown cleanup 均须 fail closed。
8. workspace/portable preparation 超限、generation mismatch 与 checked arithmetic overflow 必须在零 content request
   时失败；ZIP traversal、重复 entry、layout/length/CRC mismatch 均不得 seal。
9. output trace 失败路径仍不得出现名称、路径、handle、capability、object URL、content 或 raw error text。
10. REGISTER/RESUME/STOP challenge 的 purpose、ID、nonce、expiry、RelayIdentity 或任一 route identity 替换及
   challenge replay必须失败；expiry 相等即过期，错误 proof 消耗 attempt，stopped code 的 retry 必须为 0。
11. WS2A/B/N 修改任一 hello axis、digest、code、retry、reserved 或 signature 均失败；同 grant/response replay
    只消费一次。WS2O 修改 magic/reserved/RelaySessionID/length、零长、65,537B 或非 owner connection 均拒绝。
12. direct recovery 必须保持 one-in-flight、fresh AttemptID/operation/grant、wave/session budget 与 typed classifier；
    quiescent rearm、detach replacement 和 late callback 都不得复用旧 authority、关闭 relay 或制造 session terminal。
13. phase/recovery trace 在成功、失败、timeout 和 observer fault 路径都不得出现 SDP、candidate endpoint、nonce、
    proof、raw attach frame、capability、content metadata 或 raw error text。
