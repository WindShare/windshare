# WindShare 威胁模型

本文描述 suite `0x02`、当前在线分享（`LiveOnly`）的核心安全边界。


## 0. 文档维护原则

- 规则描述“必须防止什么以及为什么”，不固定“具体怎么实现”。新增规则若不能指出对应威胁、资产和缺失后的安全后果，就不属于本文。
- UI 流程、产品默认值、平台支持、容量与时间常量、错误码、状态机、存储布局和当前能力限制不得写成安全不变量。
- 本文只保留理解安全边界所需的机制假设。


## 1. 资产与信任边界

保护对象包括读取密钥、文件内容与元数据、发送端身份、接收会话，以及用户授权的本地文件范围。

| 角色 | 信任边界 |
|---|---|
| relay 与网络 | 不可信，可监听、篡改、重放或丢弃流量，也可能与恶意持链者合谋。 |
| 持链者 | 完整链接代表读取授权，可以读取和转发；不因此获得发送端身份、路由控制权或其他接收者的会话密钥。 |
| 发送端 | 是分享内容的来源，但提供的名称、媒体和文件仍可能恶意，不能授予接收端本地文件权限。 |
| 接收端 | 受用户信任保存读取能力、验证内容，并在用户选择的范围内写入文件。 |

默认信任运行客户端的设备、浏览器和操作系统。源文件与输出目录仍可能发生正常的并发修改、重命名或权限变化。

## 2. 核心安全保证

- **端到端保密**：relay 不获得读取密钥、文件内容、文件名、精确大小等明文元数据或内层操作语义；连接协商也受端到端保护。
- **发送端真实性**：链接锚定发送端身份。内容、控制消息和完成状态可验证来源与所属上下文；持链者即使能解密，也不能冒充发送端。路由注册、恢复和停止需要有效且新鲜的发送端证明。
- **会话隔离与防重放**：接收者证明持有读取能力后建立独立会话。其他会话或过期上下文中的消息不能被用于窃取会话、扩大权限或恢复已失效的授权。
- **内容一致性**：目录和文件版本可验证，不能把不同版本的内容静默拼接，也不能把未完成内容当作完整结果。源文件变化不能静默替换已认证版本，恢复进度需要可信的完整性证据。
- **本地权限受限**：发送端只读取授权的源范围；接收端只在用户授权范围内写入、覆盖或清理。远端路径、归档条目和符号链接不能绕过这一边界，恢复与清理不能认领或删除归属不明的对象。
- **资源与故障隔离**：不可信输入和并发工作受资源预算约束；失败尽量限制在受影响的范围内，单个参与者不能无必要地拖垮其他分享或会话。
- **停止与恢复**：发送端停止分享后，该分享实例的路由与活动服务失效，旧消息不能使其复活。重新分享或恢复需要有效授权，新内容实例不能继承旧实例的内容验证结果或输出权限。

## 3. 已知风险与保护范围之外

- **链接泄漏即读取权泄漏**：完整链接被转发、截图或聊天平台读取后，对方即成为持链者。URL fragment 不会阻止聊天平台读取消息中的完整链接；本地保存链接也会延长暴露窗口。当前不提供接收者身份认证，也无法收回已经泄漏的密钥或已获取的内容。
- **不保证可用性或匿名性**：恶意 relay 和网络可以拒绝服务。relay 仍能看到路由身份、发送端公钥、IP、连接关系及密文长度、时序和总量，并据此推测活动；直连也可能向对端暴露地址。不承诺流量隐藏。
- **可信来源不等于安全内容**：恶意发送端可以提供签名有效的恶意文件或媒体，接收端仍按不可信输入处理。
- **版本验证有能力边界**：源版本证据存在缺陷或无法识别的变化时，可能漏检内容修改；未采用快照或内容哈希的模式不承诺相应保证。
- **前向保密有范围**：临时密钥擦除后的会话流量与控制消息应具备前向保密；长期读取密钥保护的分享对象不作此承诺。
- **端点与依赖风险**：设备被入侵、同一 OS 账户下的恶意进程、受信任前端被注入代码、供应链攻击，以及密码库、浏览器和文件系统的实现缺陷不在本模型的保护范围内。
