# 分享连接恢复计划

分享在用户停止分享或退出发送软件时结束，连接是可以失效和替换的承载。网络或中转恢复后，应自动恢复同一分享的接入能力，保留原链接、健康直连和可复用的下载进度。

## 当前问题

- 服务端恢复检查只接受 `routeGrace`；客户端先发现断线时，仍在线的旧连接会挡住恢复，并被错误地归为 `NotFound`。
- CLI 约 55 秒恢复失败后，中转接入循环永久退出；某个中转首次连接失败也不会再试。
- 恢复仅尝试 `RESUME`，无法处理中转重启或登记过期后的重新发布；缺少心跳也让失联检测没有明确时限。
- 默认输出显示恢复失败，却隐藏恢复成功，无法说明当前下载、新接收者接入和后台恢复的实际状态。

主要涉及 `cmd/wind/internal/cli/sender_relay.go`、`connectivity/relayset/sender.go`、`relay/signaling/v2route/registry.go`、`relay/signaling/v2endpoint` 和 `transport/relayv2`。

## 设计调整

1. **统一每个中转的完整生命周期。** 一个组件负责首次连接、在线接入、快速恢复、低频等待、重新发布和停止。临时故障在快速恢复预算耗尽后转入带随机抖动的低频重试，每次拨号有超时；网络变化可提前唤醒。同一中转只允许一个恢复任务。首个可用中转即可提供服务，其余中转独立恢复，包括首次连接失败的备用中转。

2. **明确恢复结果的语义。** 已完成发布的登记仍存在时，允许完成身份和恢复凭据认证后接管旧连接；登记确实不存在时，重新认证发布。未完成发布的 `routeStarting` 按发布流程处理，不能直接恢复为可用登记。`NotFound` 不再兼指旧连接仍在线。首次发布或重新发布的成功确认丢失时，沿用原凭据认证恢复，不能把拨号失败当作登记不存在，也不能把 `AlreadyRegistered` 一律当作身份冲突。凭据无效、身份冲突、分享已停止或撤销等情况有明确的终止或人工处理路径，不能一律转为重新注册。

3. **保护接管与清理的连接所有权。** 恢复认证前绑定待替换的所有者和登记版本，认证后原子校验并切换；版本已变则拒绝本次提交，防止迟到请求覆盖新连接。使用现有 `ConnectionRef` 代际机制清理旧连接及其所属中转会话，不能误伤新登记、其他中转或健康直连。停止状态不可逆，停止与重连并发时也不能重新开启分享。

4. **分享持有稳定发布材料。** 复用 `PreparedSender` 已持有的分享身份、分享实例、密钥和原始加密描述字节；各中转的恢复凭据由连接生命周期组件在首次拨号前生成并保留。恢复时逐字节复用描述对象，避免重新加密被浏览器判为身份变化。重新发布不重建整个分享、不重新扫描目录；已验证的下载进度由下载层继续管理。

5. **传输层负责发现失联。** 原生客户端与中转使用 WebSocket Ping/Pong；浏览器使用由中转连接层直接响应的应用层探活，同步更新 Go/TypeScript 协议解析。探活及响应超时覆盖静默丢包和收不到关闭通知的断线；超时需考虑队列背压导致的读取延迟，避免误判正常阻塞。健康直连传输时仍维持中转探活，不能以缺少文件流量判定失联。心跳只负责检测并结束对应失效连接，恢复策略集中在连接生命周期组件，CLI 负责装配和展示，中转集合负责汇合接入。

6. **界面表达实际可用性。** 首次启动时所有中转均暂不可用，则显示可取消的等待状态；至少一个中转完成发布并确认可接入后，才生成、展示分享链接并宣布就绪。分别说明当前传输是否继续、新接收者能否加入、是否仍在恢复，并显示恢复成功；结合全部中转的状态判断接入能力。详细尝试次数、恢复阶段、失败原因以及分享和连接代际标识进入结构化日志与 trace。

## 接收端恢复与续传

- **活动下载持续等待。** 浏览器和 CLI 的中转重拨、协议会话重建在临时故障的快速恢复预算耗尽后均转入低频自动等待，不因此终止下载。复用现有跨会话恢复抽象，保留原下载任务、输出归属和可复用进度。每次尝试有超时，并发和重试速率有界；重连不绕过 P2P 尝试预算。CLI 支持调用者指定等待期限。
- **优先原页面恢复。** 浏览器自动恢复并提供立即重连入口，连接失败不直接结束下载任务。立即重连只唤醒现有恢复组件，不走会重置任务和输出状态的重新加入流程。重开原链接后找回下载作为页面关闭后的兜底，沿用各保存方式的检查点、授权和进度保留限制。
- **首次接入有限等待。** 暂时不可达或 `NotFound` 时，在有限窗口内自动等待，之后提供重试或继续等待；不能仅凭 `NotFound` 宣布链接永久失效。明确无效的链接或认证错误及时反馈。
- **尊重用户操作和故障边界。** 暂停后不自动继续下载，停止后取消相关恢复。分享撤销、身份异常、文件版本变化和输出错误按各自范围处理，不能统一归为网络等待。连接重试由恢复组件统一调度，下载与输出层继续管理进度和保存。

相关入口：`web/src/receiver/`、`web/src/transport/relay/v2-receiver.ts`、`web/src/ui/v2-gateway.ts`、`web/src/ui/v2-controller.ts`、`cmd/wind/internal/cli/get.go`、`get_transfer.go` 和 `connectivity/relayset/receiver.go`。

## 用户体验与代价

短暂断网、休眠恢复或中转重启后，软件自动恢复原链接；直连健康时下载继续。正常分享不增加操作步骤，也不增加逐块确认、目录扫描或磁盘复制。

代价主要是少量心跳和后台重试，以及等待期间保留任务状态、可能持续占用输出句柄；低频退避会增加恢复等待。避免过短心跳超时、持续高频重试，以及等待所有中转恢复才允许已有路径工作。实际性能开销在实现后验证。

重点覆盖首次连接全部失败后恢复、发布确认丢失、旧连接接管、迟到提交与清理、登记丢失、停止与重连竞争、健康直连持续传输，以及浏览器静默断线检测、首次接入等待、活动下载长时间断网恢复、原页面重连、CLI 等待期限与取消、页面关闭后的续传行为。超时和退避使用可控时钟测试，避免拉长本地测试时间。
