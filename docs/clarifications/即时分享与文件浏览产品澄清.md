## 1. 目录时间语义

- 后代目录按首次按需扫描（浏览或下载）冻结为不可变 generation，不提供 live refresh，也不承诺点击分享时的全树快照。
- 每个目录 generation 完整提交后，其中的已选文件即可传输；不发布 provisional page。
- 冻结后源文件变化使该文件 revision 失败，不静默更新旧 generation。
- R0 为同一能力链接下的 `ShareInstance` 换代（原地刷新）预留协议语义，实现不早于 M2；
  初版分享界面明示“内容在对方首次按需浏览或下载时定格，之后的修改和新增不会同步”。
- 链接就绪后默认低优先级预取所选目录根的第一层；这是按需浏览的明确根层例外，首层在分享时刻附近冻结；
  更深目录仍按首次按需发现（浏览或下载）冻结，未被请求的更深内容不会提前加载。纯文件分享无需预取（根事务已冻结其身份与大小）。
- 宽目录首次按需发现期间显示“已发现 x 项”单调进度；目录仍原子冻结，不发布临时页。
- 一次多选的顶层项有具名上限（初值 4096 项），所选文件夹内的后代不计数、无上限。
- 中转确认后才展示链接，之前显示“正在启动”；分享界面显示接收端连接与传输的基础状态。

## 2. 内容激活与连接

- 纯目录浏览继续使用已建立的 relay，不启动 ICE。用户点击 preview/download 时，同一次 activation 立即允许 relay
  content 并启动后台 P2P；文件数、体积、目录发现、artifact confirmation、picker 和 preparation 都不参与连接准入。
  这比原始需求中的短等待更快开始出字节，同时保留稍后采用 P2P 的目标。
- relay 与已认证 peer 可同时承载 block；P2P 的 negotiation、admission、重试、detach recovery 或耗尽都不打断 relay。
  当前不承诺 route priority、relay throttling、low-speed/cost convergence、mandatory TURN 或用户可调 timeout。
- P2P negotiation 默认 15 秒；DataChannel Open 后获得新的 20 秒 lane-admission budget，并为 30 秒 one-use grant
  保留至少 5 秒 completion margin。每个 ProtocolSession 同时最多一个 attempt。
- transient failure 与 authenticated `grant-expired`/`admission-limited` 可在 3 attempts/2 minutes 的 wave 和
  8 attempts/6 active minutes 的 session budget 内恢复。wave exhaustion 后的新 activation 或 network change 可
  rearm；permanent path failure 与 session exhaustion 不可由 UI event 绕过，relay 仍可继续。
- 同一 ProtocolSession 的 PeerPathID 在恢复期间稳定；每次 replacement 使用新的 AttemptID、offer/grant operation、
  one-use grant 与 proof。peer detach 复用同一 supervisor；logical LaneID 只能配新 epoch 与新 grant 重新接纳。

## 3. 发送端源文件

- 发送端不得创建内容临时文件、完整副本、staging 或本地内容快照，也不靠读取/哈希完整内容生成 revision identity。
- 默认优先写入排除句柄，无法取得（如源已被写模式打开）时回退可靠单调变化标识；两者皆不可得时直接失败。
  锁定在最后 lease 与 resume grace 结束后释放，但 frozen source evidence 的逻辑 revision identity 保留。
- grace 后 reopen 只有证据完全相同才以新 lease 复用同一 revision；权限、暂时 I/O 或其他无法完成的比较保持可重试。
  已证明的变化永久失效该 revision 及 cache，不为同一 frozen FileID 静默发布 replacement revision。
- POSIX 无强制锁时，inode+size+mtime+ctime 组合即视为可靠变化标识；provider token 误复用或同指纹原地改写
  可能越过 handle gap 而无法检测，这是已接受的文档化残余，不是内容 hash/snapshot 保证。
- 发送端 UI 须明示：分享期间文件可能被锁定，本机修改会中断接收方下载。

## 4. 输出产物、保存与恢复

- 选择变化先进入“正在确认所选内容”。认证证据一旦证明 tree shape，即使最终命名/层级仍未解析，也可显示
  `directory-tree` 的语义产物选择；后台确认与发现永不打开 picker。
- 用户点击先安装一次 activation，并在同一调用栈启动至多一个所需 picker。兼容的发现细化、确认重试、joined-object
  或 ProtocolSession 替换会从 observation replacement 一直保留选择和本地 authority 到 commit/adoption；commit 等待非空
  `ArtifactSpec` 与最新 route facts，已返回的 compatible bound operation 也会等最新 observation 到齐后才采用。picker 拒绝
  回到已提供的选择且不产生 incident；selection、已认证 ShareInstance 或产物/route 语义变化要求重新点击。
- replacement 在 final fence 前中止 commit 时，route 只有证明 durable effects 全部不存在并恢复为可提交状态，才会返回
  `retryable-precut`；coordinator 随最新 observation 自动 recommit 同一 authority，不会重开 picker。普通 rejection 会结束
  authority；fence 后可能已有 durable effects 时只能返回 owned authority 或 bound operation，不能伪装成无害重试。
- 用户选择最终产物，而不是 OPFS、stream 或 backend。单文件可“下载 <文件名>”或“保存到文件夹”；多个文件、
  目录或显式空目录在有目录 authority 时默认“按原文件夹层级保存”，ZIP 是单独标注的显式操作；只有 bounded
  portable route 时显示“检查后下载”。能力/容量变化不能静默在 `directory-tree` 与 `zip-archive` 间降级。
- `ReceiveIntentV1` 只在 resolved action、最新 route facts 与已取得 authority 通过 final fence 后冻结本次
  SelectionSpec、非空 ArtifactSpec 与 materialization binding。它只属于 receiver；不传给 sender/relay，也不包含
  projection epoch、未来 revision、连接路径或 runtime session。intent freeze 后的勾选变化只影响下一次 operation。
- `original-file` 与 `zip-archive` 是 complete artifact；`directory-tree` 是 prefix-visible artifact。完整选择一个目录
  使用原目录名和 `<目录名>.zip`；目录内部分选择使用 `<目录名>-selection`；多根使用 `windshare` / `windshare.zip`。
  目录与 ZIP 保留同一结果根、必要祖先和显式空目录。单文件保存到目录直接用文件名，不额外创建结果根。
- `directory-tree` 只让用户选择 parent/container。WindShare 创建或 reopen task-owned result entry；同名 unrelated
  entry 使用 persisted suffix，ownership 或外部并发不明时停止提示，不合并、不覆盖。单文件在 authenticated
  revision open 前不创建占位；真实零字节文件仍按普通 transaction 完成。
- workspace 是 receiver-owned materialization/storage，不是最终 destination。workspace `original-file`/`zip-archive`
  完整封存后才进入 `waiting-to-save`；之后换保存位置或使用 `browser-handoff` 只创建新的 publication attempt，
  不重新接收或打包。save picker 取消仍是 `waiting-to-save`，不伪装成 pause/failure。
- Workspace ZIP 与 portable download 在任何文件内容请求前完成 exact preparation：确认完整 selection、layout、
  exact ZIP bytes、metadata 与容量；超限或 generation 变化在零 content request 时失败。ZIP 使用 `store` encoding 与
  `complete-only` completeness；所有 selected items 成功并验证 close/layout 后才可用，不生成 partial ZIP。
- `WorkspaceBudgetV1` 按 `uniqueRawBytes`、`packageBytes`、`peakTemporaryBytes`、`durableMetadataBytes` 计算 checked
  `peakOwnedBytes`。浏览器 quota estimate 是 optional observation，不是 route authority 或 reservation；缺失、失败或无效时
  记为 unknown，不隐藏 workspace，也不连带隐藏 FSA/portable。实际 allocation 仍逐阶段 admission，动态不足进入
  `resumable-receive` 或 `resumable-package`，不能改变用户选定 artifact。portable route hard limit 为 64 MiB 且不能跨刷新恢复。
- workspace 在创建任何 OPFS entry 前，先原子持久化 operation、binding、初始 lifecycle 与带不可预测 entry identity 的
  activation candidate；随后创建 entry、写入 exact ownership marker，再以持久 handle 原子 promote 并移除 candidate。
  reload 会在展示 retained inventory 前恢复这些 candidate：只认 exact marker/entry；无法证明 absent 或 owned 时保留为
  `needs-attention`，不会按名称认领陌生目录。
- `directory-tree` 可在完成前看到文件。Native CLI 的 item/subtree failure 保留成功文件、本次命令为 partial、
  operation 仍 active，直到剩余项成功或用户显式 discard。checkpoint revision conflict 只阻塞该 item，独立 siblings
  继续；collision-only partial 明确报告已有 destination，不显示 `unexpected`。Web 继续用 `partial-directory` 表示相同
  prefix-visible 行为。两类 output 的 stop/discard 都只清理 ownership-proven unfinished state；
  `original-file`/`zip-archive` 永不发布已知残缺 bytes。
- managed atomic target 确认 commit 才是 `published`。`browser-handoff` 只能进入 `download-started`，表示浏览器
  已接管；它不代表已保存，也不等于 `published`。workspace-backed download 在原 deadline 前可再次下载；
  portable handoff 不宣称 recovery。
- `FileCheckpointV2` 是唯一 verified-range truth；`RecordID` 和 ranges 仍属于原 physical record。receiver 以
  operation/intent/binding、FileID、canonical path、materializer 与 authority 派生本地 lineage index，不新增 wire
  或 persisted checkpoint field。exact lineage+revision 才恢复；另一 revision 是 `revision-conflict`，ownership/invalid
  binding 分别是 `owned-object-unknown`/`checkpoint-invalid`，均保留旧 data 并只阻塞该 item。只有没有 authenticated
  lineage 的已占用 destination 才是 collision。继续仍要求 sender 在线、相同 derived revision evidence 且 permission
  可重新取得；progress、UI、preview cache 和 aggregate manifest 都不能制造 have-state。
- 当前 Web 已支持 inventory、ownership-scoped discard/expiry、`waiting-to-save` 保存和 workspace
  `download-started` 再次 handoff。`resumable-receive`/`resumable-package` 的 Continue 调用 output-owned executor，
  分别复核 exact preparation 或 sealed package evidence；UI 不重建 authority。
- post-cut settlement 或 detach 失败时 activation 保留 in-memory owner 并显示可重试的 cleanup-required 状态；重试只执行
  尚未成功的阶段，成功 detach 后刷新 retained inventory。在 cleanup 完成前，新 activation 与 retained continuation 都被阻止。
  retained action 自开始即显示 busy，并暂时禁用 selection、artifact/retry 与全部 retained controls；controller admission 仍是
  authority，busy presentation 会在成功、失败、取消或 reload 时清除。
- 24 小时 retention 只在 task 稳定进入 `resumable-receive`、`resumable-package` 或 `waiting-to-save` 时开始。active
  receive/package/publication 不过期；heartbeat、查看页面和 handoff 不续期。workspace `download-started` 沿用原
  deadline。到期后禁止继续并在下次前台运行清理；浏览器提前回收 storage 时不能承诺仍可恢复。
- v1 checkpoint、paused descriptor 与 partial-ZIP record 不迁移、不双读，也不会生成可继续 task。certified cleaner
  只删除 WindShare namespace 内 ownership-proven old state；`published` 或 ownership-unknown object 保留并提示。

## 5. 离线上传与退出

当前生产只实现 `LiveOnly`：服务来自在线发送端；明确 Stop/退出会终止活动下载并使链接永久失效。
只有意外中断（进程崩溃或网络断线）可进入具名 crash grace，明确停止不得恢复在线路由。

`OfflineUploading` 与 `OfflineCommitted` 是 M4 预留合同，当前没有生产 offline uploader、inventory commit
或寄存交付路径。若 M4 实现：

- 未提交对象不得对 receiver 可见，在线发送端仍是服务源；
- 只能寄存 transport-neutral descriptor、catalog、revision、block 等 sender objects，不保存 session envelope，
  也不取得解密密钥或 sender 私钥；
- 只有服务器验证完整 inventory 并原子返回 `COMMIT_ACK` 后才能进入 `OfflineCommitted`，此后 UI 才可提示
  发送端退出而不使链接失效；commit 前 Stop 必须取消上传并清理未提交 staging。

## 6. 元数据隐私

文件名、精确大小和文件标识不得以协议字段明文暴露。允许 relay 从密文长度、时序和传输量推断
近似甚至精确的大小；本阶段不要求 padding 或流量隐藏。

## 7. 预览粒度

- 首版预览仅由用户对单个文件的显式点击触发，不提供缩略图墙；批量预览列为 M2/M3 评估项。
- R0 的 lease/句柄/配额合同须为批量预览预留余量，避免未来回改已冻结预算。

## 8. 链接与密钥分发

- 支持将链接与 `#` 后密钥分开复制、经不同渠道发送；接收页缺密钥时本地输入拼接，密钥不离开浏览器。
- suite 0x02 的 `pkHash` 使 fragment 约 44 字符，长度代价已接受。
