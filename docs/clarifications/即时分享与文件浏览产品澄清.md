## 1. 目录时间语义

- 后代目录按首次按需扫描（浏览或下载）冻结为不可变 generation，不提供 live refresh，也不承诺点击分享时的全树快照。
- 每个目录 generation 完整提交后，其中的已选文件即可传输；不发布 provisional page。
- 冻结后源文件变化使该文件 revision 失败，不静默更新旧 generation。
- R0 为同一能力链接下的 `ShareInstance` 换代（原地刷新）预留协议语义，实现不早于 M2；
  初版分享界面明示“内容在对方首次按需浏览或下载时定格，之后的修改和新增不会同步”。
- 链接就绪后默认低优先级预取所选目录根的第一层；这是按需浏览的明确根层例外，首层在分享时刻附近冻结；
  更深目录仍按首次按需发现（浏览或下载）冻结，未被请求的更深内容不会提前加载。纯文件分享无需预取（根事务已冻结其身份与大小）。
- 宽目录首次按需发现期间显示“已发现 x 项”单调进度；目录仍原子冻结，不发布临时页。
- 一次多选的顶层项有具名上限（初值 4096 项），所选文件夹内的后代不计数、无上限。
- 中转确认后才展示链接，之前显示“正在启动”；分享界面显示接收端连接与传输的基础状态。

## 2. 小分享与连接

```text
Small = discoveryTerminal && fileCount < 30 && totalBytes < 8 MiB
```

- 只统计文件；空文件计数，目录不计数。恰好 30 个文件或 8 MiB 均为非小分享。
- 未完成或失败的目录发现不能证明为小分享，按非小分享时序处理。
- 下载点击即启动连接计时，R 合同冻结 0/8 两档：0 秒启动直连，非小分享最迟约 8 秒加入应用 relay；
  目录发现不得延后该上限。约 8 秒是对原始需求“10 秒等待”的有意收紧（接收者更早开始出字节）。
  TURN 升级档位待连接可用性提案批准后插入。

## 3. 发送端源文件

- 发送端不得创建内容临时文件、完整副本、staging 或本地内容快照。
- 默认优先写入排除句柄，无法取得（如源已被写模式打开）时回退可靠单调变化标识；
  两者皆不可得时直接失败。锁定随最后 lease 与 resume grace 结束释放。
- POSIX 无强制锁时，inode+size+mtime+ctime 组合即视为可靠变化标识；同指纹原地改写是
  已接受的文档化残余，不按安全事件处理。
- 发送端 UI 须明示：分享期间文件可能被锁定，本机修改会中断接收方下载。
- 检测到变化后永久失败该 revision，并废弃其 lease、缓存和 receiver VerifiedDurableRanges。

## 4. 输出产物、保存与恢复

- 选择变化先进入“正在确认所选内容”。确认是后台状态，不会打开 picker；暂时失败可“重试确认”并保留
  已认证证据。只有最终 artifact action 已显示后，用户点击才在同一调用栈启动需要的 picker。
- 用户选择最终产物，而不是 OPFS、stream 或 backend。单文件可“下载 <文件名>”或“保存到文件夹”；多个文件、
  目录或显式空目录在有目录 authority 时默认“按原文件夹层级保存”，ZIP 是单独标注的显式操作；只有 bounded
  portable route 时显示“检查后下载”。能力/容量变化不能静默在 `directory-tree` 与 `zip-archive` 间降级。
- `ReceiveIntentV1` 在 action 和 authority 校验后冻结本次 SelectionSpec、ArtifactSpec 与 materialization binding。
  它只属于 receiver；不传给 sender/relay，也不包含 projection epoch、未来 revision、连接路径或 runtime session。
  运行中的勾选变化只影响下一次 operation。
- `original-file` 与 `zip-archive` 是 complete artifact；`directory-tree` 是 prefix-visible artifact。完整选择一个目录
  使用原目录名和 `<目录名>.zip`；目录内部分选择使用 `<目录名>-selection`；多根使用 `windshare` / `windshare.zip`。
  目录与 ZIP 保留同一结果根、必要祖先和显式空目录。单文件保存到目录直接用文件名，不额外创建结果根。
- `directory-tree` 只让用户选择 parent/container。WindShare 创建或 reopen task-owned result entry；同名 unrelated
  entry 使用 persisted suffix，ownership 或外部并发不明时停止提示，不合并、不覆盖。单文件在 authenticated
  revision open 前不创建占位；真实零字节文件仍按普通 transaction 完成。
- workspace 是 receiver-owned materialization/storage，不是最终 destination。workspace `original-file`/`zip-archive`
  完整封存后才进入 `waiting-to-save`；之后换保存位置或使用 `browser-handoff` 只创建新的 publication attempt，
  不重新接收或打包。save picker 取消仍是 `waiting-to-save`，不伪装成 pause/failure。
- Workspace ZIP 与 portable download 在任何文件内容请求前完成 exact preparation：确认完整 selection、layout、
  exact ZIP bytes、metadata 与容量；超限或 generation 变化在零 content request 时失败。ZIP 使用 `store` encoding 与
  `complete-only` completeness；所有 selected items 成功并验证 close/layout 后才可用，不生成 partial ZIP。
- `WorkspaceBudgetV1` 按 `uniqueRawBytes`、`packageBytes`、`peakTemporaryBytes`、`durableMetadataBytes` 计算 checked
  `peakOwnedBytes`。浏览器 quota estimate 不是 reservation；动态不足按阶段进入 `resumable-receive` 或
  `resumable-package`，不能改变用户选定 artifact。portable route hard limit 为 64 MiB 且不能跨刷新恢复。
- `directory-tree` 可在完成前看到文件。Native CLI 的 item/subtree failure 保留成功文件、本次命令为 partial、
  operation 仍 active，直到剩余项成功或用户显式 discard。Web 继续用 `partial-directory` 表示相同行为。两类 output 的
  stop/discard 都只清理 ownership-proven unfinished state；`original-file`/`zip-archive` 永不发布已知残缺 bytes。
- managed atomic target 确认 commit 才是 `published`。`browser-handoff` 只能进入 `download-started`，表示浏览器
  已接管；它不代表已保存，也不等于 `published`。workspace-backed download 在原 deadline 前可再次下载；
  portable handoff 不宣称 recovery。
- `FileCheckpointV2` 是唯一 verified-range truth。refresh/reopen 必须复核同一 OperationID、ReceiveIntentDigest、
  FileID/revision/path/size、binding 与 owned object；progress、UI、preview cache 和 aggregate manifest 都不能制造
  have-state。继续仍要求 sender 在线、revision 未变且 permission 可重新取得。
- 当前 Web 已支持 inventory、ownership-scoped discard/expiry、`waiting-to-save` 保存和 workspace
  `download-started` 再次 handoff。`resumable-receive`/`resumable-package` 的 Continue 调用 output-owned executor，
  分别复核 exact preparation 或 sealed package evidence；UI 不重建 authority。
- 24 小时 retention 只在 task 稳定进入 `resumable-receive`、`resumable-package` 或 `waiting-to-save` 时开始。active
  receive/package/publication 不过期；heartbeat、查看页面和 handoff 不续期。workspace `download-started` 沿用原
  deadline。到期后禁止继续并在下次前台运行清理；浏览器提前回收 storage 时不能承诺仍可恢复。
- v1 checkpoint、paused descriptor 与 partial-ZIP record 不迁移、不双读，也不会生成可继续 task。certified cleaner
  只删除 WindShare namespace 内 ownership-proven old state；`published` 或 ownership-unknown object 保留并提示。

## 5. 离线上传与退出

当前生产只实现 `LiveOnly`：服务来自在线发送端；明确 Stop/退出会终止活动下载并使链接永久失效。
只有意外中断（进程崩溃或网络断线）可进入具名 crash grace，明确停止不得恢复在线路由。

`OfflineUploading` 与 `OfflineCommitted` 是 M4 预留合同，当前没有生产 offline uploader、inventory commit
或寄存交付路径。若 M4 实现：

- 未提交对象不得对 receiver 可见，在线发送端仍是服务源；
- 只能寄存 transport-neutral descriptor、catalog、revision、block 等 sender objects，不保存 session envelope，
  也不取得解密密钥或 sender 私钥；
- 只有服务器验证完整 inventory 并原子返回 `COMMIT_ACK` 后才能进入 `OfflineCommitted`，此后 UI 才可提示
  发送端退出而不使链接失效；commit 前 Stop 必须取消上传并清理未提交 staging。

## 6. 元数据隐私

文件名、精确大小和文件标识不得以协议字段明文暴露。允许 relay 从密文长度、时序和传输量推断
近似甚至精确的大小；本阶段不要求 padding 或流量隐藏。

## 7. 预览粒度

- 首版预览仅由用户对单个文件的显式点击触发，不提供缩略图墙；批量预览列为 M2/M3 评估项。
- R0 的 lease/句柄/配额合同须为批量预览预留余量，避免未来回改已冻结预算。

## 8. 链接与密钥分发

- 支持将链接与 `#` 后密钥分开复制、经不同渠道发送；接收页缺密钥时本地输入拼接，密钥不离开浏览器。
- suite 0x02 的 `pkHash` 使 fragment 约 44 字符，长度代价已接受。
