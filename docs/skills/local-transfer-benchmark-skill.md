# Local folder transfer benchmark

Run the actual product with freshly built sender/relay binaries, an isolated installed Edge profile, and a real native destination. Default to one warmup plus three measured transfers **per mode and version**: eight transfers for current code, sixteen for a two-version comparison. This measures local product transfer with diagnostics enabled, not network bandwidth.

## Local dependencies

| Item | Configuration |
| --- | --- |
| Repository | Current Git checkout |
| Original source | `$env:WINDSHARE_BENCHMARK_SOURCE` |
| Native-picker automation | `$env:WINDSHARE_NATIVE_UI_REPLAY_MODULE` |
| Benchmark launcher | `.tmp/local-transfer-tools/run-local-transfer-rust-current.ps1` (generated by the [tracked adapter](../../web/scripts/browser-evidence/local-transfer-benchmark/prepare.mjs)) |
| Local helper directory | `web/test/.tmp/local-transfer-ab/` |

Go, stable Rust, Node, installed Edge, and matching `web/node_modules` dependencies are required. The adapter uses `run-current.mjs`, `source-identity-rust.mjs` and `fixture-identity.mjs` from the local helper directory and the native-picker template `.tmp/local-transfer-tools/run-local-transfer-current.ps1`. Helpers and launchers under `.tmp` are **ignored local files, absent from a fresh checkout**. Check their existence and contents before use; filenames and version arguments alone do not prove which source or timing contract they execute. Do not assume old reports or source snapshots still exist.

If helpers are missing, recreate an ignored driver using the contract below and the tracked [native evidence helpers](../../web/scripts/browser-evidence/folder-recovery/README.md). The stock folder-recovery benchmark generates local bytes and exercises output modules; it does not replace this product transfer test. Keep the ES module driver beneath `web/test/.tmp/` so Playwright, Vite and ZIP imports resolve. Set the two environment variables above to your local fixture and native-picker module before running.

## Shared preparation

Execute commands through `mcp__ripple`; set the repository location explicitly. If Ripple says **Pipeline NOT executed**, resend. Use 30-second execution timeouts and bounded `wait_for_completion` calls. For progress, read the run's `current.json`; it records navigation/ready/receiving transitions, not a live completion percentage. Avoid repeatedly dumping the large report.

```powershell
$repoRoot = (git rev-parse --show-toplevel).Trim()
Set-Location -LiteralPath $repoRoot
$fixture = (Resolve-Path -LiteralPath $env:WINDSHARE_BENCHMARK_SOURCE).Path
$ErrorActionPreference = 'Stop'
$env:GOWORK = 'off'
$env:GIT_OPTIONAL_LOCKS = '0'
$runId = Get-Date -Format 'yyyyMMdd-HHmmss'
Get-ChildItem -LiteralPath $fixture -File -Recurse -Force |
    Measure-Object -Property Length -Sum
node web/scripts/browser-evidence/local-transfer-benchmark/prepare.mjs
if ($LASTEXITCODE -ne 0) { throw 'Rust benchmark preparation failed' }
```

The fixture last contained 582 files and 6,762,858 bytes. Count it again, including hidden `.git` and `.venv` files, and preserve its contents. Disabling optional Git locks prevents read-only status checks from refreshing the original index when verifying its exact bytes.

**Normalize native-picker paths before creating directories or invoking the UI wrapper.** PowerShell/Node filesystem APIs accepting `C:/...` does not imply the Windows dialog accepts it. A real setup attempt rejected that format as an invalid folder name. Use `[IO.Path]::GetFullPath($Target)` in the Windows launcher and OS-native `path.join` when generating paths in Node; pass the same normalized absolute path to directory creation, picker selection and permission verification. Preserve the `native-acquired.json` / `permission-complete.json` handshake. Keep the launcher's existing Edge unnamed-RootView/Label handling and scoped foreground recovery when adapting it.

## Current code only

```powershell
# The _stignore suffix keeps run output out of Syncthing replication.
$output = Join-Path $PWD ".tmp/local-transfer-ab-${runId}_stignore"
& .\.tmp\local-transfer-tools\run-local-transfer-rust-current.ps1 -RunId $runId -Repetitions 3
```

This includes the current working-tree edits without reverting them. No baseline worktree is needed for this mode. The launcher rejects existing output/target directories and uses independent ephemeral ports, so the user's `dev.ps1` need not be stopped.

## Before/after comparison

For “before the uncommitted changes”, default to the current **HEAD**, record its full SHA, and state that choice. Honor a specifically requested revision; the local preparation helper below currently snapshots HEAD only. `main` and `workspace` are helper version labels, not branch-selection instructions.

Prepare two isolated source directories: a clean baseline and a snapshot containing staged, unstaged, intent-to-add and non-ignored untracked files, including deletions. Before creating them, save the original index bytes, staged/unstaged binary patches, exact changed/untracked file bytes, and a complete file-hash manifest. Verify the current snapshot against the original sources. Do not stash, reset, clean, switch branches or stage files in the original checkout. Reuse `web/node_modules` only when the dependency manifests match.

Use the same generated Rust launcher for both snapshots when both revisions support `--config`. The local comparison helpers prepare the source snapshots and generate `compare-workspace.mjs` for the results.

```powershell
$helpers = 'web/test/.tmp/local-transfer-ab'
$comparison = Join-Path $PWD ".tmp/local-transfer-compare-$runId"
node "$helpers/prepare-workspace-comparison.mjs" $PWD.Path $comparison
if ($LASTEXITCODE -ne 0) { throw 'Snapshot preparation failed' }
node "$helpers/adapt-workspace-comparison.mjs" $PWD.Path $comparison
if ($LASTEXITCODE -ne 0) { throw 'Comparison helper preparation failed' }
$config = Get-Content -LiteralPath (Join-Path $comparison 'comparison-config.json') -Raw | ConvertFrom-Json
$launcher = Join-Path $PWD '.tmp/local-transfer-tools/run-local-transfer-rust-current.ps1'
& $launcher -SourceRoot $config.mainRoot -Output $config.mainOutput -Target $config.mainTarget -Version main -Repetitions 3
& $launcher -SourceRoot $config.workspaceRoot -Output $config.workspaceOutput -Target $config.workspaceTarget -Version workspace -Repetitions 3
node "$helpers/compare-workspace.mjs" $comparison > (Join-Path $comparison 'comparison-output.json')
if ($LASTEXITCODE -ne 0) { throw 'Comparison or strict output verification failed' }
node "$helpers/verify-workspace-preservation.mjs" $comparison
if ($LASTEXITCODE -ne 0) { throw 'Original checkout changed; inspect without restoring automatically' }
```

Run versions sequentially to avoid competing for local resources. Both must use `local-transfer-observed-completion-v2`, identical diagnostics and the tracked transfer clock. The old `run-revision.mjs` uses a later selector/metrics endpoint; do not compare its durations with observed-completion samples. Isolated Vite roots both load `/src/main.tsx`; discard obsolete expectations for a historical nested baseline URL. Source comparison must handle added/deleted files and distinguish newline-only differences from code changes.

## Driver contract

1. Capture HEAD, working-tree status, relevant source/configuration hashes, tool/browser versions and fixture hashes. Build `./cmd/wind` with `GOWORK=off` and the Rust `relay-native` (release) into the run output; never reuse a possibly stale `cmd/wind/wind.exe`. Build the relay in `relay-rust/` with `rustup run stable cargo build --locked --release -p windshare-relay-native --bin relay-native --message-format=json-render-diagnostics` and copy the reported executable.
2. Start Vite on an ephemeral loopback port with HMR and watching disabled. Use [the relay configuration helper](../../web/scripts/browser-evidence/local-transfer-benchmark/relay.mjs) to write `<output>/relay-state/node.json` with an ephemeral loopback listener and STUN ports, an isolated database and identity, and the Vite origin allowlisted. Launch `relay-native --config <output>/relay-state/node.json`. Read `relay_url` from the `listening` event on stdout. Start the fresh sender with `share <source> --relay <relay_url> --front-url <vite-origin> --verbose --trace <output>/sender.ndjson` and read the emitted link.
3. Launch installed Edge with a new persistent profile. Acquire the real directory handle through `folder-recovery/native-target.mjs` and the native wrapper, completing the permission handshake before opening product pages.
4. Each transfer gets a new product page and cleared IndexedDB/local/session storage. Preserve only `windshare-folder-evidence-target`. Override `showDirectoryPicker` to return a fresh child of that authorized root; retain real native filesystem and IndexedDB implementations.
5. For ZIP, disable `showDirectoryPicker` and `showSaveFilePicker` on that page to select the production browser-download path. Keep production staging enabled and save the resulting ZIP inside the run output.
6. Enable `window.windshareDiagnostics`, identical IndexedDB/filesystem lifetime counters and CDP performance metrics. Keep automatic peer/relay selection and the 1.5-second settling interval; record the actual loaded frontend entry URL.
7. Run repetitions `0..3`, folder then ZIP; zero is warmup. Persist each completed row and receiver trace immediately, then close its page before resetting databases.
8. Compare source **and fixture** fingerprints after the run. Close owned browser, Vite, sender and relay processes in `finally`, including launcher/setup failure paths. A changed HEAD is different from changed source bytes; investigate mismatches without relabeling a failed report as successful.

## Timing and content checks

Use the tracked [transfer clock](../../web/scripts/browser-evidence/transfer-timing.mjs) in the page. Call `startTransferTiming({ mode })` immediately before clicking **Download this folder**. For folders, a MutationObserver records the first rendered `saved` task stage; the later selector wait only confirms completion. For ZIP, call `completeZipTiming()` immediately after `saveAs`. Read `finishTransferTiming()` before metrics/export, retaining `elapsedMs`, `detectionLagMs` and `driverElapsedMs` separately. Exclude startup, settling, picker interaction and integrity checks.

Verify every output **before** deleting native targets or ZIPs. For a current-only run:

```powershell
node web/test/.tmp/local-transfer-ab/analyze.mjs $output --verify > (Join-Path $output 'verification-output.json')
if ($LASTEXITCODE -ne 0) { throw 'Output integrity verification failed' }
$report = Get-Content -LiteralPath (Join-Path $output 'report.json') -Raw | ConvertFrom-Json
$integrity = Get-Content -LiteralPath (Join-Path $output 'integrity.json') -Raw | ConvertFrom-Json
if ($report.status -ne 'completed' -or -not $report.sourceUnchanged -or -not $report.fixtureUnchanged) {
    throw 'Inspect the run failure or changed source/fixture'
}
if (@($report.rounds).Count -ne 8 -or @($integrity.checks).Count -ne 8 -or
    @($integrity.checks | Where-Object { -not $_.ok }).Count -gt 0 -or
    @($report.rounds | Where-Object { $_.errors.Count -gt 0 }).Count -gt 0) {
    throw 'Expected eight successful, verified transfers without browser errors'
}
```

`analyze.mjs` consumes duplicate hash matches separately, but permits renamed matches and checks only the number of extra files. Its successful exit is **not full path/restoration verification**. Also verify expected paths, compatible-name mappings and restoration contents. For the known fixture, ZIP retains 582 original paths. Folder saving adds exactly two matching restoration artifacts; on browser builds that enforce the `.git/hooks` write-path policy (observed from Edg/156) it preserves 567 paths directly and maps both `.git/hooks` (a directory; its 14 hook samples follow it) and `.venv/pyvenv.cfg` to their declared compatible names, while builds that permit `.git/hooks` preserve 581 directly with only the venv mapping. Reject duplicate paths, wrong mappings and unexpected extras. The comparison's `compare-workspace.mjs` performs these stricter checks and writes each batch's `strict-integrity.json`. For a current-only run, `node web/test/.tmp/local-transfer-ab/verify-rust-current.mjs $output` applies the same checks and writes `strict-integrity.json` plus `benchmark-summary.json`.

Report the three non-warmup `elapsedMs` samples and their sorted middle value per mode/version. If pooling an even sample count, average the two middle values. `analyze.mjs` has legacy before/after fields that are empty/null for `version: current`; do not report them as timings. Use `analyze-current.mjs` only with an explicit, existing historical report and matching timing contract; its default references a deleted report and its median shortcut supports odd counts only. Never use the current report as a fake baseline.

## Failures, interpretation and cleanup

- A setup failure may occur before `report.json` or sender logs are flushed. Inspect native-ready/picker/permission evidence and the launcher error, record a setup failure with the completed-transfer count, and verify owned processes have stopped. For the observed forward-slash picker rejection, normalize the path and retry once with fresh output/target/profile directories, preserving the failed attempt. Do not count it as a product transfer timeout. Stop repeated identical failures and diagnose the evidence.
- For product failures inspect `report.json.error`, `failure-body.txt`, `failure-diagnostics.ndjson` and `sender.log`. Waiting for Saved can time out because the product reached Needs action. Inspect `incident` and `local_output_operation_failure`, particularly `record.stageFailure.stage`, path and exception; a writer-close `InvalidStateError` is distinct from the expected `pyvenv.cfg` name rejection.
- Preserve failed batches and all slow successful samples. A bounded fresh-profile repeat can distinguish reproducible behavior from an isolated failure; a successful repeat does not establish a fix. Separate setup failures, failed transfers and completed transfers in the report.
- Filesystem/transaction lifetime sums include overlapping work. Bounded trace overwrites do not mean file data loss. Small differences across separate sessions and three measured samples do not establish a regression or speedup.

Write a short report beside the traces with exact revisions/source fingerprints, fixture identity, samples/medians, timing boundary, completed/failed counts and verification results. Check the original checkout's file hashes, HEAD, Git status and index again after cleanup; preserve and investigate unexpected changes without automatically restoring over them.

Stop only owned processes. After verification, remove this run's native targets, `profile`, `vite-cache`, `relay-state` and built executables. Resolve each absolute target, confirm ownership, reject unexpected reparse-point ancestors/contents, then use PowerShell `Remove-Item -LiteralPath` and verify removal. Source snapshots may have `web/node_modules` junctions into the original checkout: retain snapshots/backups by default and never recurse through those links. Keep reports, ZIPs, traces and reusable helpers unless the user requests their cleanup. Never clean the original source fixture, another task's artifacts, or broad globs across Downloads, `.tmp` or `cmd/wind`.
