# Playwright implementation-alignment audit

## Baseline and verdict

This audit treats `docs/Playwright修复执行计划.md` at blob `f5eb2091fc92675061fc11740c434338d1176bb9` as the authoritative baseline. It evaluates the current working tree only; it does not revisit or recommend restoring an older plan.

**Verdict: not implementation-aligned. P0: 2; P1: 7.** The suite-specific result model, evidence reducers, guard scanner, and Windows Job primitives are useful foundations. The blocking issues come from an incomplete helper migration and obsolete Docker/OCI code that remains in the build graph. The root fix is to finish the new architecture and delete the superseded authorities, not repair their old contracts.

## P0 findings

### P0-1 — The helper CLI and helper authority are split-brain

Plan line 104 requires `execute`/`aggregate` to receive explicit `--publisher-helper` and, on Windows, `--windows-job-helper`, then authenticate those exact paths against the build manifest and its SHA-256 values.

- `web/scripts/browser-network-matrix/cli/main.ts:58-60,94-96,159-170` accepts and forwards the explicit helper paths.
- `web/scripts/browser-network-matrix/cli/publisher-helper-process.ts:36-80` instead accepts only `helperManifestPath` and derives both executable paths from the manifest.
- No CLI option supplies `helperManifestPath`; conversely the backend no longer accepts the paths the CLI supplies.
- `pnpm -C web exec tsc -b --pretty false` fails at `main.ts:166` and four `publisher-helper-process.test.ts` call sites because `publisherHelperPath` is not a valid backend option.

**Required resolution:** keep explicit helper flags as invocation authority. Also pass/authenticate the build result's manifest (prefer a required `--helper-manifest`), require the explicit canonical paths to equal the role-specific absolute paths in that manifest, and verify the held executables against the recorded SHA-256 before launch. Do not infer executable paths solely from the manifest.

### P0-2 — Code that lines 99/105 require deleting still breaks the Web build

The same typecheck fails in the obsolete containment stack: `linux-container-contract.ts:458,460` and `browser-network-matrix/linux-topology/docker-topology.ts:218,242,527`. These are part of the Docker/OCI subsystem that the plan explicitly removes.

**Required resolution:** delete/refactor this dependency chain before attempting other gate validation. Fixing these Docker-specific type errors would spend effort preserving an architecture forbidden by the baseline.

## P1 findings

### P1-1 — The 1/3/5 run policy is still a global fixed-three contract

`web/scripts/browser-evidence/vocabulary.ts:1-2` defines `BROWSER_EVIDENCE_SAMPLE_COUNT = 3`; `verdict/contract.ts:157-163`, `artifact-publication/upload-bundle.ts:26-32`, and `scripts/ci/browsergate/main.mjs:118,1600-1615,1984-1985,2235-2240` bind schemas and execution to it. No versioned run-policy object exists. Consequently the long-term one-sample gate and five-sample stability gate in plan lines 49-54 cannot be represented.

Introduce a versioned policy identity with closure=`3`, blocking=`1`, and stability=`5`; bind its ID/version/count into context, sample identity, and verdict. Validate `sampleIndex` against the bound policy rather than a vocabulary constant.

### P1-2 — The workflow graph and event boundary still describe the removed architecture

`.github/workflows/ci.yml` still has `schedule` and `workflow_dispatch` on ordinary CI (`17-31`), a real OCI containment job (`243-261`), no standalone `browser-contract`, no independent `windows-browser-process`, and an empty topology-readiness job (`500-520`). `browser-main` and `browser-pion` each run their own contract operation through `main.mjs:895-920`. `browser-verdict` installs pnpm tooling and has a 150-minute job / 95-minute command ceiling (`407-429,466-488`), rather than the standard-library-only 10-15 minute boundary.

Replace the graph with `browser-contract -> {browser-main, browser-pion} -> browser-verdict`, run Windows process integration independently, remove schedule/manual from `ci.yml`, and create the separate non-blocking network workflow only when its real fixtures exist.

### P1-3 — Focused samples are repeated by both remainder suites

`scripts/ci/browsergate/main.mjs:367-379` runs `v2-real-hot-switch.spec.ts` and `pion-interop.spec.ts` as focused samples. `runFullSuite` then invokes the unrestricted package scripts (`1794-1824`); `web/playwright.config.ts:39` and `web/test/transport/webrtc/browser.playwright.config.ts:28` do not exclude those specs. Contract tests are also embedded in both hosted suite plans (`main.mjs:914-918`), and `web/package.json:18` mixes pure contracts with Docker/OCI lifecycle tests.

Create explicit remainder configurations or CLI exclusions, and make the standalone `browser-contract` job the only owner of schema/reducer/guard/workflow unit tests.

### P1-4 — Local entrypoints do not implement the planned boundary and Linux remains Docker-bound

`Makefile:29-45` filters `browser` out of `make ci`; `make check`, `make browser-stability`, and `make browser-network` do not exist. `scripts/ci/browsergate/main.mjs:20-21,1600-1645` still creates Linux image/container authorities, while `process/containment-factory.ts:98-139` supports only Windows Job Objects or Linux OCI containers.

Make `ci` include `browser` exactly once, add the three declared entrypoints, retain Windows Job containment, and replace Linux OCI containment with a native process-group/tree supervisor. `browser.sh` and `browser.ps1` should remain thin dispatchers.

### P1-5 — Artifact handling is still a multi-authority publication pipeline

The current path is generation staging (`artifact-generation.ts` and `process/attachment-staging.ts`), guard publication (`artifact-guard.ts:97-130`), verdict publication (`artifact-index.ts:79-108`), and a second upload-bundle authority (`artifact-publication/upload-bundle.ts`). `result.ts:154` exposes `artifactGeneration`, and the workflow uploads contracts and publication bundles separately (`ci.yml:311-333,383-405`). This conflicts with plan lines 99 and 112.

Collapse this into one guard-owned transaction: copy the allowed attachments and required result contract into a fresh private staging directory, write one manifest plus `guard.json`, seal it atomically, and upload only that directory. Keep content-addressed manifest/index logic, but remove generation IDs, publication pointers, guard/verdict republishing, and upload-bundle authority.

### P1-6 — Guard verdict and secret isolation do not meet lines 110-115

`guard-result.ts:438-464` rejects only `not-started` and `failed`, while `cli.ts:146-165` publishes and exits zero for `quarantined`; the plan requires both `quarantined` and `failed` to block the verdict. The hosted orchestration steps inject `GITHUB_TOKEN` into the process that launches samples (`ci.yml:297-304,369-376`), and `main.mjs:2818-2823` passes the full parent environment to children. The workflow has neither top-level `permissions: contents: read` nor `checkout.persist-credentials: false`.

Keep quarantine orthogonal to the immutable sample result, but make any non-`passed` guard outcome fail final reduction. Move real-secret injection into a separate guard/finalize step or process after the sample tree exits; construct a clean sample environment rather than inheriting `process.env` wholesale. Add the required workflow permissions and checkout setting.

### P1-7 — The retained network-matrix runtime is a Docker reproduction subsystem

`browser-network-matrix/linux-topology/docker-topology.ts`, `docker-journal.ts`, and `namespace-identity.ts` implement Docker-owned topology state; `concrete-local-fixtures.ts` and `concrete-runtime-bootstrap.ts` import that implementation. This conflicts with plan line 105. The readiness-only job in ordinary `ci.yml` is also not the future real-fixture workflow described at line 103.

Retain the network profile/result/aggregation contracts and authenticated publisher-helper path, but remove the Docker topology implementation. Wire real non-Docker fixtures only in the future dedicated scheduled/manual workflow.

## Material already aligned — retain

- **Suite-specific schema:** `result.ts:139-175,180-250` is a discriminated `main`/`pion` model with only the common `rtcCapability` and `executionOutcome`; main owns attempt/delivery fields and Pion owns applicability/native-interop fields. `child-evidence.ts:432-438`, `sample-runner.ts:434-449,675-692`, and `capability-result.test.ts` enforce that separation.
- **Evidence semantics:** the attempt reducer, capability classification vocabulary, parent-owned provisional/final result flow, and suite-specific acceptance validators match the direction of plan sections 1 and 4; preserve them while adding run-policy binding.
- **Guard primitives:** retain stable-file identity checks, path/symlink/size limits, trusted ZIP parsing, explicit-secret scanning, GitHub-token pattern scanning, `artifact-manifest.ts`, and the indexing half of `artifact-index.ts`.
- **Process primitives:** retain `process/containment.ts`, `windows-job-backend.ts`, `windows-job-client.ts`, `web/scripts/browser-evidence/windowsjob/`, and their tests. The plan deletes hosted OCI containment validation, not Windows process-tree proof.
- **Network helper foundation:** retain `build-helpers.mjs`, `helper-build-manifest.ts`, the Go publisher helper, and network result/aggregate contracts; finish the explicit-path binding described in P0-1.

## Verification order

1. Remove the obsolete Docker/OCI and multi-publication compilation paths; finish the explicit helper/manifest contract.
2. Make `pnpm -C web exec tsc -b --force` and the standalone browser-contract tests pass.
3. Validate policy modes independently: blocking `1`, closure `3`, stability `5`.
4. Prove focused/remainder disjointness and that contract tests execute once.
5. Prove samples receive no token/secret, `quarantined` blocks verdict, and each suite uploads exactly one sealed guard directory.
6. Validate the final workflow graph and local `make check`, `make browser`, `make ci`, `make browser-stability`, and `make browser-network` entrypoints.
