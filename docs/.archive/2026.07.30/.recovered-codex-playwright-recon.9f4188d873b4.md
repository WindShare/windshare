## Executive finding

This is a contract and orchestration rewrite, not a timeout fix. The current Firefox failure is caused by an API-presence boolean being treated as peer capability, while the actual attempt failure is not observable at the test boundary. The test then holds the first relay write behind a 15-second barrier and turns a healthy relay fallback into a zero-byte `Aborted` transfer.

The required dependency order is strict:

```text
Phase 0 evidence contract and attempt lifecycle
  -> Phase 1A controlled browser<->Pion topology (3 clean processes per engine)
    -> Phase 1B product hot-switch on that proven topology
      -> Phase 2 WebKit classification and crash evidence
        -> Phase 3 local/CI aggregation, guard, upload, scheduled/manual matrix
```

Phase 1B must not be used to discover whether the topology works. Phase 3 must not invent verdicts before Phase 0 supplies truthful evidence.

## Non-negotiable semantics

- Each sample has four independent outcomes:
  - `rtcCapability`: `unknown | unavailable | unusable | available`
  - `peerAttemptOutcome`: `not-started | admitted | failed`
  - `deliveryOutcome`: `not-started | succeeded | failed`
  - `executionOutcome`: `healthy | crashed | infrastructure-failed | unknown`
- `available` must start a real product attempt. `unavailable` means the API is absent and the product must not allocate a binding or `attemptId`.
- An API-present but failed minimal probe is `unusable`; the probe never controls the product attempt.
- Preserve complete `attempts[]`. Reduce as: no attempts = `not-started`; any failed attempt = `failed`; otherwise any admitted attempt = `admitted`.
- Each side's attempt stream has monotonic `sideSequence`; no cross-process clock comparison. Reject reverse order, duplicate terminal, post-terminal events, and missing terminal.
- Relay fallback may preserve delivery after peer failure, but it cannot turn that sample into a pass.
- A crash/infrastructure failure before probing or transfer preserves `unknown/not-started`; never synthesize `unavailable` or delivery failure.
- A passing `available/admitted` sample requires an authenticated lane, direct selected pair, relay cut fence, a post-fence peer dispatch, exact 16 MiB bytes/hash, and healthy execution.
- A passing `unavailable/not-started` main sample requires the same 16 MiB workload over relay with exact bytes/hash and healthy execution.
- Capability specs use no skip, retry, browser-name assumption, global-timeout increase, or weakened assertion.
- Main config owns product hot-switch/fallback. Pion config owns native adapter/interop. They share one classifier and one final verdict.
- The v2 protocol and production STUN/TURN defaults are out of scope.

## Contract decisions that must be frozen first

These are architectural decisions, not permission blockers; the contract owner must settle them in schema tests before runtime agents start:

1. JSON schema version, base64url identity encoding, exact required/optional fields per stage, and whether sequence gaps are legal.
2. Terminal uniqueness: define the side-stream rule and logical-attempt reduction so browser and sender terminals cannot be mistaken for duplicates.
3. Stable typed-error vocabulary and mapping from authenticated peer operation codes.
4. Named capability probe deadline and exact success boundary for the minimal DataChannel offer probe.
5. Precedence for page crash, browser disconnect, runner exit, assertion failure, and infrastructure failure when deriving `executionOutcome`.
6. Pion `unavailable`/not-applicable representation and how final verdict correlates it with the main relay-fallback result.
7. `TestIceTopology` schema and the reproducible Ubuntu/Windows interface/family selector. A literal checked-in machine address is not acceptable.
8. Selected-pair evidence shape: browser candidate IDs/types/protocol/address-optional fields and Pion-authoritative family/address evidence tied to the same `attemptId`.
9. Exact event completing `cutAndWait`: proxy no longer accepting plus receiver relay lane detached/ineligible.
10. `guardOutcome` values and archive limits: recommend `passed | quarantined | failed`, with explicit entry-count, expanded-byte, nesting, path traversal, and malformed-ZIP failure rules.
11. Explicit real-secret inputs for scanning. Synthetic fixture URLs/keys/SDP/ICE/digests are permitted diagnostic data and must not be treated as repository/runner secrets.
12. Windows atomic replacement and D5 evidence-to-result ingestion contract.

## High-risk failure modes to test explicitly

- Browser API absent after an `attemptId` was allocated.
- Probe failure suppressing the real product attempt.
- Observer throwing and destabilizing transfer.
- Sender/browser terminal duplication or an admitted attempt later reclassified as failed on normal close.
- Typed operation code lost through `V2SessionSignalingRoute`.
- Peer failure releasing the transfer as an abort instead of relay fallback.
- A relay dispatch begun before cut completing after cut and being misclassified as post-fence.
- Firefox topology “fixed” by skip, retry, public STUN, TURN, or a browser-name allowlist.
- Browser selected-pair address blank while valid Pion family evidence exists.
- Reused Playwright browser/context or reused Pion helper across nominal samples.
- WebKit crash rewritten as `unavailable`.
- Main failure preventing Pion execution.
- Initial `result.json` missing when Playwright never starts.
- Wrong checkout SHA, duplicate sample, invalid schema, or missing terminal accepted by verdict.
- Secret scanner treating synthetic fixture data as a real secret.
- ZIP traversal, malformed central directory, nested archive bomb, or scanner crash allowing upload.
- Windows D5 manifest producer/consumer updated on only one side.
- New Go entrypoint/test-support package pulling package coverage below 70%.

## Out of scope

- v2 wire protocol or lane-admission semantic changes.
- Production STUN/TURN default-policy changes.
- Core-release, Linux/ext4 certification, or claiming core coverage completion.
- Full image/MP4 range/seek R7 evidence.
- Any “fix” based on longer global timeouts, retries, skips, disabled assertions, or downgraded crashes.
