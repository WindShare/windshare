# Playwright CI 改造审查

## 结论

浏览器证据语义应保持严格，但当前 hosted OCI、volume sealing、nonce 和镜像销毁证明超出项目威胁模型。供应链攻击与同账户本地攻击是非目标；CI 应重点解决测试隔离、失败诊断和意外 secret 泄漏。

## 推荐架构

- `browser-contract`：evidence schema、reducer、guard 和 workflow contract 只执行一次。
- `browser-main`：三引擎各 3 个独立进程，运行产品 hot-switch/fallback 证据；剩余 full suite 排除已重复执行的 focused spec。
- `browser-pion`：使用独立 runner、topology lock 和 artifact namespace，执行 Pion/adapter 证据。
- `browser-verdict`：`if: always()` 聚合两套结果；不安装 pnpm，不运行浏览器，job timeout 控制在 10–15 分钟。
- `windows-browser-process`：只运行 Windows Job Object/Named Pipe 真实 integration tests，并设置明确超时。

删除以下内容：

- `browser-containment-validation`
- hosted OCI image authority、dependency-volume sealing 和 nonce retirement 证明
- 空的 topology readiness job
- 重复 preflight、重复 contract tests
- full suite 中已由 focused evidence 覆盖的相同 spec

GitHub browser job 直接使用 hosted runner 和固定 Playwright/package/browser 版本。Docker 只可保留为可选的本地复现入口，不参与门禁。

## Artifact 边界

外层 runner 负责 provisional/final `result.json`，确认子进程树退出后，将附件复制到私有 staging；guard 拒绝 symlink、路径越界、超限和非法 ZIP，扫描真实 secret 与 token 格式，写入单一 manifest 和 `guard.json`，最后原子封存 upload 目录。只上传封存目录。

必须保留 checkout SHA/schema/identity 校验、独立 `guardOutcome`、quarantine 和 scanner failure fail-closed；不保留多层 publication authority 与 OCI 证明。

安全配置：

- `permissions: contents: read`
- checkout 使用 `persist-credentials: false`
- `GITHUB_TOKEN` 不进入 sample runner、Playwright 或测试子进程
- 如需精确值扫描，只在独立 guard/finalize step 注入 token
- 普通 PR/push 使用 scoped concurrency；不得取消 tag 或 scheduled/manual network run

## 确定方案

- `make ci` 串行执行全部非浏览器门禁，并恰好调用一次 `make browser`；`make browser` 仍可独立运行。
- 新建独立 `browser-network-matrix.yml`，仅响应 schedule/manual，不让定时任务重跑普通 CI。
- Browser gate 对所有非纯文档 PR/push 运行，避免路径过滤遗漏跨模块影响。
- 保留一个薄的固定 digest 本地 Docker 复现命令，但不作为门禁；删除当前 OCI authority 子系统。
- 同步修订执行计划和项目级验证说明中与上述方案冲突的表述。

在真实公共 STUN、受限 UDP、coturn 和 real-NAT fixture 可用前，删除当前空 schedule/readiness；完成 fixture 后再实现非阻塞 network matrix。
