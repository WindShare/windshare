# CI Slimming Plan

核心问题不是产品测试太严，而是 CI 控制框架过度工程化、重复执行，并开始制造自身故障。

## Priority and evidence

1. **P0 — 收敛普通 gate 的 Make/Go authority。** [Makefile](../Makefile#L22)、611 行的 [makeauthority/entry.mjs](../scripts/ci/makeauthority/entry.mjs)、ELF/`/proc/fd` 校验和 [stability semantic contract](../scripts/ci/stability/execution-contract.mjs#L565) 已形成第二套控制平面。retained Make FD 修复后，Hygiene 曾因旧 semantic contract 失败；core-release 也曾被 Make 参数禁令反噬，说明这些自证层正在产生高耦合连锁故障。
2. **P0 — 增加分层与取消。** 当前没有 `concurrency/cancel-in-progress`，昂贵 job 也不依赖廉价 preflight；format、SLOC、lint、typecheck、compile/vet 应先于 race、coverage 和 browser。
3. **P0 — 消除 push/PR 双跑。** [ci.yml](../.github/workflows/ci.yml#L8) 同时覆盖所有 branch push 与 PR。同一 `e23dfc72` 的 [PR run](https://github.com/WindShare/windshare/actions/runs/30326395511) 和 [push run](https://github.com/WindShare/windshare/actions/runs/30326040457) 合计约 65 runner-minutes。
4. **P1 — 明确测试的唯一 owner。** 当前 Linux/Windows 互相 cross-vet；integration/E2E 同时存在于 race、coverage 和独立 job；[web.sh](../scripts/ci/linux/web.sh#L14) 与 `pnpm build` 重复执行 `tsc`；full-browser 重跑 browser-contract/generated semantic。完整 full graph 静态包含 22 次 checkout、17 次 setup-go、10 次 setup-node、7 次显式 Web dependency install，普通 PR 路径也有 19 次 checkout。

不降低 coverage 门槛、覆盖 integration/E2E 的双 OS 原生 race、scheduled integration stability、golden vectors、关键 browser smoke 和独立 release artifact 验证。削减的是重复 owner 和 CI 自证层，不是产品风险证明。

full-browser 的 `ref_protected=true` 是合理边界；当前仓库没有 branch protection、ruleset 或 protected environment，导致 full 模式不可达。应配置保护规则和 environment，并保持 PR 与 self-hosted/OIDC workflow 的结构隔离。

## Decisions

- CI 采用 PR-first：保留 `pull_request`、`push: main` 和手动触发，feature branch push 不再运行完整 CI。
- `ci.yml` 始终启动，不使用 workflow 级 `paths-ignore`。轻量变更检测决定后续任务，固定名称的 required verdict 始终产生，供 main ruleset 使用。
- PR 可达图只使用 GitHub-hosted runner 和只读权限，结构中不得包含 self-hosted job 或 `id-token: write`。
- 普通 gate 是 correctness boundary，不再对 Make、PATH、解释器、文件描述符或 Go 可执行文件进行 retained authority 自证。
- `browser-full.yml` 只拥有 protected browser evidence，不重跑普通 PR 图。`release-readiness.yml` 按同一 protected main SHA 验证 CI、full-browser 和 stability evidence，不再调用混合权限的 `current-commit.yml`。
- 普通 actions 跟随 latest major；接触 OIDC、protected environment 或发布权限的最小 broker/action 固定完整 SHA，并自动跟进升级。

## Execution order

1. 重建 workflow 拓扑：拆除混合权限的 `current-commit.yml`，分离普通 CI、protected full-browser 和 release-readiness；先让固定 verdict 在 PR/main 稳定出现，再配置 ruleset，避免锁死 main。
2. 为普通 CI 增加按 PR 或 branch 隔离的 `concurrency` 与 `cancel-in-progress`；移除 feature push 全量触发和 workflow 级路径过滤，并增加始终运行的 required verdict。
3. 建立 preflight DAG：Linux 负责 format、SLOC、lint、typecheck、compile/native vet，Windows 只负责 native compile/vet；race、coverage、browser 和其他昂贵任务通过 `needs` 依赖对应 preflight。
4. 将 Make 收敛为 `make <gate>` 与 `make ci` 的薄本地调度层。普通脚本直接调用本地工具链，删除 makeauthority/goauthority retained launcher 及依赖源码片段的 stability semantic contract，同时保留结构化 run ID、stability handshake 和结果证据。
5. 收敛测试 owner：
   - 每个 OS 只执行 native vet；由 Linux 单独保留一次 `GOWORK=off go build ./...`，验证根模块消费已发布 core。
   - PR race 与 coverage 因 instrumentation 不同继续各跑一次完整模块；删除独立的无 instrumentation integration/E2E 重放，scheduled stability 保留普通 integration 样本。
   - Web build 只执行一次 `tsc`。
   - PR browser preflight 与 full-browser 各自由单一 browser orchestrator 生产一次 contract/generated evidence，不在同一 run 内另设重复 job 或跨 job authority。
6. 配置 main ruleset、protected environment 和一次性 self-hosted runner。full-browser 仅接受 protected default branch 的 schedule/workflow_dispatch，OIDC 只授予最小 broker job。
7. 更新 release-readiness，使其校验与目标 SHA 绑定的普通 CI、full-browser 和 scheduled stability 结果；release artifact verification 保持独立，不复用普通 CI 的工作区或产物。
8. 删除失效的 authority 测试、源码语义快照和文档，更新 `make ci` 图后执行各 gate 与本地 `make ci` 验证。
