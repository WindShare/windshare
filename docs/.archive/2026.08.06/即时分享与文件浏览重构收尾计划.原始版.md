## 审计结论

即时 descriptor、relay 注册后出链接、按需 catalog、file-local revision、预览范围读取、分离密钥、
错误隔离、按文件续传、0/8 relay 回退和 LiveOnly 停止语义已经有实现与测试支撑。根层第一层预取是已确认保留的根层例外；
真正尚未闭合的产品语义有两项：目录边发现边传输，以及从旧 journal 清理切换到 file-local checkpoint。

| 目标行为 | 当前状态 | 根因 |

## 收口顺序

### 1. 固化真正的按需目录语义

- 保留 `StartRootPrefetch`，并把它明确写成“所选目录根第一层”的低优先级例外：可取消、受预算约束、不递归，且接收方明确请求时优先于预取；它只预热 catalog，不传输文件内容。
- 普通目录仍由接收方首次 `LIST_CHILDREN` 提交 generation；预取策略不能改变目录身份、冻结时点或失败范围，并继续使用 singleflight、预算和失败隔离。
- 目标摘要和产品澄清已经对齐；实施时同步 `协议规范.md`、CLI/浏览器 trace 与生命周期测试，清除把根层例外误写成“完整按需”或“递归预取”的表述。

### 2. 重构传输核心为增量作业

- 在 Go `core/transfer` 先冻结版本化的 `TransferIntent` 合同：规范化编码固定包含 `ShareInstance`、synthetic root、选择模式与选择规则、输出目标/backend/format；普通下载冻结 `SelectionRules`，CLI `--only` 冻结规范化的 `SelectionByCatalogPath`，协议层 `SelectionByNodeID` 仍只使用 opaque ID map，三者不得混称。canonical bytes 与 digest 算法由 Go↔TypeScript 向量固定，`TransferJobID` 标识作业，`OutputSessionID` 只标识本次运行。picker 未确认前只能保留 draft，确认后才持久化 final intent。当前 selection/generation 是观察态；完整终态计划、`SelectionIdentity` 和旧 `ResumeIntent` 不再充当 durable resume namespace。
- 用户选择“下载全部”时只冻结 `SelectionRules(Default=select)`，不先把整棵树物化为完整文件清单；之后成功提交的 generation 中，尚未发现的后代继续继承这条规则。
- 输出目标确认后只打开一个 `OutputSession`，先建立输出根/恢复命名空间，不等待整树 discovery，也不提前创建未提交目录。synthetic root 在 `OpenOutput` 中建立 admission；每个已提交 generation 通过 `AdmitDirectory` 幂等确认 parent，再把已选文件送入有界队列；发现与文件传输并行，队列满时暂停扫描。
- 终端发现只负责封存 job、汇总精确或未知/部分完成的 measure 和最终 finalize；它不是首个文件的输出屏障。文件 revision、checkpoint、resume 以及目录/文件级失败继续独立结算。ZIP central-directory spool 只保存封口所需的有界元数据，并设置独立的 entry/byte 上限；spool 耗尽按输出失败进入 `paused`，不得把未封口归档伪装成成功，也不得退化为整树 selection spool。直接单文件流和 OPFS/FSA 的能力差异要在同一输出契约中表达。
- CLI `--only` 的 `SelectionByCatalogPath` 与协议层 `SelectionByNodeID` 的显式目标，只有在已发现，或其所在目录 generation 已完整结束且仍未出现时才能结算；发现中断则保持 `unknown/partial`，不报成功或“不存在”。
- discovery、admission、文件队列、NodeID 账本和 ZIP spool 各有先行定义的上限常量；discovery/身份预算耗尽保留 `unknown/partial`，输出/admission/队列/spool 预算耗尽进入 `paused`，不允许无界积压或复用身份。
- job 状态固定为 `draft → intent-frozen → output-open → discovering → generation-admitted → settling → terminal-finalize → succeeded|completed-with-errors|paused`；隔离的目录/文件失败进入 `completed-with-errors`，取消、根/session 失败或不可回滚输出失败进入 `paused`，未完成 discovery 的显式目标保持 `unknown/partial` 且不得使 job 报成功；`paused` 保留最后 checkpoint，不自动 discard。
- Web 下载点击处理器必须同步触发 output picker 并记录 `downloadT0`，不能等待 discovery 或 picker 才启动 P2P；picker 取消只丢弃 draft 并取消该 job 的连接尝试。随后收敛现有的 `transfer/job.ts`（已有增量测试但未被生产 v2 引用）与 `v2-job.ts` 两套作业模型，再复用同一语义；不能让测试绿在未接入的实现上。重写 Go 的 `TestTransferJobCompletesCatalogDiscoveryBeforeFirstRange` 等“终端发现后才能传输”测试，并补充“延迟兄弟目录时首个文件已写出”的小型跨层测试。

#### 规范合同切换

- 同步重写 `协议规范.md` 9.1/9.2 与 `威胁模型.md` 3.5：`OpenSelection(terminal OutputSelection)` 不再是生产前置条件，改为 `OpenOutput(TransferIntent)` 加逐 generation `AdmitDirectory`；`BeginFile` 只能引用成功的 parent admission。
- 新合同保留目录 generation 的原子性和全局 NodeID 身份账本，但删除“整树 selection spool 完成后才能输出”的屏障；`OutputDirectory` 必须携带 directory ID、generation、parent admission 和 canonical path，`DirectoryAdmission` 是幂等且不可伪造的 opaque token；同一 `DirectoryID+generation+parent+path` 的重复 admission 返回同一结果，任何绑定不一致都按目录 scope fail closed；Go↔TypeScript 向量覆盖稳定 `TransferIntent`、directory admission 和 file-local checkpoint。
- `core/osfs` 的 authority/outputruntime/outputcap、原生/FSA/OPFS 后端及 Web `OutputSession` 一并切换：`OpenOutput` 只做输出根、后端和恢复 namespace 校验，目录 ancestry、metadata 和 descendant 权限在 `AdmitDirectory` 时逐代校验。

#### “已提交目录”是什么意思

这里的目录不是半扫描的临时页，而是发送端已经完整读取直接子项、写完 pages 和 terminal marker 并原子提交的 catalog generation。generation 提交后，其中已选文件即可进入传输队列；未完成的兄弟目录仍可继续发现，接收方永远不会看到半个目录。

#### 用户体验

- 用户点击下载后立即建立 intent draft；输出目标确认后冻结 final `TransferIntent` 并只打开一次 `OutputSession`；首个已提交目录中的文件随即开始写出，不等待整棵树的终端发现。
- “下载全部”表示本次任务对当前根及之后成功发现的后代默认选择，不表示分享创建时刻的整棵树快照；generation 提交后源端新增或修改的内容不会自动加入；正常情况下无需逐层展开，首个已提交目录即可开始写入。
- 界面同时展示“已发现 `X` 个文件/`Y`”与“已完成 `A` 个/`B`”。`open` 或 `failed` 时总量只是下界，不显示伪百分比；只有 discovery 完整结束后才显示确定总量；发现中断或失败时明确提示仍有未发现分支。
- 已提交 generation 才能创建用户可见的目录；已提交的空目录可以发布，未提交或失败的目录不创建；父目录在所有已选 child 结算后按成功/部分完成分别 finalize。
- 某个目录分支或文件失败只标记该分支/文件并继续兄弟分支，汇总为“部分完成”；连接的 0/8 计时与发现进度相互独立。
- 原生目录输出可逐项创建；ZIP 继续遵守“尚未开始写出的成员可跳过、已开始写出的成员失败则终止整包”；根层预取始终只是 catalog 预热，不应让用户误以为内容已上传。

### 3. 续传身份、新状态与旧状态清理

- 这里的“续传状态”不是 sender 的重连 token，而是 FSA/OPFS/原生输出保存的 journal、checkpoint 和已验证范围。新合同命名为 `FileCheckpointV1`；各后端可有独立物理版本，但都必须写入 schema、ownership 和 binding。旧 `output-state-v2`/`output-state-v3` 不是兼容边界。
- 在输出目标确认后冻结 final `TransferIntent`（`ShareInstance`、synthetic root、选择模式/规则、输出目标/后端和格式），不把未来后代、动态总量、连接路径或 `ProtocolSession` 放进身份；选择变化只影响下一次 job。
- 持久化 checkpoint 以 `TransferIntentDigest + FileID + FileRevision + canonical path + exact size + backend/root identity + owned output object` 绑定，按文件记录排序且不重叠的 verified ranges；`OutputSessionID` 只标识本次运行。`FileCheckpointV1` 的 schema、ownership marker、record ID、canonical 编码、state/checkpoint generation、checksum 和 crash-cut 恢复规则由向量与后端合同固定，清理前必须先验证 namespace/root ownership。
- 不提供旧状态迁移或双读。启动/升级只在 WindShare 自有 native/FSA/OPFS/IndexedDB namespace 内按 ownership marker 清理旧 header、file records、checkpoint 和未完成 staging；清理使用独占锁、可重复的分步提交，崩溃后可继续，并拒绝并发双写。已发布文件、归属不明内容和路径冲突不自动删除，改为 quarantine/明确提示。
- `FileCheckpointV1` 成为唯一运行时语义；旧状态只允许被一次性 namespace 清理器识别，不导入 ranges、不推断后代、不参与传输。清理器完成后按保留策略回收孤立 file-local records。

### 4. 做跨层验证与可诊断性收口

- 覆盖未展开目录、未发现总量、目录分支失败、文件变化、取消和刷新续传；增加队列满时反压、NodeID 预算耗尽、重复 admission、根失败及各边界取消测试。旧 v2/v3 状态只验证清理后可用新 schema 重建，不验证迁移。
- 重点验证一个文件失败不拖垮仍在发现的兄弟分支、显式目标在发现未完成时保持 `unknown/partial`、输出目标确认后 session 已打开、generation 提交前不创建目录、延迟兄弟目录时首个文件已写出、ZIP 在 terminal 后才封口，以及清理在每个崩溃切点和并发打开时仍可重复且不误删成品。
- 进度展示必须区分 `discovery=open|complete|failed` 与文件结算：`open` 显示“已发现/已完成”而不显示百分比；`failed` 显示“至少已发现”及失败分支，不把下界当总量；只有 `complete` 才显示精确总量和百分比。发现已完成但单个文件失败时，分母仍准确，显示 `A/B` 并明示失败数。原生目录/FSA/OPFS 可逐项可见，ZIP 明示“正在生成压缩包”，不得把未封口的归档当成可用成品。UI 不展示 intent/admission 等内部状态；“暂停”保留 checkpoint，“取消”停止后续发现并保留已完成文件，清理未完成输出另行确认。
- 在目录提交、文件 admission/开始/完成、发现完整结束、状态清理和输出终结处保留结构化 trace，携带稳定的 share/`TransferJobID`/session/file 标识与决策上下文；路径、文件名和密钥按隐私边界脱敏。
- 运行 `make check`、完整 `make ci`、现有 core candidate（含 `GOWORK=off`）及浏览器 progressive/relay smoke；记录固定 commit、workflow run、环境和时序背景，不能只留下无上下文的绿色数字。

### 5. 退役实现与合同清理

- 新的增量 `TransferJob`、`TransferIntent` 和统一 `OutputSession` 成为 Go/Web/CLI 唯一生产权威后，删除不可达的整树 selection/transfer consumer、旧适配器和只服务旧生命周期的辅助代码；重点清点生产 Web gateway→`v2-job`、Go 终态 barrier 测试、CLI `get` 入口和旧 canonical-selection 向量。删除范围不得包含 ZIP central-directory metadata spool；仅保护现行合同的测试夹具可以保留。
- 清理不再属于 suite `0x02` 的协议字段、消息/错误枚举、Go↔TypeScript 向量、生成夹具和旧行为测试；实现不得留下只解析、不再生成的兼容分支。历史文档只留在 archive，活动文档和链接改指现行合同。
- 以现有 `make hygiene`、`scripts/ci/go-v1-forbidden.mjs`、`scripts/ci/web-forbidden.mjs` 为基线，补充退役路径、符号、向量和生产依赖图检查；默认与 all-tag 生产图都不得重新引入已删除权威。
- 删除 `resume_legacy.go` 等迁移器和兼容运行时分支；如需升级清理，只保留按自有 namespace/ownership marker 工作的一次性清理器，不导入旧 ranges、不参与传输。应用自有状态目录之外的文件不在清理范围内。
